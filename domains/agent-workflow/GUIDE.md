# 使用指南：小 Agent 的可靠工作流

完整状态语义见 [数学模型](FORMAL_MODEL.md)，单个动作和删并边界见 [原语卡](PRIMITIVES.md)。

## 先固定四项

1. **目标**：用户要求的真实结果与原验收；用户未取消，不因时间久自动作废。
2. **事实**：原实例/visit/版本、已发生效果、原命令关联和未知之处。
3. **合法能力**：当前身份、工具、权限和业务/人类边界。
4. **恢复**：谁从哪份持久事实发现原义务；不能只说“下一个负责”。

## 最小节点任务包

| 输入字段 | 必须说明 |
|---|---|
| `task_ref / obligation_id` | 属于哪一笔未完成原义务 |
| `instance / visit / sv` | 当前合法位置和并发版本 |
| `input / digest` | 必要工件、来源、版本及其可读性 |
| `actor / capability` | 谁依法执行、有哪些具体工具 |
| `one_action` | 一个局部动作 |
| `output` | 可复验工件、原回执或失败阶段 |
| `verifier` | 谁能独立核验 |
| `outcomes` | PASS/FAIL/BLOCKED/UNKNOWN 对应哪些已批准出口 |

固定命令、计数、幂等核验由程序完成；仅把无法由规则判定的局部问题交给 Agent。**细分节点不等于增加角色**；只有权限、工具或独立性不同才采用不同执行身份。

## 五类典型组合

**正常接续**：持久建立义务 → 合法接纳 → 执行 → 受信核验 → 与原提交关联的后继义务。消息送达、执行、结果接受、业务验收分别留回执。

**环境修复**：环境测试失败 → 环境修复子工作 → 原测试者身份复检 → 恢复原测试。修好环境不等于测试通过。

**反复退回**：有界重试耗尽 → 保留原任务及当前 Case → 比较多轮拒绝原因、材料版本 → 有权修复子工作 → 独立验收 → 合法解除门 → 原任务继续。不要把第 3 次退回直接等同用户本人需要审批，也不擅自调大上限。

**回执丢失**：原键和合法信封先持久化 → 外部写可能生效 → 本地 UNKNOWN → 原事实所有者对账 → 证实原效果或证实未发生且排除迟到生效后恢复；相同载荷、时间相近和超时不足以判断。

**人类决策**：付款、真实物理行为、私人偏好授权、新范围决定须有准确问题和有效权限。已有有效预授权可依法复用，缺少真实证据不得编造；答复后自动恢复原业务。

## 哪个层次算推进？

| 观察 | 可以证明 | 不能证明 |
|---|---|---|
| 定时器正在跑 | 进程存在 | 它发现了本任务 |
| 消息 ingested | 接收方收到了 | 该步执行 |
| 工件 GREEN | 本次检查通过 | 原目标完成 |
| 正式 transition | 控制位置改变 | 外部业务效果成功 |
| 固定原 AC 满足 | 该目标在指定条件下完成 | 其他目标也成功 |

## 什么时候不再拆

若节点已有完整合法输入、单一明确动作、独立可验产出和有消费者的失败出口，则停止继续拆小。只增加“协调专家”却不消除额外判断，不是简化。
