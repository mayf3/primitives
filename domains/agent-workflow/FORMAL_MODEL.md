# 数学模型：带部分可观测性与外部效果的无人值守工作流

**0.2.0 · 2026-11-20 · 抽象规范 / 部分条件定理已形式化**

这是平台无关的形式定义，将“控制位置发生转移”与“用户原目标真的完成”分离。较早模型保留在本文；后续评审要求的非空信息集、宏步全后继降秩、状态压缩充分性及不可信报告，见 [FORMALIZATION.md](FORMALIZATION.md)。本版 [Lean 工程](formal/README.md) 已证明明确列出的条件命题；没有证明本页全部性质或任何生产部署满足它们。

## 1. 状态机及其可见世界

定义：

\[
M=(X,X_0,U,E,\Delta,\operatorname{obs},\operatorname{Acc},\operatorname{Env})
\]

- \(X\)：全局状态；\(X_0\)：允许的初态。
- \(U\)：控制方合法动作；\(E\)：外部事件（故障、人类回复、外部效果、迟到回执）。
- \(\Delta\subseteq X\times(U\cup E)\times X\)：一次允许的状态转换，不等于 Agent 自述已经执行。
- \(\operatorname{obs}_p\)：主体 \(p\) 在其真实权限下可观察的历史。
- \(\operatorname{Acc}_g\)：任务 \(g\) 在原合同中固定的业务验收谓词。
- \(\operatorname{Env}\)：调度公平性、真实输入/授权最终可得、服务恢复、故障预算等假设。

合法策略 \(\sigma\) 只允许使用其主体已经获得的观测历史和动作权限。测试者看见的数据库真实状态，不自动等于运行中的恢复者可以获得该事实。

## 2. 构形与必须区分的身份

\[
x=(G,P,D,A,K,W)
\]

| 组成 | 内容 | 常见错用 |
|---|---|---|
| \(G\) | 用户目标、原验收、授权、显式取消权 | 把一条消息或技术 Issue 当业务完成 |
| \(P\) | 固定 Definition 版本、节点角色、工具、执行类别、策略 | 用新版本边名运行旧实例 |
| \(D\) | 未完成业务义务、治理义务、源 visit、依赖与必需后继 | 文件写了 pending 却没有消费者 |
| \(A\) | attempt、generation、fence、执行阶段、入站与退出事实 | Agent 会话结束当作节点完成 |
| \(K\) | 持久工件、原命令回执、来源、独立核验和归属 | 模型自填 PASS 当作可信事实 |
| \(W\) | 外部世界实际的操作效果与发生次数 | 超时就推断未执行 |

至少要绑定三类不同的身份：

- **业务逻辑操作**：稳定键 \(k\)，用于幂等与跨重启对账。
- **当前流程位置**：\((instance,visit,sv)\)，用于合法角色、固定图、并发版本。
- **本轮尝试**：\((attempt,generation)\)，用于执行与迟到回执归属。

RETURN 可以创建新 visit；恢复可以保留 visit 但创建新 attempt；新一轮也可能需要旧操作键。只按时间、角色显示名、内容相同或最近一条记录结账会串账。

## 3. 抽象单步与持久交接

### 创建与接纳

`Create(g,p)` 有效时，同时记录固定的 \(G,P\) 和入口义务 \(d\in D\)。若创建后没有任何可运行的合法消费者能发现这笔义务，后述 S1、L1 无法成立。

`Admit(d,a)` 只有在当前角色合法、材料/能力/依赖齐备、fence 有效时才发生，并形成持久 attempt。网络 DELIVERED 或会话 ingested 只是投递层事实。

### 效果、回执与世界状态

在产生副作用之前持久保存原键、请求信封、预期效果与必要的恢复关联。发生外部效果后，\(W\) 可以先变化而 \(K\) 不变（例如 HTTP 响应丢失）；崩溃只能抹掉易失信息，不能倒转外部效果。

可信工件 \(e\) 必须绑定原义务、候选、visit、attempt、来源/摘要与已执行动作。模型自填证据标签不能赋予自己权威。

### 核验与后继

令 \(R_P(d,K)\) 为当前固定合同下真正**必须建立**的后继义务集合。合法结账要求：

\[
D'_{\mathrm{open}}=(D_{\mathrm{open}}\setminus\{d\})\cup R_P(d,K')
\]

同一个权威提交应已包含后继，或持久保存足以让已运行的恢复者**确定性重建**后继的事实。若先标记“已完成核验”，后续派发失败后无人读取，则可能丢失原责任。结果被接收与业务判定通过仍是两件事。

### 故障、治理、恢复与真正的人类门

`Blocked(d,h)` 保留原义务 \(d\)，而 \(h\) 是明确的外部依赖、治理 Case、授权事实、材料补证或工具修复。治理本身也有可恢复的当前责任。修复的代码存在不等于修复已采用；只有独立验收、合法采用、效果读回并按规则解除门，才恢复原任务。

执行尝试可以有上限；上限耗尽后应有真实可接单的诊断/治理/补证责任，**不能等同取消用户目标**。

真的需要人类输入（购买决定、物理验收、特殊授权）时，持久保留准确问题与恢复条件。系统不得凭偏好推导权限，也不能因等待时间长就取消任务。人类答复后由原流程接续。

## 4. 安全性不变量 S1–S3

**S1 责任连续。** 每项尚未满足、未被用户显式合法取消的必需业务义务，必须有可靠可恢复表示，并能沿明确关系找到**实际存在的**合法消费者、受监测的依赖，或具备到达/重试能力的升级接收者。记录在某份 JSON 里、但无人读取，不构成 S1。

**S2 原目标真实完成。**

\[
\operatorname{ClosedSuccess}(g)\Rightarrow \operatorname{Acc}_g(W,K,D).
\]

不能从图到 TERMINAL、子任务通过、Case RESOLVED、消息送达、测试退出码为零，直接推出父目标完成。必须保留原验收及证据的身份、来源和业务意义；独立 QA 或真人决定如为合同必需，不可由作者自填代替。

**S3 逻辑效果安全。** 对被合同规定“至多一次”的逻辑操作 \(k\)：

\[
\operatorname{EffectCount}_{W}(k)\leq 1.
\]

这约束的是**业务效果**，不是消息发送次数。可允许重复传输，只要身份和幂等/对账保证不会增加逻辑效果。两个不同的合法命令不能仅因载荷相同而合并。

## 5. 条件活性 L1–L2

**L1 持续责任最终有人接。** 若义务 \(d\) 最终持续有资格、合法身份及工具最终可用、消费者确实覆盖该类义务且调度满足公平性，则它最终被合法接纳或按合同移交有效依赖/修复流程。定时器每分钟运行，不意味着它看到了 \(d\)。

**L2 原目标在约定任务族上最终满足。** 对任务族 \(H\)，存在仅使用合法观测的控制策略 \(\sigma\)，使所有满足 \(\operatorname{Env}\) 的运行始终安全，并最终满足原目标：

\[
\forall g\in H:\quad \Box\operatorname{Safe}\land\Diamond\operatorname{Acc}_g.
\]

该主张**必须附适用前提**：关键外部输入、物理动作及授权最终可得，环境故障属于预先限定且可修的故障族，验收器能识别真成功，调度公平且恢复者能够观察必要事实。永久缺失任何关键条件时，只能保证“安全留存、有接收者的等待或升级、条件恢复后可继续”，不能保证无条件完成。

## 6. 有限可达性构造

在有限、完全可观测、可枚举全部允许后继的抽象中，取 \(W_0\) 为“安全且原验收已满足”的状态集合：

\[
W_{i+1}=W_i\cup\{s\in Safe\mid \exists u\in U(s),\;\varnothing\neq Post(s,u)\subseteq W_i\}.
\]

首次落入第 \(i\) 层的状态赋秩 \(i\)。若真实可执行的策略总选能让所有后继降低秩的动作，则在模型与调度假设下可以有限步到 \(W_0\)。这是有限博弈中的**候选获胜区域**，不是任意弱 Agent 或真实生产的普适定理。

部分可观测时，相同合法观测历史对应的所有可能世界必须用同一个动作，必要时转成 belief-state 博弈。弱 Agent 只负责局部输入/工件，状态、身份、合法边、恢复和核验由外围程序承担；其实际错误率和资源成本仍要实测。

## 7. 响应丢失不可区分性

两个世界可能产生相同本地日志：

- \(w_0\)：服务端没有提交写操作。
- \(w_1\)：服务端已提交，回复在到达调用者前丢失。

若没有原操作键、可信读回，且无法排除迟到生效：

- 重发可能在 \(w_1\) 重复效果，违反 S3；
- 直接结账可能在 \(w_0\) 假完成，违反 S2；
- 永久不动虽可能安全，却无法保证 L2。

**超时不是操作未发生的证明。** 应由事实所有者提供可区分的新证据或有幂等性的原键重放；否则进入带接收者的持久 UNKNOWN/补证义务，不能换 key 盲发。

## 8. 组合与非目标

- 顺序与 XOR：保留实际选中边及固定 Definition 版本；不能猜“新图应该怎么走”。
- AND：持久记录所有必需分支和各自验收；缺一个分支不能关闭父义务。
- 外部授权：执行能力有效不代表业务同意发布；技术补证不等于自动授权。
- 版本演化：新 Definition 发布不会自动改变旧实例的固定合同；受控迁移需保留旧效果、原验收及待办。
- 运行证据：规格已接受、候选已测试、安装已生效、自然自动接单、原业务完成，五层不能相互替代。

## 9. 如何精化到真实实现

对每个抽象动作，留下**事实所有者／准确版本 → 服务端或持久提交点 → 重启后发现者 → 执行者实际回执 → 原验收证据**。任意一条缺失，不能用文件名或汇报补齐。

建议先取一个正常业务、一个明确失败、一个丢响应、一个修复者失败样本。独立检验：

- S1：丢通知、进程双退、已有义务无人认领、两个等待项同窗。
- S2：给假 PASS、已解决 Case、只达 TERMINAL 的反例。
- S3：同一原键重放、不同键同载荷、旧代迟到回复、已生效但无回执。
- L1：持续有资格但因查询遗漏而永远空扫的责任。
- L2：修复子任务完成后回到原目标，并按原 AC 完成；计入所有 Assisted 技术接力。

公开的 [有限检查器](model_check.py)只覆盖一个合成两步系统及刻意的错误变体，模型通过**不证明**无限并发、真实权限或生产采用。方法与报表格式见 [VALIDATION.md](VALIDATION.md)，历史同构反例见 [EXAMPLES.md](EXAMPLES.md)。
