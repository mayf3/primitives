# Agent Workflow 的验证与验收边界

这是“能推翻模型的测试计划”，不是已经验收生产系统的报告。检验需绑定：**准确源码或已安装制品、原任务/定义版本/visit、输入摘要、执行权限与环境、原验收、日志及回执**。

## 三条安全性、两条活性

| 性质 | 可失败的测试 | 通过只证明什么 |
|---|---|---|
| **S1 责任连续** | 结果保存后断掉发送、消费者退出；同窗两笔待办；一项结果 CONSUMED 后暂停 | 当前范围内没有静默遗弃，原责任和下一责任可恢复 |
| **S2 真正验收** | 工件自填 PASS、只解决 Case、只达 TERMINAL、错候选/错 visit、遗漏原 AC | 可信验收器对这些反例拒绝假完成 |
| **S3 效果安全** | 响应丢失后原键重放；同主体同载荷不同键；迟到旧代与重复通知 | 可观测的逻辑业务效果未被重复；消息可以重投 |
| **L1 接续** | 消费者周期运行却永远漏掉某类已就绪责任；接单后退出，重启再扫 | 在明确公平与可用性假设下会重新发现并接单 |
| **L2 原目标接受** | 治理者先失败一次、无效修复先被拒、有效修复采用后恢复父任务 | 在此故障族、此版本与原 AC 下闭环，不代表所有故障 |

## 固定验收链

    原业务创建
      → 当前义务由已运行消费者自然发现
      → 合法 Agent 入站并完成一步
      → 结果保存且核证
      → 真后继持久建立
      → 再次自然发现和接单
      → 原业务按原 AC 完成

测试注入者可以按已批准边界制造故障并观察；**不能在测试主进程里替失效消费者调用 resume、替后继角色执行或直接修改权威数据库**。需要人工辅助须记 Assisted，并定位第一条缺失连接。

对双端退出至少覆盖：(A) 工件已持久化，下一事务未提交；(B) 外部事务已生效，调用方尚未取得可用回执。须保留同一原操作信封、原键和身份关联，恢复后记录**谁**从**哪份持久记录**认领义务、**凭什么**判断业务效果及**谁**实际接单。

## 四种独立状态轴

| 轴 | 建议值 | 验证口径 |
|---|---|---|
| `model_status` | proposed / bounded_checked / independently_reviewed | 形式定义、有限检查或独立审阅，与生产无关 |
| `implementation_status` | proposed / sandbox_tested / installed | 固定源码、隔离实跑、安装哈希 |
| `operational_status` | not_observed / assisted / natural_partial / natural_e2e | 触发来源与完整业务回执 |
| `acceptance_status` | unknown / partial / failed / passed | 原目标当前可判定的证据 |

不要把 `CONSUMED` 写成 `GREEN`，把“已登记”写成“有人接单”，把“安全拒绝”写成“业务完成”，或把新候选测试当安装版的结果。

## 两份责任与几个典型变异

在真实执行接续前，以合成 A/B 两笔业务义务检查：

1. **误用结果**：只有 B 结果，A 仍然开放；错误候选/visit/attempt 的结果不得关闭 A。
2. **丢后继**：A 结账前进，但 B 没有 durable entry 或消费者；S1 必须报错。
3. **盲重放**：A 已执行而回复丢失，换键再试导致两次效果；S3 必须报错。
4. **伪完成**：A 未执行、只生成文字 PASS，却被关闭；S2 必须报错。
5. **死等**：A/B 已就绪，却始终没有可用发现者；L1 在满足前提时不能被宣称通过。
6. **无权威读回**：保留 UNKNOWN 可以安全，但不得在没有可区分事实时承诺 L2 必达。

可运行 [有限检查器](model_check.py) 会枚举一个精简的 A→B 串行模型，并对丢后继、伪 PASS、盲重发、失去消费者、无对账入口给出可复查的反例。它**不**复现真实生产数据或任何内部审阅结果中的状态/边计数。

    python3 domains/agent-workflow/model_check.py
    python3 tools/primitives.py validate
    python3 -m unittest discover -s tests -v

## 什么时候能声称生产无人值守？

对确定的任务族/故障族，需给完整的“原目标 → 已运行发现者 → 合法接纳 → 真实业务执行 → 原验收 → 父任务完成”的同版本证据，且在已声明的 \(\operatorname{Env}\) 内出现故障也能自动恢复。有限模型测试的成功不能替代真实角色、真实凭据、合法 Definition、发布签核及外部效果。没有数据、权限或物理动作，合法的“持续等待并自动恢复条件”也是正确行为，但不是完成。

## 原语本身如何修订

先冻结输入范围和判据，再用陌生业务任务检查这八项候选是否有遗漏、重叠或隐藏在上游的成本。删除某项时用其他方法重建同等可观察区别；如果把责任转移进模糊参数，不算真正简化。
