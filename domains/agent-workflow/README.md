# Agent Workflow：无人值守执行原语

**把复杂目标拆成可检验的小工作；由持久工作流负责接单、交接、失败治理与恢复，不要求每个 Agent 理解整个系统。**

版本 **0.3.1**（2026-11-20）。本模块是**公开的、平台无关的候选方法与抽象数学模型**。0.1.0 来自较早 v1.1 概念稿；0.2.0 补入后续评审中的信息集、全后继进展、状态充分性及不可信报告边界，并用 Lean 证明明确限定的切片。0.3.0 将证据与进展统一为关系观测，并从初态归纳推出逐边界真值包含。0.3.1 收紧宏执行合同：有限返回之外，每个返回都须符合模型，不能只选择后来一次合法返回。完整较新源稿同步和生产精化仍待完成；不复制私有运行记录。模型、合成反例与条件证明不是对生产系统的正确性认证。

## 本域的责任

本域区分：用户目标与控制节点、持久义务与一次消息、尝试与业务效果、可观察证据与未知世界、结果消费与验收成功、合法阻断与责任遗弃。**不**替业务负责人判断文章、购物、家庭活动或生产授权的真值。

    原目标及固定验收
      -> 持久化当前义务 -> 合法消费者接纳
      -> 小节点执行/产生工件 -> 独立或机械核验
          -> 合格：正式交接下一义务
          -> 可修故障：持久治理 -> 修复验收 -> 原任务恢复
          -> 外部效果 UNKNOWN：原命令对账，不盲重放
          -> 真实人类门：持久等待决定，答复后恢复
      -> 原业务标准满足才关闭

图走到 TERMINAL、Case 被解决、Agent 自报 PASS、通知 DELIVERED 或定时器运行，都不是独立的原目标完成证明。

## 最小合成例

测试 Agent 收到准确义务、候选版本、原验收项、允许工具、隔离运行入口及输出位置；只交原始日志、退出码、工件与失败阶段。执行内核按原版本和授权建立下一责任，独立验收者对业务意义负责。Agent **不**自行扩权、取消原任务、降低标准或为自己签发验收。

## 本版状态与命令

- **状态与规范**：S1–S3、L1–L2 是待检验条件，未获实际生产端到端证明。
- **有限模型**：[model_check.py](model_check.py) 仅验证合成的两项串行责任与有限故障变体；不证明无限并发。
- **Lean 切片**：证明信息集条件进展、关系状态充分性及可靠门隔离任意报告；实际合同满足性、概率模型及生产采用另证。
- **适用前提**：原目标可验收、身份合法、事实可观察；永久缺外部数据、物理动作或授权时，不承诺必达。
- **最小性**：八个候选入口未证明独立、最小或完备。
- **实现边界**：本仓库不建立新 Scheduler、权限系统或运行账本。
