# 写作动作

本页八个动作是 **0.1.0 整合候选**，由原仓库的方法、修订与声音说明重新组织。每项都可单独调用；顺序和组合由当前作品决定。动作的共同边界见 [使用指南](GUIDE.md)，来源关系见 [迁移记录](MIGRATION.md)。

<a id="choose-angle"></a>
## 选切口

**ID：`writing.choose-angle`**

**何时用：**材料很多，却不知道这次具体讲什么；原方向尚在探索，或作者明确希望找一个更值得讲的角度。

**做什么：**从材料能支撑的内容中选一个问题、处境或观察焦点，说明面向谁、这段文字要提供什么。在最能体现差别的位置直接试写，必要时给少量不同候选，让作者通过文字作选择。

**保护什么：**候选不冒充已确认方向。已有明确方向的定向修改，不因编辑偏好悄悄重开选题。作品可以让人理解一个区分、看见一种处境、欣赏表达或获得陪伴，不强制每篇交付方法论。

**怎么检查：**指出具体用了哪些材料；试写是否真的呈现了拟议重心；为此省去了什么、还缺什么。作者选择记录为选择，不能写成“读者一定更感兴趣”。

**例子：**同一份活动记录可以写“主持人怎样调整环节”，也可以写“一句参与者反馈带来的未知”。两者都是候选，不用先判定其中一个有结构错误。

<a id="find-material"></a>
## 找材料与标缺口

**ID：`writing.find-material`**

**何时用：**已有判断但支撑不足，故事关键处没有来源，或不同材料的范围与说法发生冲突。

**做什么：**定位当前问题真正需要的事实、原话、例子和限制，保留来源及位置。将可以使用的材料与尚缺的信息分开；缺口写到能继续寻找或决定缩小范围的程度。外部研究只在任务需要且获得相应授权时展开。

**保护什么：**材料快照不为配合结论被重写。不能把来源作者的意见升级成已核验事实，也不能把编辑解释塞回材料。缺少动机、内心或结局时保留未知；不要求把所有材料都写进正文。

**怎么检查：**关键说法能否回到准确位置，适用范围和归属是否保留；新找到的材料是否真的填补所说缺口。尚未核对的来源如实标记，不因存在链接就称已经验证。

**例子：**材料只有“一位参与者说想再来”，就保留一位的反馈；若想写“多数参与者更满意”，应补相应证据或撤回这层外推。

<a id="shape-middle"></a>
## 搭中段

**ID：`writing.shape-middle`**

**何时用：**观点、例子和段落都有了，却在重复或堆放；读者需要自己补出论述中间的桥。

**做什么：**先恢复当前稿每部分实际承担的作用，再围绕这次作品目标决定保留、合并、前移或补充什么。必要时写一份很短的结构草图，并试改能体现变化的段落。

**保护什么：**结构草图是编辑解释，不是读者已经获得的效果。多个例子可以共同支撑一个判断；不要求每段都出现问题、反转或一次认知升级。技术说明中的必要前提和故事中的有用停留不因“推进不够快”自动删除。

**怎么检查：**关键结论是否有需要的前提；每部分的作用能否在正文里找到；删掉或合并后，事实、声音、铺垫和限定由哪里承接。多个顺序均可行时说明得失，不制造唯一结构。

**例子：**三个案例都说明同一个边界，可以并列形成一组依据，再作一次解释；不必把它们写成三次相同的总结。

<a id="connect-relations"></a>
## 接关系

**ID：`writing.connect-relations`**

**何时用：**段与段之间跳跃，结论与证据接不上，或对谈下一轮没有真正回应前一轮。

**做什么：**明确这里需要的是支持、限定、对照、条件、举例、回应还是先后关系，再用材料能支持的内容把它接上。缺少依据时呈现缺口或改弱结论，不能仅加“因此”“实际上”掩盖断裂。

**保护什么：**先后不自动构成因果，人物自述动机不等于客观原因，同意不等于证明。对谈回应可以补充、确认、澄清、追问或提出有根据的反例，不强迫制造争执。

**怎么检查：**读前后文，指出连接所依赖的材料和前提。有新因果或必然推论时，可寻找与材料相容的反例；没找到反例仍不等于证明。问答检查下一轮是否提供了真实回应，而不是重复题目或读下一张提纲。

**例子：**已知“执行结束”，可以继续问“结果是否生成”；不能改成“执行结束，所以结果已经有了”。

<a id="sequence-reveal"></a>
## 调选材与揭示顺序

**ID：`writing.sequence-reveal`**

**何时用：**材料与方向大致成立，作者希望比较不同的重心、披露顺序或留白。

**做什么：**用现有材料试一个能显示差别的候选，例如先给观察再讲背景，或让某段前史进入正文。分别说明选了什么、略去了什么、先后次序怎样变，给实际文字供比较。

**保护什么：**现实发生顺序与讲述顺序分开；重排不能暗改事实因果。固定材料可重新措辞，但不能新增场景、动作或感受。不同候选的信息覆盖改变时，不能把结果差异全部归给语感或顺序。

**怎么检查：**对照同一材料包检查新增与删去的信息，以及时间、归属和连接词。留白是否符合本次目标，必要限定是否仍在恰当位置。没有受众数据时只陈述编辑取舍，不预设哪版更吸引人。

**例子：**直叙可以保留当晚的一次动作与反馈；另一个候选加入材料里已有的前史。两版是在共同材料库里做了不同选材，不是严格的“只换顺序”实验。

<a id="tune-voice"></a>
## 调声音

**ID：`writing.tune-voice`**

**何时用：**口播难说、指代难跟，稿子呈现机械路标，或角色失去了已有的语言差异。

**做什么：**定位具体片段，尝试具体动词、信息拆合、自然限定、停顿或更有内容的回应。以作者提供的声线、稿件中的可靠线索和媒介为依据，交付局部表达候选；允许保留正式精确的原句。

**保护什么：**更顺口不能换来更强的事实、虚构经历或统一人设。不按禁词表批量改写，不设短句配额，不强制幽默与认知冲突。重要原句的犹疑、幽默、铺垫或归属需要有承接。

**怎么检查：**分别检查意义忠实、声音适配、实际可说性。用文字检查只能报告编辑判断；实际朗读与真人试听按各自过程记录。具体方法见 [VOICE.md](VOICE.md)。

**例子：**将“尚不能据此确认全面恢复”改得口语化时，仍不能添成“消息根本没发出去”。

<a id="targeted-revision"></a>
## 定向修补

**ID：`writing.targeted-revision`**

**何时用：**已有明确的事实、逻辑、回应或表达问题，或者用户只要求修改指定段落。

**做什么：**锁定当前版本和准确原句，给能解决问题的具体修改。可以替换、插入、删除、移动、拆分或合并；在有效候选间比较语义风险、无关变动和作者返工，而不是只选字数最少的改法。

**保护什么：**已获授权的范围直接完成；范围之外的方向变化单独提出。删除不等于功能已补回，移动不等于因果未改变。建议、作者采用、实际应用、完成检查分别记录，详见 [修订协议](TRACE_AND_REVISION.md)。

**怎么检查：**候选是否实际解决了定位的问题；原句承担的必要功能是否保留；相邻段、后文回指和上一轮修复是否受到影响。没有检查全文就不声称全文无问题。

**例子：**把“所有用户都更快”改回“在这次十二人试验中，完成任务的时间更短”，并查看后文是否又外推成普遍结论。

<a id="review-and-stop"></a>
## 回查与停笔

**ID：`writing.review-and-stop`**

**何时用：**一次改动结束、多轮审稿后，或继续修改的收益已经不清楚。

**做什么：**对实际变更检查受影响的材料、解释、声音和前后关系，并核对已经解决的问题。任务已满足且没有新的关键缺陷时结束；对合理风格分歧只交代取舍，不为继续产出制造问题。

**保护什么：**没有发现错误不等于完整证明。作者选择不等于受众实测，模型判断不冒充真人反馈。未采用的探索不偷偷并入正文；新材料或新请求可以重新开启讨论。

**怎么检查：**说清检查了哪个版本、哪些位置、结果和未查范围；确认是否完成本次请求，而不是完成一张无关清单。若需要效果证据，另做适合受众与媒介的观察，不把未运行的计划写成通过。

**例子：**第一轮修好范围，第二轮仅压缩开头，回查确认限定仍在即可；不必为了第三轮“更有力量”重新提高结论强度。
