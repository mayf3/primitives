## 为什么需要本次整理

main 的 README 和 METHOD 仍以 D/C/U/R 四类对象组织默认说明；PR 候选简化了日常流程，增加直接试写与局部交付，但其 README、METHOD 和 SKILL 依然以 D/C/U/R 解释系统。

因此，“前台按创作动作、后台按需保留材料—新解释—成稿”并不是已经存在于上游的完整动作版。本次在保留来源的基础上完成入口整理，不把新内容冒称为原文，不把未合并 PR 宣称为正式稳定版。

## 保留和改变了什么

保留作者控制、材料边界、固定材料与自由虚构的区别、准确版本锚点、高承载表达保护、局部修订回查、声音与回应检查，以及受众效果的证据边界。

改变默认检索方式：使用者按“选切口、搭中段、调声音”等当前动作进入，不先学习对象字母表。后台需要回查时才记录来源、作者或编辑新增解释、成稿位置和版本关系。八个动作的分组与本模块措辞属于本次整理，并非学界公认或已经验证的最小集合。

没有新增跨领域通用对象，也没有把其他领域的状态导入写作。没有创建或安装新的 Skill，没有修改上游源 `SKILL.md`。

## 旧记录怎样继续读

以下只帮助理解历史缩写，不是新的强制映射或存储迁移：

| 旧表达 | 在日常工作里怎样使用 | 保留边界 |
|---|---|---|
| D / Direction / Author Contract | 作者方向、受众、媒介和本次要求 | 已确认方向与编辑候选分开；现稿呈现不能倒改作者约定 |
| C / ContentItem | 查清具体说法、事件、范围和来源 | 其中可能包含材料，也可能包含推论，不能统统归作原始材料 |
| U / Unit | 当前成稿版本、准确位置、说话人和表达 | 多重功能的原句可改，但需承接必要作用 |
| R / Relation | 按需检查支持、限定、对照、回应或先后 | 旧关系名不自动证明关系成立；先后不等于因果 |
| E / Event | 需要叙事时查看事件材料 | 不补造内心、动机或结局；未知继续保留 |
| B / Beat / Move | 按需理解当前部分的讲述作用 | 属于作者或编辑解释，不是每段必须出现的心理变化 |
| RS / ReaderStep / Reader Evidence | 读取预期、预测和实际反馈 | 旧预测不能直接升级为真人观察 |

不再给这一层重新发明一组字母。旧编号仍可用于读旧审稿意见；新作品只保存对当前问题有用的记录。

## 后续维护

修改本模块时写清使用困难、实际变更与影响范围。若引用上游的新版本，新增精确版本快照与来源记录，不覆盖 `sources/44ed9bd/`；将差异明确引入本模块，而不是自动拉取覆盖。

需要验证方法效果时，再用相同材料与合理预算比较可接受的写法，保留分歧和成本。源文件中的测试为未运行计划，本模块也没有模型或真人效果成绩。结构检查与方法效果验证始终分别报告。
