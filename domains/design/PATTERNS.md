# 四个可组合模式

模式是多个原语对一个情境的组合，不增加原语数量。前三个模式来自[原报告](sources/research-original.txt)，步骤与边界由工作稿整理；第四个根据[后续评审](sources/review-20261113-original.txt)补入。全部仍是待验证的方法安排，按本次困难选用其中必要动作。

<a id="novice-choice"></a>
## 1. 新手选择

**适用问题：** 读者不知道哪个方案适合自己的任务，容易被术语或分散的优点描述淹没。

**组合：** [交代页面承诺](PRIMITIVES.md#page-promise) → [按共同维度比较](PRIMITIVES.md#comparable-options) → [预告入口结果](PRIMITIVES.md#entry-outcome)。

1. 说明本页帮助作出哪一种选择，以及选择所需的使用情境。
2. 按真正影响这个情境的维度并列候选，标出未知项与适用前提。
3. 每个后续入口说明将获得什么，例如查看说明、尝试演示或前往外部服务。

**产物：** 用途说明、有限的共同维度、去向可预测的选择入口。

**检查：** 用户能解释选择依据，知道选择之后会发生什么，并能指出哪些未知条件可能改变决定。

**边界：** 没有可比维度时应先补充资料或缩小问题；不要强制推荐唯一方案，也不要把点击率当作选择正确的证明。

**来源：** 原报告第 94 行明确列出该组合；第 49、98 行提供比较形式及入口细节。机器 ID 和步骤展开是本次整理。

<a id="learning-route"></a>
## 2. 学习路线

**适用问题：** 读者需要推荐顺序，却也可能已有基础、想跳过或随时结束。

**主要组合：** [标明位置与阶段](PRIMITIVES.md#position-progress) + [交代页面承诺](PRIMITIVES.md#page-promise) + [接通下一步](PRIMITIVES.md#next-step)。需要完整收尾时调用[任务终点接续](#task-continuation)，其中包含必要的入口说明与条件呈现。

1. 显示完整路线、当前位置和本步目的。
2. 提供本步内容与任务的完成判据；如果需要声称掌握，另有相应理解任务或测评证据。
3. 选择能使用当前成果的后继，展示推荐理由，并允许按实际依赖跳过、返回总览或结束。

**产物：** 当前位置、本步目的、当前内容、推荐下一步、完整路线和可跳过说明。

**检查：** 用户能说明现在在哪、已完成什么及可继续做什么；另用理解任务检查学习是否发生。

**边界：** 阅读过、勾选过与理解了是不同状态；路线只提供推荐，不把没有依赖关系的内容伪装成必修顺序。缺少完成证据时不生成可信度过高的进度声明。

**来源：** 原报告第 163 行给出该结构，第 100、279 行讨论可退出的下一步与理解检验。0.2.0 按位置、后继选择与状态证据的修订重新说明分工，没有新增学习效果证据。

<a id="diy-preflight"></a>
## 3. DIY 采购前检查

**适用问题：** 用户准备投入费用或开始实物操作，但设备、兼容性、权限、风险或验证状态可能不满足要求。

**组合：** [前置必要条件](PRIMITIVES.md#prerequisites) + [标明位置与阶段](PRIMITIVES.md#position-progress) + [让变化可见](PRIMITIVES.md#visible-change) + [保留恢复路径](PRIMITIVES.md#recovery-path)。若低投入步骤尚未确定，再调用[接通下一步](PRIMITIVES.md#next-step)选择后继。

1. 说明项目实际状态，列出会影响开始或付款的条件，并区分已满足、未满足、未知。
2. 定位当前核对阶段，给出已经选定的资料核对或低投入步骤，说明进入采购的条件。
3. 每次核对后显示实际得到的结果、依据及仍未知的条件；界面状态不替代设备兼容或实物验证。
4. 条件不满足时，保留已完成检查，提供修正方案或返回相应步骤的路径。

**产物：** 有条件的阶段安排、明确的采购前提、可见的检查结果及修正入口。

**检查：** 给设备与经验不同的用户情境，请其判断今天可做什么、何时该投入、条件不满足时如何继续。

**边界：** 文档整理完成、数字模拟通过和实物验证不能互相替代；方法模板也不能替实际项目判断通过。采购的现实不可逆部分不能用虚假的“撤销”承诺遮蔽。

**来源：** 原报告第 94 行列出该组合，第 102、165–177 行给出应用建议。这里的步骤是可复用提案，不声明任何具体项目当前已达到这些阶段。

<a id="task-continuation"></a>
## 4. 任务终点接续

**适用问题：** 当前阅读或任务告一段落，需要同时说明已有产出、建立后继、交代条件与去向，并允许暂停、返回或自由探索。

**核心组合：** [接通下一步](PRIMITIVES.md#next-step) + [预告入口结果](PRIMITIVES.md#entry-outcome)。路线阶段不明时补[标明位置与阶段](PRIMITIVES.md#position-progress)，条件影响行动时补[前置必要条件](PRIMITIVES.md#prerequisites)，操作结果不明时补[让变化可见](PRIMITIVES.md#visible-change)。无需每次全部调用。

1. **确认可用的当前产出。** 区分访问到这里、阅读结束与真正完成任务。完成或掌握的判断必须有任务自身的证据；位置原语用于定位，反馈原语用于显示已有状态。
2. **选择并接通合适后继。** 依据目标、当前产出、已知条件与候选可用性，建立能继续推进的动作。若只有相关内容而无明确依赖，就按探索方向呈现；若没有可执行后继，如实说明并允许结束。
3. **说明为何继续及会发生什么。** 给出与当前成果的衔接理由，入口说明动作、对象及结果类型；必要条件在影响选择或行动之前可见。
4. **保留结束与返回。** 提供任务确实需要的暂停、总览或其他方向；需要保留输入或画布位置时另用恢复路径。

**产物：** 当前产出说明、可执行且有理由的后继、可预测入口、必要条件及结束或返回方式。

**检查：** 沿完整路径核对能否执行、是否产生实质新增信息或任务进展；请读者说明为什么继续、去哪、可以停在哪里。标签准确但目标没有推进，也不能算接续成立。

**边界：** 该模式不负责制造完成证据、不强行推荐唯一顺序，也不把所有相关链接都改成必修步骤。仅需改一个现有链接的文案时，直接使用入口原语即可。

**来源与裁决：** 后续评审建议将整个 `design.next-step` 降为该模式。0.2.0 采纳完整流程进入模式库的建议，同时保留“选择并建立合适后继”的独立候选动作；位置、条件和入口说明尚不能独自完成这一决策。详见[版本评审](REVISIONS.md#next-step-decision)。

## 组合记录

每次使用只记录本次需要的原语、选择原因及冲突如何处理。简洁与解释充分、引导与探索、一致性与情境适配、氛围与可读性之间的权衡仍需保留，不能用“模式已应用”替代具体判断。参见[验证与状态](VALIDATION.md)。
