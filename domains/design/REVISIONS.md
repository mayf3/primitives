# 设计原语 0.2.0：评审裁决与兼容说明

**日期：2026-11-13（北京时间）。基线：0.1.0；当前：0.2.0。**

本轮依据用户追加的[独立评审原文](sources/review-20261113-original.txt)，重新检查动作粒度、重复、覆盖缺口和验证办法。原文逐字节保存；以下处置是本次工作解释，既不改写评审，也不将其推演视为真实用户结果。

当前继续提供 **10 个候选动作、4 个组合模式**。十项尚未证明全部必要或最简；本轮优先修清边界，保留可挑战的数量。评审提出的“9 项 + 4 模式”保留为比较方案，不直接升为定论。

## 1. 这轮采用的粒度标准

一个候选动作应能指向明确困难、一个连贯的干预目标，以及可界定的实现分支。判断是否重复，要同时比较改动对象、所作决策和预期可观察结果；仅有相似名称或共同的认知目标还不够。

为避免把任意模式重新概括为一个大动作，每项还需明确直接决定的对象与产出，指出哪些判断作为输入、哪些需要调用相邻原语。某个实现分支若完整承担了另一原语的独立决策，应显式组合，不能只靠重新命名共同目标将其吸收。

多个独立目标需要分别判断、可以单独成立时，放入模式组合。实现包含几步不直接决定它是不是原语：恢复可能需要保留状态再提供重试，比较可能需要选择维度再对齐条件。若一面接受这些分支，一面用“超过一个动作”单独否决下一步，尺度就不一致。

因此本版暂不用“理论上不可再分”定义已完成的成果，也不预设七、九或十这个数。症状索引可以提供多个入口，动作和模式分别承担解决工作。最小性仍需删除反例、替代成本和未见案例的实际使用来检验。

## 3. 为什么本轮暂不把下一步整个降为模式

评审的替代方案包含位置或阶段、后续准入条件和入口结果。这三者可以说明“在哪、能不能做、点了会得到什么”，却没有明确承担“依据当前目标选择并建立哪一个后继”。把这项决策默认为已经做完，会在减少条目时漏掉实际工作。

**合成反例：** 一个读者的目标是把自己的材料做成 PPT。页面已经说明当前位置，现有链接的标签都准确，所有候选的条件也都满足；但链接只通向又一篇同样的概念说明。此时改位置标记、条件提示或入口文案，都不会自动建立“使用自己的材料产出一份可检查提纲”的后继。如果项目决定提供这样的后继，仍需核对实际可用内容、选择该动作并接通路径。

据此将职责拆清：

- **动作 `design.next-step`：** 以当前成果、目标和条件为输入，选择并接通合适的可执行后继。
- **模式“任务终点接续”：** 组织当前产出、必要阶段或状态说明、后继选择、入口结果、条件和退出安排，按实际困难组合。

这项反例只说明评审给出的替代推演尚不充分，不证明下一步必须永远保留为原语。如果后续采用模式承接后继选择，而且它可发现、可独立调用、不增加漏检或隐藏决策，可以重新归层。届时应明确功能迁移到了哪里；减少一个标题本身不能证明最简性。

## 4. 用什么案例检查本轮边界

下表均为**合成分析情境**，包括评审提出的论文工作台情境及本轮新增反例。它们参与了这次改稿，不能再当作未见案例、真实网站缺陷或已完成的用户测试。

| 情境 | 本版如何判断 | 避免的误用 |
|---|---|---|
| 从外部搜索进入教程，只知标题不知本页交付什么 | 页面承诺 | 用面包屑替代内容用途说明。 |
| 入口标签清楚、条件都满足，却在没有信息、能力或任务状态变化时反复回到原问题 | 下一步；需要完整收尾时用接续模式 | 只改标签便声称任务已经推进；反过来也不能把有价值的重试或重新比较判成无效循环。 |
| 公式在上方、符号解释在几屏之后 | 关系外化中的就地对照 | 为解决跨屏参照强加一张大图。 |
| 一段定义过于抽象，只缺一个普通例子 | 先补内容说明与例子 | 把所有难懂文字都纳入关系外化。 |
| 不同实验条件下的方案数值被直接放在同一表格 | 共同维度比较，显式说明条件与不可比处 | 为表面整齐填造统一数值。 |
| 参数改变后需要比较结果，差异不易定位 | 让变化可见，保留必要基线和条件 | 每次反馈都显示复杂 Diff，或从变化直接推导因果。 |
| 失败后有效参数丢失、返回图谱时画布重置 | 恢复路径 | 只有错误提示，没有可继续工作的状态。 |
| 图谱中找不到当前节点或刚访问过的节点 | 位置与阶段，按需显示访问足迹 | 标为“已学会”或编造完成百分比。 |
| 只有提交后才知道字段格式、单位和范围 | 前置必要条件，同时检查实际校验 | 把新增提示当成已经实现防错机制。 |

## 5. 哪些结论没有直接采纳

- **“覆盖 90% 以上”“9 项最简”“应控制在 7～8 项以内”：** 没有对应的任务总体、独立样本或比较结果，不能作为本版覆盖率或数量依据。
- **“三个节点以下不准画图、线性关系一律禁图”：** 节点数和形状不足以替代具体理解任务的判断。应比较读者能否正确对照和理解关系，而非设置无依据的统一阈值。
- **“让变化可见负责检验真正完成”：** 调整为它呈现已有状态及完成证据；测评或任务核验保留自己的职责。
- **“恢复保证已有劳动不清零”：** 限定为系统实际能够保留或恢复的部分，说明不可逆损失。
- **用两个 Agent 或极少读者直接宣称显著效果：** Agent 试标只能帮助找术语和路由分歧；真实读者观察另外记录。小规模探索适合发现反例，不直接估计覆盖率或显著改善。

评审引用的理论名词在这轮没有重新溯源核验，保持材料中的主张身份。上述裁决主要基于定义一致性、动作能否被替代的分析，以及明确标注的合成反例。

## 6. 兼容与接入

- 十个动作的机器 ID、`PRIMITIVES.md` 原有锚点均保持。`design.position-progress` 的显示名改为“标明位置与阶段”，旧名保留在卡片及索引关键词中。
- `design.next-step` 仍是动作，原路径仍可解析；不创建相互指代不明的新旧 ID。引用它的项目应复核自己是仅选择后继，还是需要完整接续模式。
- 现有三个模式保留，新增“任务终点接续”；四个模式有显式锚点。机器目录仍登记十个动作，具名模式链接置于关联卡片，`find` 可以找到该入口。
- 0.1.0 中“纯举例”的使用不再自动符合关系外化；位置、反馈与掌握的分工也已收紧。历史记录保留原版语义，采用 0.2.0 的项目需检查受影响用法，不能只替换版本号。
- 两个跨域组合逐项复审后固定设计 `0.2.0`：播客入口例仍需要后继选择；视频观看例只定位章节，不声明掌握。组合本身继续是 `synthetic` / `not-run`，观察为空。
- 原研究快照和全部旧来源哈希不变；新评审独立追加来源 ID `design-review-20261113`。其他三个领域的定义与模块版本不随本次修改改变。

## 7. 下一轮如何推翻或修订这版

按[方法版本验证](VALIDATION.md#method-revision)区分两类任务：审阅者能否稳定选到合适动作，以及真实读者是否受益。优先检查后继是否漏掉、普通举例是否误入关系外化、访问足迹是否被误读为掌握，以及就地对照与关系表示是否仍需分开。
