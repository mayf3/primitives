本版为 **0.2.0**。十项从[原报告](sources/research-original.txt)第 83–92 行总表继承，按[后续评审](sources/review-20261113-original.txt)修订边界；十个机器 ID 和原有显式锚点全部保留。“十项”是当前可调用的候选集合，尚未证明必要、正交或最简。逐项处置和仍有争议的地方见[版本评审](REVISIONS.md)。

原报告第 98、100、102、104 行详述四项，其余六项由 0.1.0 整理补足操作说明；机器 ID、操作性增补及本版修订均属工作解释。每张卡片中的“来源”追溯原始依据，“整合增补”保留首次整理边界，“0.2.0 修订”说明这次改变。

本域暂以“一个明确困难、一个连贯的干预目标、有边界的实现分支”作为动作粒度。多个可独立成立的干预目标在[模式](PATTERNS.md)中组合。这是实用判据，不是理论上不可再分的证明；诊断入口数、实现分支数和原语数量不要求相等。

每项还需说明自己直接决定的对象与产出，哪些判断作为输入、哪些应调用相邻动作。如果某个实现分支完整承担了另一原语的独立决策，应显式组合；不能仅用更大的共同目标把其他动作吸收到本项。

“预期检查”表示未来可以怎样观察，不表示已经获得结果。外部理论、研究与规范来源尚未由本次整理独立复核，详见[来源登记](sources/README.md)。

<a id="page-promise"></a>
## 1. 交代页面承诺

**ID：** `design.page-promise`

- **触发：** 读者无法判断此页用途，或入口承诺与页面实际能交付的内容不一致。
- **具体动作：** 在首屏用一句可核对的话说明“这页能帮谁回答什么或完成什么”。让标题、简介和主要内容共同支持这项承诺；若内容尚未验证或尚不可完成，说明当前能获得的结果。
- **预期检查：** 不解释页面，让读者用自己的话说出用途，再核对其预期是否与实际内容一致。
- **边界与代价：** 不将一句话变成夸大效果的口号；也不在已足够清楚的首屏重复叠加说明。承诺必须与真实可交付状态相符。
- **相邻分工：** 本项检查落地后的用途与可交付边界；[预告入口结果](#entry-outcome)检查点击前的目的地预测。用户从外部直接进入时，仍需要前者。
- **组合入口：** [新手选择](PATTERNS.md#novice-choice)。
- **来源：** 原报告第 83 行；第 5、11、124、165 行讨论用途与承诺—状态关系。
- **整合增补：** 原报告仅有简表定义；这里的写作步骤、逐项检查和边界汇总由本次整理补写，尚无本次用户验证。

<a id="position-progress"></a>
## 2. 标明位置与阶段

**ID：** `design.position-progress`；0.1.0 显示名：**标明位置与进度**。保留旧 ID 与锚点。

- **触发：** 从搜索或外部链接直接进入后不知页面类型；路线中不知道当前阶段；自由探索时分不清当前位置和刚才访问过的内容。
- **具体动作：** 显示页面或节点身份、所属结构与回到总览的路径。有可靠顺序时标明本步、总阶段及前后关系；无固定顺序时按任务需要标记当前位置和访问足迹。使用“已访问”描述真实访问记录。
- **预期检查：** 让读者指出“我在哪、属于哪里、怎么回总览”；路线中再说明前后阶段，开放探索中再指出哪些只是访问过。核对其是否把访问或所在阶段误当成掌握证明。
- **边界与代价：** 访问过不等于读完，读完不等于学会。无固定顺序时不伪造步骤或完成率；位置标记也不应压过任务本身。掌握度与实际操作完成需要相应测评或任务证据；[让变化可见](#visible-change)仅负责呈现已经获得的状态与证据。
- **组合入口：** [学习路线](PATTERNS.md#learning-route)。
- **来源：** 原报告第 84 行；第 9、32、163 行讨论当前阶段和学习路线。
- **整合增补：** 原报告仅有简表定义；“进度所指对象”、不伪造百分比及具体检查由本次补写。
- **0.2.0 修订：** 采纳评审中对位置、阶段与访问足迹的区分；不采用把“真正完成的核验”全部交给反馈呈现的说法。

<a id="entry-outcome"></a>
## 3. 预告入口结果

**ID：** `design.entry-outcome`

- **触发：** 相似入口分别通向摘要、节目、外部服务、路线或图谱，读者点击前无法区分。
- **具体动作：** 入口文案包含足够的“动作 + 对象 + 结果类型”。例如把“看看更多”改为“阅读本期要点与时间轴”，或“到音频平台听完整节目”。耗时、外站或新窗口提示只在真实且有助决策时展示。
- **预期检查：** 在点击前分别询问用户预期，记录预测与实际目的地是否一致；脱离装饰背景仍能理解链接作用。键盘使用者应能获得同等结果线索。
- **边界与代价：** 不适用于有意隐藏目的地的探索型叙事；不要把每个链接都写成段落。可见文案与可访问名称的对应关系需要独立技术检查。
- **相邻分工：** 已有入口去向不清时调用本项；入口去向清楚但没有合适后继时调用[接通下一步](#next-step)。两种困难同时存在时再组合。
- **来源：** 原报告第 85、98 行；第 161 行讨论同类入口去往不同页面类型。
- **整合增补：** 原报告已有完整卡片；本次压缩表达并增加“提示只在真实时展示”的编辑约束，未新增外部核验。

<a id="next-step"></a>
## 4. 接通下一步

**ID：** `design.next-step`；原报告详细卡片别名：**接通当前可完成的下一步**。

- **触发：** 当前内容已经产生可用的结果，但后继动作缺失、不适合当前目标，或来回跳转只重复内容、没有增加理解或任务进展。即使所有入口标签和准入条件都清楚，仍可能存在这个问题。
- **具体动作：** 以当前实际产出、用户目标和已知条件为输入，从已核对的候选中选择并接通一个合适、现在能够执行的后继。说明它如何使用当前成果、推进任务或带来新增理解。没有可执行后继时如实说明，并允许在此结束。
- **预期检查：** 沿后继实际走一次，核对是否可执行、是否推进同一目标；避免在信息、能力或任务状态均未改变时，仅重复返回原问题。返回原题重试、修正输入或重新比较可以是有效后继。请读者说明“为什么现在做这一步，它会用到什么、增加什么”；目的地标签正确但选择仍无助于目标时，本项尚未解决。
- **边界与代价：** 合适的后继可能是练习、比较或实际操作，未必是另一篇文章。开放探索可以给几个有理由的方向；不伪造唯一顺序，也不强迫继续。学习是否发生、操作是否完成由相应任务证据决定，不能靠提供下一步按钮证明。
- **相邻分工：** 本项负责后继的选择与接通；位置标记、条件呈现和入口标签各有自己的动作。完成收尾、分支说明和退出安排的完整流程使用[任务终点接续](PATTERNS.md#task-continuation)。
- **来源：** 原报告第 86、100 行；第 159、163 行讨论页面职责和学习路线。
- **整合增补：** 原报告已有完整卡片；机器 ID、别名归并及对不可执行后继的检查由本次整理新增。
- **0.2.0 修订：** 将原卡片中的收尾、提示和退出安排拆到组合模式；保留后继选择这一候选动作。评审的替代方案尚未明确由谁选择和建立合适后继，因此本轮暂不降级。后续可用未见案例检验该分工，见[版本评审](REVISIONS.md#next-step-decision)。

<a id="prerequisites"></a>
## 5. 前置必要条件

**ID：** `design.prerequisites`

- **触发：** 存在设备、版本、权限、费用、风险、兼容性、验证状态，或输入格式、单位、取值范围等会改变“当前这一步能不能做”的条件。
- **具体动作：** 在条件即将影响决定或操作的位置提前说明：关键投入前呈现投入条件，字段旁呈现填写前必须知道的格式、单位与范围。依照真实依据区分已满足、未满足和未知；以后才需要的细节留在相应阶段。
- **预期检查：** 给设备或输入不同的情境，请读者在投入或提交前判断哪些条件满足、哪些未知、现在能否开始；核对其是否能按真实约束准备有效输入。
- **边界与代价：** 不把全部细节一次性搬到首屏，也不折叠真正影响当前行动的前提。预计兼容、模拟通过和实物验证保持区别。约束说明不能替代实际输入校验、非法状态限制或错误恢复；本项也不承诺覆盖全部防错设计。
- **组合入口：** [DIY 采购前检查](PATTERNS.md#diy-preflight)。
- **来源：** 原报告第 87、102 行；第 165–177 行给出 DIY 应用提案。
- **整合增补：** 原报告已有完整卡片；“已满足/未满足/未知”的展示建议由本次明确化，不代表新增事实或门禁执行结果。
- **0.2.0 修订：** 采纳评审的输入边界提醒，限定为操作前必要条件的呈现，不扩展成全部防错机制。

<a id="comparable-options"></a>
## 6. 按共同维度比较

**ID：** `design.comparable-options`

- **触发：** 用户为了选择要记住多个页面上的信息，或各方案分别描述优点却没有可比较维度。
- **具体动作：** 先明确当前选择真正依赖的维度，再把方案按这些维度并列。统一单位、条件和时间范围；不掌握的值写明未知，不用空白暗示相同。
- **预期检查：** 让用户说明为何选择一个方案、放弃另一个，以及哪些未知值会改变选择；检查是否仍需来回记忆才能比较。
- **边界与代价：** 维度太多会掩盖关键差别；不可比的对象不能靠表格伪造可比性。移动端和辅助技术使用场景需要保留维度与数值之间的关系。
- **来源：** 原报告第 88 行；第 36、49、243–244 行讨论识别、比较形式和问题路由。
- **整合增补：** 原报告仅有简表定义；统一单位、未知值处理及具体提问由本次补写，属于实施建议。

<a id="externalize-relations"></a>
## 7. 把抽象关系外化

**ID：** `design.externalize-relations`

- **触发：** 理解所需的信息已经存在，但符号与解释、代码与注释等相隔太远，或依赖、因果、先后、对应与归属关系仍需要读者自行在记忆中拼接。
- **具体动作：** 把需要一起判断的信息组织为可直接对照的关系。两个实现分支是：将对象与参照就地对齐；将关键连接及其语义明确表示。可以用邻接注释、带标签的文字或表格、局部图，不预先规定必须画图。
- **预期检查：** 请读者找到对应解释、复述关键关系，再判断一个小变化；记录是否仍需跨屏记忆比对，是否把相关误读为因果。纯文字已能完成这些任务时，新增图形需要另有理由。
- **边界与代价：** 仅仅缺一个具体例子、术语未解释或文字写得干瘪，不自动触发本项；先补足必要内容。比较方案的共同属性由[按共同维度比较](#comparable-options)处理。关系表示仍需真实依据、关键条件及非视觉表达；小屏可用就地注释，不强制宽分栏。图有解码成本，但节点数或线性关系也不是一律画图或禁图的门槛。
- **来源：** 原报告第 89 行；第 47、51、57、295 行讨论例子、关系图和图解优势的条件。
- **整合增补：** 原报告仅有简表定义；关系标签、反例提问与误读检查由本次补写，不是原研究已做的实验。
- **0.2.0 修订：** 移出普通举例，明确就地对照与显式关系表示。两分支暂以“减少必须在脑内完成的关系整合”为共同目标，是否仍应拆开保留待检验。

<a id="visible-change"></a>
## 8. 让变化可见

**ID：** `design.visible-change`

- **触发：** 操作后无法判断是否被接收、正在进行、成功、失败，或结果变化藏在大量输出里。
- **具体动作：** 呈现已接收、当前状态、结果或错误及其影响。任务确实需要比较前后结果时，保留相关基线和条件，让变化容易定位，例如并列新旧值或突出变化列；保留必要原始结果供核对。
- **预期检查：** 询问用户操作是否被接收、现在是什么状态、结果依据是什么；需要比较时再问哪些结果改变、相对哪个基线。观察是否因缺少反馈重复提交。
- **边界与代价：** 控件动效不等于有意义反馈；处理中不能冒充成功。状态与完成证据由实际系统、任务检查或测评产生，本项负责准确呈现，不能创造“已验证”或“已学会”的证据。简单操作未必需要前后差异视图；实验结果变化也不能直接解释为已确认因果。
- **来源：** 原报告第 90、104 行；第 181、279 行讨论学习站提案和学习检验。
- **整合增补：** 原报告已有完整卡片；本次整理为分步动作及提问，学习站情况仍是原材料中的待核对假设。
- **0.2.0 修订：** 将有必要的前后差异对照写清楚，区分状态呈现与状态核验，不把所有反馈都要求做成 Diff。

<a id="recovery-path"></a>
## 9. 保留恢复路径

**ID：** `design.recovery-path`

- **触发：** 用户担心点错，或错误后丢失输入、位置与已有成果，需要全部重做。
- **具体动作：** 以“回到可继续工作的状态”为目标，保留仍有效且可保留的输入与上下文，提供可发现的恢复动作。导航返回可恢复搜索词、滚动或画布位置；失败重试保留有效参数；可逆修改提供真实撤销。不可逆操作只说明确实可行的补救与已无法恢复的部分。
- **预期检查：** 在安全情境中模拟一次错误，请用户自己找回任务；记录丢失了什么、是否需要提示、能否从保留的状态继续。
- **边界与代价：** 保留状态不代表无限期存储所有信息；撤销承诺必须与实际行为一致。恢复入口需要可发现，不能只有设计者知道快捷键或隐藏流程。
- **来源：** 原报告第 91 行；第 36、40、106、276、279 行讨论恢复、控制和观察。
- **整合增补：** 原报告仅有简表定义；可逆性区分、模拟错误步骤和存储边界由本次补写。
- **0.2.0 修订：** 将状态保留与恢复动作视为同一目标下按故障选择的实现分支，不要求每次全套实现，也不承诺任何错误都不会丢失劳动。事前提示属于预防，不能代替事后恢复。

<a id="progressive-disclosure"></a>
## 10. 按需展开次要复杂度

**ID：** `design.progressive-disclosure`

- **触发：** 少数人才需要的低频细节遮蔽了当前主任务，而这些细节可以从主任务中独立出来。
- **具体动作：** 先划定当前理解、选择和行动所必需的信息，将其保留可见；其余用可预测的标签按需展开。主内容不能依赖被隐藏但未说明的前提。
- **预期检查：** 初始视图是否足够完成主任务；需要细节的人能否找到入口，并在展开前合理预测其中内容；键盘和辅助技术能否操作。
- **边界与代价：** 关键风险、前提、价格差异和比较维度不能只因篇幅而折叠。每次展开都会增加寻找和操作成本，不能把折叠视为普遍优化。
- **相邻分工：** 信息过多时也应检查重复内容、组织方式和比较结构；按需展开是其中一种动作，不是唯一的信息密度调节办法。
- **来源：** 原报告第 92 行；第 15、55、102、255–257、292 行讨论渐进披露的条件。
- **整合增补：** 原报告仅有简表定义；本次把散落边界合并为操作说明并增加操作性提问，未新增验证结果。
