# 把设计原语落实到网页

**适用于设计领域 0.2.0 的实施补充，整理于 2026-11-13。** 本页细化状态呈现、窄屏阅读与路径接续的检查办法，不改变十个候选原语、四个模式、机器 ID 或版本。按当前问题取用，不要求每次修改都增加一套表单、数据结构或流程。

本页从已有[版本评审](REVISIONS.md)与页面应用复查中提炼实施要点；以下案例是方法说明，不是任何网站的当前运行报告。具体版本、截图、个人进度和项目事实继续保存在相应项目。本页没有新增真实读者观察。

<a id="state-subject"></a>
## 1. 呈现状态前，先说清是谁、什么事、凭什么

“已完成”“已验证”必须有明确对象。应用[位置与阶段](PRIMITIVES.md#position-progress)、[必要条件](PRIMITIVES.md#prerequisites)和[变化反馈](PRIMITIVES.md#visible-change)时，先核对四件事：

| 要分清的事 | 需要回答的问题 | 常见混淆 |
|---|---|---|
| 主体 | 这是作者、当前访客，还是系统的状态？ | 作者拥有某设备，被显示成所有访客都已具备。 |
| 对象 | 记录的是访问、自记、计算、模拟、实物操作，还是理解表现？ | 点过页面或勾选清单，被显示成已经掌握。 |
| 依据 | 谁通过什么记录、操作或检查得到这个状态？ | 绿勾、进度条或动画本身被当成证明。 |
| 适用范围 | 对应哪个方案、版本、条件和时间？ | 一次模拟通过，被推广为任意配置都可复刻。 |

作者公开的项目事实由内容源维护，向访客呈现为只读说明；个人清单是访客自己的记录，使用独立的控件与存储位置，不能覆盖作者事实。不要把文档里所有勾选项统一转换成“我的进度”，也不要用个人存储的缺省值抹掉来源中已有的状态。个人清单可以标“我已核对”，但它不自动证明兼容、安全或学习掌握。

**合成检查：** 作者记录“模拟通过，尚未进行实物测试”；访客勾选“我已阅读材料表”。刷新或换一个访客后，两类状态仍各有主体，作者事实不随访客操作改变，访客也不会被宣称已经完成作者的工作。状态尚无依据时保留未知，不替用户预先确认。

<a id="readable-reflow"></a>
## 2. 窄屏适配要保住阅读与参照关系

响应式布局属于技术基线。[比较](PRIMITIVES.md#comparable-options)和[关系外化](PRIMITIVES.md#externalize-relations)还要求读者能找到“哪个对象对应哪个标签、单位或解释”。二者需要一起检查。

Fiorella 与 Mayer 对[空间邻近原则的概述](https://www.cambridge.org/core/books/abs/cambridge-handbook-of-multimedia-learning/principles-for-reducing-extraneous-processing-in-multimedia-learning/F29A19FCD34C542806F736E0661C05F5)支持将对应文字与图形整合呈现，以减少与学习目标无关的处理。本页据此提出就地参照检查；它不意味着所有内容都应画图，也不指定必须使用双栏或动画。

- **看实际显示，不能只看样式声明。** SVG 的文字会受到 `viewBox` 映射和变换影响；声明的 `font-size` 不等于最终显示尺寸。检查最终截图与渲染几何，而不是只确认没有横向溢出。
- **空间不足时重排信息。** 可以减少次要刻度、缩短标签，把末端名称与数值放到相邻的普通文字区，或提供清楚的表格对照。标签移动后仍需能直接对应曲线或对象；不能为了塞进宽度而丢掉单位、基线和条件。
- **保留必要关系。** 代码与解释、曲线与名称、比较数值与表头在换行或折叠后仍须对应。原本需要同时比较的信息，不应被拆到多个互斥面板里。
- **允许有理由的局部二维布局。** 地图、数据表或关系图确实需要二维空间时，可以提供可发现、可操作的局部滚动或替代视图；周围正文仍应正常回流。不要把“所有内容禁止横向滚动”当作统一规则。

验证时分开记录：正常缩放下的目标窄视口、桌面浏览器缩放、设备模拟与真机。记录实际 CSS 视口、浏览器缩放比例及检查范围；桌面缩放可暴露回流问题，但不等同于触控、虚拟键盘或真机体验。

WCAG 2.2 的[文字缩放说明](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)对应 SC 1.4.4：除字幕与文字图像外，文字应能在不使用辅助技术的情况下放大至 200%，而不丢失内容或功能。[回流说明](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)对应 SC 1.4.10：纵向滚动内容按等效 320 CSS 像素宽度检查，并保留确需二维布局的内容例外。二者是不同的检查，且本页的说明不构成对任何站点的合规认定。

项目可根据受众选择正文或图表标签的实际字号目标，但“12 px”“14 px”等选择不是上述 WCAG 条款规定的统一字号下限。可读性仍需结合显示效果和读者任务检查。

## 3. 后继要使用当前成果，并说明新增收获

应用[接通下一步](PRIMITIVES.md#next-step)时，先选择后继，再用[入口结果](PRIMITIVES.md#entry-outcome)把它说明白。对一条样板路径回答以下问题即可：

1. 当前页面提供了什么可使用的内容或成果？
2. 下一步如何使用它，会增加什么信息、能力或任务进展？
3. 进入下一步需要哪些已知条件，目标页面现在是否可用？
4. 读者怎样暂停、返回，或在条件不满足时继续处理？

把一段重复的回答放到另一个页面，再换一个按钮名称，不会自动产生推进。入口承诺“具体例子”时，内容应提供能支持该名称的具体任务与过程；只有观点概括时，应采用与实际内容相符的标题。

NN/g 的 [A Link is a Promise](https://www.nngroup.com/articles/link-promise/)分别讨论链接文案能否预告目的地，以及落地页面是否及时兑现预期。这支持检查入口与落地内容的对应；选择哪个后继仍是另一个需要承担的判断，不能由标签清楚自动推出。

有价值的重试、检索练习、返回比较和自由探索可以回到旧页面；检查的是本次返回是否帮助任务，而不是要求链接图永远单向。没有真实可执行后继时，可以明确结束或提供探索方向，不制造假任务。

<a id="bounded-implementation"></a>
## 4. 把改动限制在一条样板与相关回归

先用现有问题记录定位本轮目标版本、仍成立的困难和内容源。历史问题已经修复时，保留结果，不为套用原语重新设计。选择一条可以完整点击的样板路径，完成当前必要改动，再检查它影响的返回、搜索、锚点或参数状态。

| 样板类型 | 可以组合的动作 | 需要保住的区别 |
|---|---|---|
| 学习实验 | 关系外化、共同维度比较、变化反馈、下一步 | 预测、模型结果与理解检查分别有自己的作用；图表与表格使用相同条件。 |
| 知识导览 | 页面承诺、入口结果、位置与阶段、下一步、恢复 | 问题解释、来源独有内容与后继信息各有收获；访问足迹不是掌握度。 |
| DIY 复刻 | 必要条件、位置与阶段、变化反馈、按需展开 | 作者进展、访客资源与个人检查分开；当前结论与历史方案分开。 |

这些是选用已有动作的示例，不是每站必须实现的新功能清单。技术信息、历史方案和证据可以按需展开；影响当前选择的费用、条件、未知项与验证边界仍然可见。

内容来自结构化源或生成流程时，修改真实源并重新生成，不只修生成后的页面副本。方法文档、项目实现、部署版本和真实读者效果分别记录；不把页面中的控件状态写回方法仓库，也不公开凭据、私人记录或无关运行数据。

## 5. 留下一段够用的应用回执

在项目已有记录中写清：**观察到什么、选了哪个动作、改了什么、目标版本与检查范围、结果与未验证项。** 继续使用[三个状态轴](VALIDATION.md#three-status-axes)，不新增一个笼统的“全部验证通过”。

实现检查覆盖一条样板及受影响回归后即可收口。需要真实读者判断的假设留给相应观察；Agent 操作通过、结构检查通过和真实用户理解保持区别。只有新证据说明当前方案仍有具体问题时，才扩展本轮修改范围。

## 来源与维护边界

- 方法边界继承设计 0.2.0 的[版本评审](REVISIONS.md)、[原语卡片](PRIMITIVES.md)与[验证指南](VALIDATION.md)。本页将其落实为实施检查，不另立原语或改变旧调用语义。
- 上文两份 W3C 官方 Understanding 页面于 2026-11-13 打开核对相关条款与例外。它们是解释材料，具体符合要求仍以所选标准和实际验收范围为准。此次核对不把旧来源清单中的其他未核对条目自动升级。
- Fiorella 与 Mayer 的 2021 年章节公开摘要、NN/g 上述文章于同日核对。此处只引用已可见的摘要和文章主张，没有宣称读过付费章节全文；它们支持局部设计判断，不证明本仓库的原语数量最小或任何站点已取得用户效果。
- 合成案例用于说明检查方法，不能计入真实用户样本，也不能据此声称原语数量最少或设计效果已经成立。
