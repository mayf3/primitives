# 验证与状态

原语卡片提出的是可观察预测。验证任务是在真实情境中检查预测是否成立，并记录失败条件。本模块当前为 0.2.0；方法文档的修订不代表页面实施或真实用户效果，本轮未修改网站或开展真实用户测试。

<a id="three-status-axes"></a>
## 三个状态轴

[原报告](sources/research-original.txt)第 219–230 行要求至少拆分以下三轴：

| 字段 | 枚举 | 如何使用 |
|---|---|---|
| `source_status` | `cited` / `source-checked` / `source-limited` | `cited` 仅表示列明了依据；`source-checked` 需要保留实际打开、核对相关主张的记录；`source-limited` 说明来源的具体限制。 |
| `implementation_status` | `proposed` / `implemented` / `regressed` / `retired` | 提案与实际落地分开；`implemented` 需要目标版本或部署证据；回归和废弃应保留原因。 |
| `user_validation_status` | `untested` / `observed` / `contradicted` / `mixed` | 未测试、获得相关用户观察、观察反驳预期、结果混合分别记录；`observed` 不表示普遍有效。 |

枚举来自原报告；表中的操作性解释由本次整合补充。它们不是从低到高的单一评分，不能用一个 `verified` 取代。

来源表中的 `imported-unchecked` 是**导入元数据**，表示 URL 从上传报告附录转录但未重新核验。它不扩展上表的 `source_status` 枚举，也不自动升级为 `source-checked`。

一次应用示例包含 `source_status: cited`、`implementation_status: proposed`、`user_validation_status: untested`，含义是“引用了上传材料、提出改法、尚无用户测试”。参见[机器可读示例](examples/entry-outcome.json)。

运行本域的 `python3 check.py` 可以递归检查 `examples/` 中 JSON 应用记录的本域原语 ID、三轴枚举及状态连贯性；也可从任意目录用脚本绝对路径运行，检查通过仅说明结构与状态一致，不代表完成了真实用户检验。合成例子必须保留 `untested` 且不得填写真实用户观察；新增真实记录使用 `observed`、`contradicted` 或 `mixed` 时，应提供非空 `user_observations` 数组与 `validation_scope` 文字，后者说明任务、目标版本和观察范围，脚本不会验证观察内容的真实性。

## 先区分证据类型

原报告第 110 行区分静态内容核对、工具化链接跟随、AI 设计推断与真实用户观察。整理与今后的应用记录应继续区分：

- 取得 HTML 只能支持该抓取结果中的内容，不等于已测试所有交互。
- 跟随链接可以核对目的地，不等于完整浏览器操作或真实用户理解。
- 解释“用户可能困惑”是一项假设，需要观察。
- 历史审阅不能在没有新证据时写成当前缺陷。
- 合成案例可演示方法，但不能计入真实观察数量。

来源转述应追溯到同一原始记录，不能将多个转述当成多个独立样本。原报告的原研究日期不明，本次导入日为 2026-11-13；两者不要混用。

## 六类用户观察

原报告第 268 行写“五类”，但第 270–277 行实际表列六类。本次按表格内容整理为六类，原文快照保持不变。

| 能力 | 任务或问题 | 记录 |
|---|---|---|
| 理解 | “这页主要能帮你解决什么？” | 用户原话、与页面职责的符合程度及误解 |
| 预测 | “点这个以后你认为会看到什么？” | 点击前预测、实际结果、差异 |
| 选择 | “为什么选它而没有选另一个？” | 使用的线索、忽略的信息和犹豫点 |
| 完成 | 让用户完成当前任务 | 完成、需提示、错误路径及卡住位置 |
| 恢复 | 在安全情境中出现一次误操作 | 能否发现返回、撤销或纠错办法；丢失的上下文 |
| 下一步 | “现在你认为可以做什么？” | 是否提出当前可执行动作、是否需要外部解释 |

学习内容另外设置理解检验，例如用自己的话解释概念或应用到一个略有变化的例子。页面顺畅和完成点击流程不能直接证明学习发生。

自然使用任务与点击前预测诊断分开进行。自然任务先让参与者在给定任务说明后独立操作，再回顾理解；点击前询问预期作为单独诊断环节，不在全过程反复追问后仍将表现计作自主完成。

## 小规模观察记录

以发现预测是否失效为目的，给参与者独立记录。记录任务、目标版本、设备与输入方式、必要的背景条件、原话或行为、是否得到提示及结果解释。

过程中额外追问或提示需逐次标记；受提示后的完成单独记录，不能计为无帮助完成。若参与者先做过预测诊断，再做同一自然任务，也要记录这种先前接触。

第一轮结果可以用来修改，第二轮在修改后检查。未招募前不写样本数；少量质性观察不换算成人口比例，也不把多次任务当成多个独立用户。收集信息只需满足分析目的。

以上流程依据原报告第 264–279 行，记录字段和本地例子是整合补充。

## 技术检查单独执行

以下是原报告第 281 行提出的检查方向；0.2.0 原整理未重新核对 WCAG 条文或运行实际站点检查，不能据此声明合规。后续局部来源核对另在本节末尾说明：

- 键盘是否可以完成相关功能，焦点顺序是否保持任务意义。
- 焦点是否可见，是否被固定区域遮挡，弹窗或展开区域的焦点管理是否符合实际行为。
- 链接文字及其程序化上下文能否说明目的，可见名称与辅助技术可获得的信息是否一致。
- 触控目标、错误识别、布局回流及表格语义是否满足目标项目选定规范版本的相关要求及例外。
- 移动端、键盘和辅助技术下，比较维度、步骤和展开信息是否仍可理解与操作。

具体数值、成功准则编号、符合等级及例外条件应在执行时直接核对官方标准，并写下检查范围和证据。此处不把上传报告中的未复核数值转写为已确认的工程门槛。

技术检查可以发现实现问题，但不能替代六类用户观察；真实用户测试也不能代替系统的技术合规检查。

2026-11-13 的[网页实施补充](APPLICATION.md#readable-reflow)另行核对了 W3C 文字缩放与回流说明，列出窄视口、桌面缩放和真机的区分，以及 SVG 标签最终显示尺寸、图文参照和二维内容例外的检查。检查截图中是否读得清，不能只以无溢出判定通过，也不从声明字号推定最终显示大小。此项补充没有执行任何站点的完整无障碍验收。

有“已完成”或勾选状态的页面，另按[状态主体检查](APPLICATION.md#state-subject)核对主体、对象、依据与适用范围：作者事实、访客自记、系统操作结果与理解表现不能互相覆盖。记录它们的来源和行为即可，不要求新增公共状态模型。

<a id="method-revision"></a>
## 方法版本怎么验证

0.2.0 的[版本评审](REVISIONS.md)包含定义分析和合成反例，还不足以证明十项或九项更好。后续分开安排以下检查，不把审阅者能分类和读者能理解混成一个结果。

### 审阅者的调用检查

准备未参与改稿的案例，保存目标版本、原始页面或截图、任务和问题描述。先请审阅者独立描述困难及希望改变什么，再选动作或模式并写出实际改法；记录找不到入口、误用、需要额外解释与未处理的决策。

比较当前十项方案与“九项加接续模式”时，保留完整指南，让候选方案真正包含后继选择，不能将它默认为外部已做。采用分组或调整案例与版本顺序，记录参与者是否已见过案例，避免把熟悉材料的表现当作方法优势。少量试用用于找分歧，不声称统计显著或覆盖率。

重点考察：

- 后继标签清楚、条件满足，但没有适合目标的继续动作时，是否仍会处理“选择并建立后继”。如果模式能稳定承接且不增加漏检，可重新考虑将 `design.next-step` 归入模式；如果只是换地方藏着同一决策，应如实说明。
- 公式与解释跨屏时能否选到关系外化；纯粹缺少例子时能否先补内容。若两类困难总被混淆，优先修路由和定义，再判断是否需要拆分或增加动作。
- 就地参照与显式关系表示的实现分支，是否仍使审阅者反复作两个独立判断；若共同目标不能有效指导调用，再测试拆开。
- 访问记录、阶段、任务完成和掌握是否被混用；观察到误用应收紧标签与证据说明。

独立 Agent 会话可用于这类术语与路由试标，结果标为 AI 推演；不得填入真实读者 `user_observations`。本轮评审中的论文工作台等案例已用于改稿，不再充当未见案例。

### 真实读者的任务检查

在实际目标页面上，分别检查页面用途、关系理解、后继选择等预测。每次尽量改变一个可解释的干预目标；若多个改动一起上线，结果先归于整组方案，不直接归因某个原语。

保留原版与改版、目标读者背景、任务、观察顺序、提示情况、原话或行为。如果新增关系图反而引起错误因果推断，应收紧使用条件、调整表示或恢复文字表达；不从这一次结果推导所有线性关系禁止画图。未访问或未知的内容也不能在界面标记为已掌握。

这些是未来计划，没有预填样本数、改善幅度或完成结果。真实记录继续使用三个状态轴，并写清具体适用范围。

## 保留、修改或废弃

一次应用完成后，记录原预测、观察、其他可能解释及处理决定。观察不符合预期时，可以修改使用方式、缩小适用边界，或停止使用这次方案。不要因为采用了一个原语，就认定变化必然来自该原语。

用例记录的状态可以变化，原始材料和过去观察应保留。参见[来源与快照规则](sources/README.md)。
