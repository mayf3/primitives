# 按问题调用设计原语

先描述“谁在完成什么任务，遇到了什么困难”，再选择一个足够小的改变。下面是根据原报告第 234–260 行和十项总表整理的问题路由，名称和动作来自原报告，路由组织与机器 ID 是本次新增。

## 问题 → 动作

| 眼前的具体困难 | 首选原语 | 先做的最小改变 | 接着检查 |
|---|---|---|---|
| 我不知道这里能帮我做什么 | [交代页面承诺](PRIMITIVES.md#page-promise) | 写出本页能回答或完成的事 | 用户能否用自己的话说出用途 |
| 我不知道在哪、已经做了多少 | [标明位置与进度](PRIMITIVES.md#position-progress) | 显示页面类型、所在路线、当前阶段 | 能否说明当前位置和剩余路径 |
| 两个入口看起来一样，却去不同地方 | [预告入口结果](PRIMITIVES.md#entry-outcome) | 在入口中写明动作、对象和结果类型 | 点击前能否合理预测目的地 |
| 我读完了，但不知道现在能做什么 | [接通下一步](PRIMITIVES.md#next-step) | 提供当前可完成的后继动作，并允许结束 | 能否说出继续的具体动作 |
| 做了一半才发现缺设备、权限或其他前提 | [前置必要条件](PRIMITIVES.md#prerequisites) | 把影响能否开始的条件放到行动前 | 能否判断现在能做什么、何时再投入 |
| 我必须记住上一页的内容才能比较 | [按共同维度比较](PRIMITIVES.md#comparable-options) | 把影响选择的共同维度放在同一视图 | 能否说明选择依据和未知项 |
| 我看过文字，却说不出其中的关系 | [把抽象关系外化](PRIMITIVES.md#externalize-relations) | 显示一个关键关系及必要上下文 | 能否正确复述该关系 |
| 我点了，但不知道是否生效 | [让变化可见](PRIMITIVES.md#visible-change) | 显示已接收、处理中、结果或错误 | 是否还需要反复点击来确认 |
| 一旦点错就要全部重来 | [保留恢复路径](PRIMITIVES.md#recovery-path) | 保留输入并提供返回、撤销或修复 | 错误后能否接着完成任务 |
| 页面细节太多，我找不到当前要做的事 | [按需展开次要复杂度](PRIMITIVES.md#progressive-disclosure) | 先区分必要与次要信息，只折叠后者 | 主任务是否仍完整，隐藏内容是否可预测 |

## 一次调用怎么做

1. **限定任务。** 写出目标使用者、当前场景和一个想完成的动作。
2. **保留材料。** 记录观察到的文字、页面位置或交互结果；区分真实观察、历史材料和合成场景。
3. **提出解释。** 写出你认为困难可能发生的原因，不把解释写成已经证实的用户心理。
4. **选一个小改变。** 从卡片取出动作，并解释为什么适合本次情境。需要组合时参考[组合模式](PATTERNS.md)。
5. **预先定义检查。** 写出用户要能说明、预测或完成什么。点击数下降不是通用成功标准。
6. **分别记录进展。** 文案写好、功能上线、用户观察成立是不同结果，使用[三个状态轴](VALIDATION.md#three-status-axes)。

“页面看起来复杂”不足以直接触发折叠。必须先判断是否因必要信息缺乏组织、比较维度不齐、位置不明，或确实有大量少用细节。风险、费用、必要权限、决定能否开始的设备条件不能为了首屏简洁被藏起来。

## 不自动调用的情况

- 开放探索页没有自然顺序时，可以给候选方向，不强造唯一下一步。
- 比较任务需要同时看到多个方案时，不为了“每页一个动作”拆开选择。
- 原文的连续论证足以表达关系时，不为视觉丰富而新增关系图。
- 主任务需要的复杂信息仍然需要解释；降低界面额外工作不等于消除学习和判断本身的思考。
- 历史审阅指出的问题若已被修复，不能继续将其当成当前缺陷；需要新的目标版本证据。

完整应用提案见[入口结果示例](examples/entry-outcome.md)。它是合成例子，不是对当前网站的审计结论。
