## 引用与溯源纪律（2026-08-25 评审确立）

2. **禁止引用中间产物**：digest/总结/编译类文件（如 thoughts-strategic-digest.md）会随时被清理、重编——引用其行号 = 引用会腐坏的坐标。2026-08-25 教训：digest 被清理后，全库 25 处行号引用全部失效，其中 5 处还带错误归因（08-03 被错误记为多个话题的来源，真来源分别是 07-31/03-10/03-14）。
3. **归因必验**：写"随想 MM-DD"前先打开当天 raw 原文核对主题——S2/S3/C1 三处"08-03 接受更乱但更快"均为迁移时误标。
4. 无出处宁可标注"（待溯源/已失效）"，不编造（CMF 事件，2026-08-25）。

| 问 | 答 | 归类 |
|---|---|---|
| ① 这是**事实**还是**判断**？ | 事实/原文/事件/数据 | → Observation |
| | 判断 | → 继续问 ② |
| ② 这判断**有没有可检验的观测**？（能反驳它，或能累积支持它） | 有 → Claim（可证伪型 / 可累积型） |
| | 完全找不到相关观测（空话） | 不入库 |
| ③ 这是**现状**还是**未来**？ | 现在的状况、可回答"我现在在哪/卡在哪" | → State |
| | 未来要做的事 | → 继续问 ⑤ |
| ④ 这事**定下来**了吗？谁定的？ | 老板本人拍板、承诺不可轻撤 | → Decision |
| | 只是倾向/考虑/想法 | → Claim 或 Observation |
| ⑤ 这个**行动**做完能得到什么？ | 明确产出（一条观测/一个证据/状态变化） | → Activity |
| | 说不出目的 | 悬空行动，不进系统（H1 硬拒） |

一句话兜底：**Goal 定方向，Observation 给事实，Claim 下判断，State 记现状，Decision 做承诺，Activity 干事情。**

## 各元语定义

### Goal 目标 — 长期不变的"最终状态"
- **定义**：人生级、长期不变（数年~终生）的方向，回答"这辈子要成为谁 / 拥有什么 / 过什么生活"。不随工具、赛道、方法变化。
- **判别**：换一个做法它还成立吗？成立 → Goal；不成立 → 路径（Claim）。"做播客、学 AI 编程、搭个人系统、做小而美业务" → 都是"是否有助于相应的 Goal？"的 Claim，永远不许升级为 Goal。
- **必要前提条款（2026-08-25 拍板）**：Goal 允许"**终态 + 必要前提**"结构——必要前提（如 G1 的财务自主）是**手段**，不并列为终点，其成立性由 Claim 层接受证据检验；Goal 是**操作性约定终点**，不向上递归（自由→意义→… 不纳入系统）。
- **防路径升级条款（2026-08-25，原 G1「重要提示」正式化）**：AI Agent / 创业 / 内容创作 / 小而美公司 / 技术型独立开发者 **都不是 Goal**，是"是否有助于目标？"的 Claim，接受 Evidence 检验。
- **验证指标归属条款（2026-08-25 拍板）**：指标（metric）由 **Observation 记录原始值、State 承载当前值**；Goal 只声明"进展看什么"——`verified_by` 引用钩子（指向 state/observation），**不存数值**。
- **机器标记**：D4 孤立目标（无 related_states 且无 related_activities → WARN）；D6 缺验证引用（无 verified_by → WARN）；verified_by 的引用存在性与类型由校验器强制（只允许指向 S/O）。

### Observation 观测 — 可证实的事实
- **定义**：能被感官/记录/引文证实的事实、原话、事件、数据。只描述"发生了什么 / 谁说了什么 / 看到了什么"，**不含判断、建议、未来**。
- **判别**："这句是不是真的发生过/被记录过？"能证实 → Observation；带"我觉得/应该/最好" → 判断，归 Claim（或作为引用的原话保留但要标引号）。
- **机器标记**：D1 判断词混入（正文出现 我觉得/应该/最好/必须/希望/想要/决定/建议 → WARN）；W1 无主（不指向任何 Claim 也没关联目标 → WARN）。

### Claim 断言 — 接受观测检验的判断（含立场型）
- **定义**：可被观测检验的判断命题。检验有**两条机制**，门槛是"有没有可检验的观测"，**不是可证伪性**：
  - **反驳性检验（可证伪型）**：存在可能推翻它的观测 → 全状态机可用。
  - **累积性检验（可累积型 / 立场型）**：立场、偏好、价值判断——通常没有单一"反例观测"，但**一致观测的多寡决定它的可信度**（可信度累积）。状态在 INCONCLUSIVE ↔ SUPPORTED 间随证据积累移动；行为与立场背离 → WEAKENED；立场本身改变 → RETIRED + 新建；原则上不设 CONTRADICTED（除非出现直接相反的观测）。
- **判别**："哪条观测能检验它——反驳它，或累积支撑它？"答得出 → Claim（可证伪型或立场型均可）；完全找不到相关观测（空话）→ 不入库。
- **立场型例子**："我喜欢写作"是**可累积型 Claim**——"频繁写作、主动排写作时间"的观测不断积累 → 从 INCONCLUSIVE 走向 SUPPORTED；"回避写作"的观测积累 → WEAKENED。可信度累积只是**驱动 Claim 状态的机制**，不新增状态枚举（仍五态）。
- **状态语义**：SUPPORTED=有支持证据（反驳型=证据确凿；累积型=可信度充分）｜INCONCLUSIVE=证据不足（**新建默认**）｜CONTRADICTED=被反驳（主要适用于可证伪型）｜WEAKENED=反例/行为背离累积｜RETIRED=过时或立场改变。
- **条目完整性（2026-08-25 老板确立「断言和逻辑要清晰」）**：断言条目**不许只写结论**——新建/评审时必须保留**论证链**（原始推理过程：反方→反驳→类比→递推）；尽量带「反方/边界」（什么情况下不成立）与「检验点」。推荐结构：陈述 → 论证 → 反方/边界 → 状态 → 证据（可对应论证链各步）→ 检验点 → 影响。陈述不可篡改；论证可随素材逐步补全。
- **机器标记**：D5 SUPPORTED 无据（SUPPORTED 但 supported_by/contradicted_by/conflicts_with 全空 → WARN——没证据请标 INCONCLUSIVE）。立场型断言同样适用：SUPPORTED 前先积累 `supported_by` 观测。D8 断言缺论证段（正文无 论证/理由/推理/为什么 段 → WARN 提示保留推理链）。

### State 状态 — 当前的事实性现状
- **定义**：当前时间点"我在哪、在做什么、有什么资源/能力、卡在哪"的**事实性现状**快照（由观测+断言+决策推导 + 老板复核更新）。可观测、可核实。
- **判别**："这是现状，还是我要做的事 / 我的判断？"现状 → State；要做 → Activity；判断 → Claim；"两个月前发生过 Y" → Observation。
- **想法不归 State（2026-08-25 老板确立）**：**想法、判断、评价、策略、计划、路径一律归 Claim 层**——哪怕是"已明确/很确定"的想法也仍是断言。写法口诀："Agent 尚未产出可验证方案"是事实（State）；"Agent 在空转 / 路径已明确 / 应该换打法"是判断（Claim）。认知现状通过**"我正在验证哪些断言"**的引用表达（如 S3「相关的判断」节列出 C5/C6/C14 及其状态），不直接写"我认为…"。
- **边界（2026-08-25 老板确立）**："**还缺什么数据 / 待验证什么**"是**认知判断**——"我认为还差 X"是对认知状态的断言（可被观测检验：数据补齐即被满足），**归 Claim 层**（作为某条 Claim 的检验点/证据缺口陈述，或独立断言），**不写进 State**。区分口诀："我现在有 X"是事实（State）；"我现在缺 X 数据"是判断（Claim）。
- **指标承载**：State 是指标的**存放处**（当前值 + evidence 引用原始观测）；Goal 只引用它。
- **机器标记**：D3 未来/判断/缺口/想法词混入（正文出现 未来/将要/计划做/打算做/准备做/需要/应该/必须/建议/还差/待验证/缺口/**认为/觉得** → WARN）；W5 无据（evidence 与 related_goals 全空 → WARN）。

### Decision 决策 — 老板拍板的行动承诺
- **定义**：**仅老板本人**拍板的、不可轻易撤回的行动承诺；通常绑定资源、锁定路线、释放其他选项。他人/系统/Agent 的建议最多是候选项。
- **判别**："这是已经定下来的承诺，还是在考虑/倾向？"已定 + 老板拍板 → Decision；还在想 → Claim（判断）或 Observation（记录想法本身）。
- **机器标记**：D2 倾向词冒充当（正文出现 考虑/打算/可能/也许/或许/希望/想试试 → WARN 疑似未拍板）；W4 无据（related_claims 与 evidence 全空 → WARN）。

### Activity 活动 — 行动侧唯一原语
- **定义**：一个可执行动作 + 明确目的。必须满足：intent 四选一（Observe/Hypothesize/Test/Optimize）+ 至少一个绑定（related_goals / related_claims / expected 预期观测）。日常维护类（吃饭睡觉陪家人）不进系统。
- **判别**："做完能得到什么观测/证据/状态变化？"答得出 → 合格活动；答不出 → 悬空（H1 硬拒，永不落盘）。
- **机器标记**：H1 悬空、H2 Test 无断言、H3 Hypothesize 无断言（conflict 层硬拒）；expected 推荐必填。

## 边界判定优先级（一条材料同时像多个元语时）

```
先判 ① 事实 or 判断        （Obs vs Claim）
再判 ② 判断 or 拍板        （Claim vs Decision）
再判 ③ 现状 or 历史事件     （State vs Observation）
最后 ④ 行动归行动侧         （Activity）
```

## 机器可校验标记清单（validate.py 定义合规层，D 规则均 WARN 级，H/W 见 conflict-rules）

| 规则 | 对象 | 标记 |
|---|---|---|
| D1 | observation | 正文含判断词：我觉得 / 应该 / 最好 / 必须 / 希望 / 想要 / 决定 / 建议 |
| D2 | decision | 正文含倾向词：考虑 / 打算 / 可能 / 也许 / 或许 / 希望 / 想试试 |
| D3 | state | 正文含未来/判断/缺口词：未来 / 将要 / 计划做 / 打算做 / 准备做 / 需要 / 应该 / 必须 / 建议 / 还差 / 待验证 / 缺口（2026-08-25 S1/S2 评审扩展两次） |
| D4 | goal | 无任何绑定（related_states 与 related_activities 皆空） |
| D5 | claim | SUPPORTED 但 supported_by / contradicted_by / conflicts_with 全空 |
| D6 | goal | 无 verified_by（未声明"进展看什么指标"；指标由 S/O 承载，Goal 只做引用） |
| D7 | 全部 | 正文出现 ID（G/C/O/S/D/A+数字）不在登记表——旧称残留/拼写错误提示 |

> 语言标记是**提示不是判决**（原话引用可能合法含判断词）——命中 WARN 后由拆分者复核，无法机器化的"事实 vs 判断"终判仍由人按五问口诀做。
> D7 同理：正文提及可能属讨论式引用（如"旧称 G0"），命中后人工复核；YAML 关系字段的引用存在性仍为 error 级。
