# 未来候选（V0 一律不做，仅记录）

> 任何超出 DESIGN.md §8 验收的功能都属于本清单。发现新候选时追加于此，不顺手实现。

| 候选 | 一句话说明 | 前置条件 |
|---|---|---|
| 决策执行追踪命令（`pca decide DEC-0001 kept/violated`） | 现在决策状态靠手工编辑 JSONL（git diff 可见），V0 够用 | 出现 ≥10 条开放决策后再考虑 |
| 图可视化 | Mermaid 导出目标/矛盾图 | 记录量足以让图有信息量 |
| 自动导入（微信收藏 / flomo / 备忘录） | 现在靠手工 `pca add` | 先验证手工录入能持续 30 天 |
| 定时提醒审问 | 自动调度被 V0 明确排除 | 同上 |
| 周期性自动周报摘要 | 深刻文字不替代 STOP/CONSTRAIN/TEST，风险是制造"系统建设"式伪产出 | 先有连续 4 份有效报告 |
| 向量检索 / 语义索引 | grep + SQLite 索引在 V0 规模足够 | 记录 > 数千条 |
| CLAIM 置信度评分 | 现在用 SUPPORTS/CONTRADICTS 计数的派生状态 | 需要更细的证据强度模型 |
| 网页前端 / 仪表盘 | V0 明确排除 | V1 立项时整体设计 |
| 移动端快速录入 | 建议先用任意备忘录 + 晚间统一 `pca add` | 手工流程验证后 |
| entry 附件（图片/语音转写） | 原文永远以文本形式入库，转写件视为新 entry | — |
| 多人/分享模式 | 本系统按单人生成，私有仓库 | — |
| E2E 加密 | 仓库已私有；敏感内容建议写入时自行脱敏 | — |
