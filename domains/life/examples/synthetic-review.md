# 合成示例：先分清事实，再决定下一步

**性质：纯合成教学示例。人物、引文、日期与结果均为本次编写，不是用户记录，不是一次真实实验。** 所有 G1 / O1 / C1 等编号只在本例中有效；它们不指向任何真实数据。下面展示的是语义用法，不是具备全部必填字段、可直接导入 Life State 的数据文件。

## 一、先保存场景材料

以下材料由本例作者虚构，作为固定输入。后续解释不能回头修改它们。

**材料 M0，虚构人物林澄的长期方向陈述：**

> 我希望长期保有自主安排工作与休息时间的能力，具体做哪个项目可以调整。

**材料 M1，虚构的周一记录：**

> 这周我花了四小时更换工具，计划中的几项工具还没配好。草稿还没请人读。我认为不把所有工具配齐，就不具备让别人阅读草稿的条件。

**材料 M2，虚构的周二明确承诺：**

> 我决定今天先用现有工具整理一页草稿，请两位愿意试读的同事给反馈；本周不再更换工具。

**材料 M3，虚构的周三结果记录：**

> 原计划的几项工具仍没配好。我用了已有编辑器，把草稿发给两名自愿试读者。两人都收到了，其中一人说开头不知道我要回答什么。

## 二、逐项区分，而不是一次总结成结论

| 局部编号 | 类型 | 从材料中得到的内容 | 边界 |
|---|---|---|---|
| G1 | Goal | 长期保有自主安排工作与休息时间的能力（M0） | “把草稿交给人读”是路径或行动，不升级为另一个人生目标；完整记录还需声明进展的观察引用 |
| O1 | Observation | 林澄在 M1 记录自己花四小时更换工具 | 这里只能确认场景中有这条自述；“他在逃避评价”仍是解释 |
| S1 | State | 截至周一，草稿尚未请人读（M1） | 不写成“草稿缺乏价值”，材料没有这个结论 |
| C1 | Claim | 不把所有工具配齐，就不具备让别人阅读草稿的条件（M1） | 先标 `INCONCLUSIVE`，明确这是待检验的必要条件判断 |
| D1 | Decision | 周二先用现有工具整理一页草稿并请自愿者反馈，本周不再换工具（M2） | 只有因为场景中的本人明确说“我决定”，才记为已承诺；不是 Agent 替他说了算 |
| A1 | Activity | 用已有工具整理并交付一页草稿，意图 `Test`，关联 C1，预期得到能否交付与读者反馈的观察 | 未执行前只能记录预期，不能填写成功结果 |
| O2 | Observation | 场景中部分计划工具仍未配好，但两人已收到草稿，一人反馈开头问题不清楚（M3） | 没有材料说明另一人是否理解，也没有材料证明整篇有效 |

在真正写入记录之前，还需要在原数据环境补齐合法来源、时间、引用等必填字段，并执行原格式与语义检查。本例没有进入该流程。[概念依据](../CONCEPTS.md)、[运行边界](../COMPATIBILITY.md)。

## 三、让证据检验相应范围的判断

O2 同时记录了“部分计划工具仍未配好”和“已有工具已经完成草稿交付”，可以在这个虚构场景内反驳 C1 的必要条件断言。因此可以提出把 C1 从 `INCONCLUSIVE` 调整为 `CONTRADICTED`，并明确反驳的是“配齐所有工具是交付前提”。如果只知道使用了已有工具，却不知道是否已经配齐，就不足以形成这一反例。这不等于证明所有工具都没用，也不等于证明草稿已经好到值得长期采用同一做法。

O2 中“读者不知道开头要回答什么”的反馈，可以产生另一个范围更小的判断候选：这页开头可能没有充分交代要回答的问题。它仍需核对原稿与更多相关观察，不能直接写成“作者不会表达”。

O1 的四小时只说明投入。即使 A1 状态变成 `done`，也只能说明该次行动完成；Claim 的状态依据相关观察判断，不能从 `done` 自动派生 `SUPPORTED`。[Evidence 说明](../CONCEPTS.md#evidence)。

## 四、没有新的本人承诺，就保留行动候选

Agent 可以提出：保留同一份材料，修改开头后再请一位自愿读者复述“这页想回答什么”，将预期产出写成具体复述记录。这是新的 Activity 候选；场景材料中没有林澄对该建议的明确承诺，因此不新增 D2，也不把它标成已采用的 `next`。

如果林澄后来明确选择了这个候选，再依据新材料记录该承诺和活动状态。没有选择，也可以暂时停在“已知道问题在哪里，下一次行动尚待本人取舍”。

## 五、本例检验的是表达是否自洽

读者应能指出：哪句话来自场景材料，哪句话是解释；哪条证据只反驳了一个必要条件；哪项承诺有明确原话；哪项仍是建议。文件或链接检查只能检查这份示例的结构，不能把虚构结果累计为真实使用证据。
