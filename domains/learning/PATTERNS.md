# 学习过程组合

以下是可按任务选用的组合，不是新的不可约原语。顺序可以分支和返回；每次返回应说明补什么、重试什么。组合中的分流标准、变式选择和时间安排由设计者明确承担，不能只写“系统自动判断”。

## 一、新手从陌生到第一次有意义的尝试

先交代任务价值、成果和先修；起点不明时用[显化当前理解](PRIMITIVES.md#elicit-starting-model)取得回应，再用[必要关系模型](PRIMITIVES.md#relation-model)补后续动作需要的概念；[展示过程](PRIMITIVES.md#worked-process)后，让学习者完成一个[目标表现任务](PRIMITIVES.md#elicit-performance)，依据结果进入[反馈与再试](PRIMITIVES.md#feedback-retry)。

**额外决定：** 哪些概念是下一步真正需要的，哪些已有基础可跳过；需要把回答与判据对应后再分流，不把“看过介绍”作为掌握门槛。

**停止条件：** 读者能判断是否适合继续，且获得第一次与目标有关的尝试及反馈。此时可以结束一节入门课，不必立刻覆盖远迁移和长期保持。

## 二、从完整示范到少帮助的变式

完整[示范](PRIMITIVES.md#worked-process)给出步骤和依据；第一次[尝试](PRIMITIVES.md#elicit-performance)可保留部分步骤；依据表现[调整支持](PRIMITIVES.md#fade-support)，再[改变一项条件](PRIMITIVES.md#vary-conditions)并[要求说明依据](PRIMITIVES.md#explain-reasoning)。失败时先定位缺关系、不会操作还是题目超出已教内容，再决定补什么。

**额外决定：** 哪些帮助正在代替目标能力，哪些是任务本来允许的工具；首个变式保持哪些条件，避免把新 API、新环境和新动作同时引入。

**停止条件：** 能报告本次任务在什么帮助条件下完成、解释还有哪些缺口。保留“零任务提示”“有限提示”“完整示范后”区别，不统一改写成“独立掌握”。

## 三、Agent 辅助下的学习

先约定目标是手写实现，还是借助 Agent 提需求、判断并修正结果。后者可要求学习者先[产生](PRIMITIVES.md#elicit-performance)任务约束与预测，再检查 Agent 产物，借助[对照与修正](PRIMITIVES.md#feedback-retry)指出差异；通过一个[变式](PRIMITIVES.md#vary-conditions)或明确标注的错误示例，观察其能否[说明依据](PRIMITIVES.md#explain-reasoning)并提出调整。

**额外决定：** 哪些产物来自人、哪些来自 Agent；哪些标准可独立核对，不能以同一个 Agent 的自评作为唯一依据。学习者调用普通工作工具不自动失去任务意义；但工具代替了哪种能力必须说明。

**停止条件：** 得到人的需求、判断或修正证据。只有视频文件或代码运行成功时，只报告产物成立，不补写人的理解。

## 四、观察保持与运用范围

有当前任务的回应后，按需要选择[延后检查](PRIMITIVES.md#delayed-check)、[改变条件](PRIMITIVES.md#vary-conditions)或[减少支持](PRIMITIVES.md#fade-support)。三个条件分别写明，可以组合，但解释结果时承认组合。

**额外决定：** 目标保持多久；怎样的变化仍主要检验已学关系；允许什么提示。需判断某个因素的影响时，其他条件尽量相当。形成性教学允许调整多项以帮助人继续，不应同时将结果包装为单因素实验。

**停止条件：** 在目标条件下获得一项观察，或如实报告未完成。没有复测就不声称长期保持；几次近变式不代表任何场景都能迁移。

## 五、只查资料或完成当下任务

已具备基础的读者可以直接找到[关系](PRIMITIVES.md#relation-model)或[示范](PRIMITIVES.md#worked-process)，在自己的任务中使用。需要时接通[反馈](PRIMITIVES.md#feedback-retry)，没有必要强制答题或重复导入。

**额外决定：** 这段体验承诺的是当下支持，还是能力培养。查到资料、找到节目、获得一个下一步，都可以是有效结果；无需为了让页面“像学习产品”增加测验。

**停止条件：** 当前查询或任务获得足够支持。若之后要宣称能力获得，再设计与那一能力相称的表现观察。
