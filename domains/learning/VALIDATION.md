# 学习证据与应用记录

**材料存在、能找到入口、能操作、在指定条件下表现如何，是不同问题。** 学习原语不能用一个全局 `mastered=true` 表示它们。

## 三条状态轴，各自注明对象与范围

本域沿用便于协作的字段名，以下值和含义由学习域定义，不自动映射其他领域状态。

| 轴 | 本版使用值 | 含义与边界 |
|---|---|---|
| `source_status` | `proposed` / `cited` / `needs_review` | 新提议尚无所引论据／论据有可追溯出处／来源或推论范围需复核。`cited` 不表示论文直接研究过这个原语，也不证明本站有效。核验层次另写 `source_scope`。 |
| `implementation_status` | `planned` / `implemented` / `checked` | 具体教学实现尚未做／已做／在明确场景下检查过。必须写对象、版本和范围。方法文档已入库不能算网站已实施。 |
| `user_validation_status` | `untested` / `observed` | 没有实际学习者观察／已有指定任务与条件下的观察。`observed` 不是通过认证，也不自动意味着改进有效；失败观察同样应记录。 |

没有可解析出处，只有原报告的旧会话引用时，不能写“已核验”。没有任何实际学习者时，统一 `untested`。一次任务被观察后，只更新该任务记录，不把整个模块或课程改成“已验证”。

本版候选定义的状态是：文献来源与抽象理由已整理，方法定义已写入仓库，学习效果未测试。它不是任何生产网站的应用回执。

## 实施检查和人的观察怎样对应

| 问题 | 可由实施检查确定 | 仍需观察人的部分 |
|---|---|---|
| 内容是否存在 | 定义、例子与任务确实渲染 | 能否据此形成正确理解 |
| 入口是否可达 | 链接存在、目标正确、键盘和触控可操作 | 目标读者能否发现、预测并选择 |
| 反馈是否一致 | 参数、画面、表格与文字对应同一条件 | 能否利用反馈发现并修正差异 |
| 是否完成任务 | 程序接收输入、产物满足列出的技术检查 | 谁做了哪些决定、依赖什么帮助 |
| 是否保持或迁移 | 复测或变式功能已经提供 | 延迟或变化条件下实际表现如何 |

上传研究提出的四栏可作为这一检查清单的灵感，不能替代三轴；尤其“可找到”要区分技术可达与人实际发现。

## 一条足够轻的表现记录

教学者的笔记就可以承载，不要求账户、遥测、上传或学习管理系统。真实学习者记录留在原项目，不因本方法模板而自动公开。

- **目标与任务版本**：要观察什么；题目和判据是什么。
- **起点与情境**：相关经验、必要环境、材料；未知项明确写未知。
- **工具与帮助**：允许的工具、实际使用的 Agent 或文档、提示何时出现及内容；看答案前后分开。
- **实际回应**：原答案、操作、产物、解释、错误及重试；不把预计答案填成实际结果。
- **时间与变化**：相距多久，变了什么，保持什么，期间接触是否已知。
- **可支持的结论**：只在上述范围内描述；下一步需要补关系、练操作、减少支持还是继续观察。

“零任务提示”表示本次作答未使用额外针对本题的概念、公式、步骤、定位或答案提示。即使没有直接给出最终数值，只提示本题应使用哪个公式，也要记为对应支持条件下的表现。任务原有条件、允许的普通工具和参考资料另行约定并记录；使用允许工具不自动判为失败，也不能因此称为无帮助记忆检索。无障碍帮助不等于代做，应按其是否替代目标能力判断。

## 合成记录示例：还没有学习者参与

下面是应用提案，供理解字段，不是实际测试数据：

```yaml
target: 首个帧号换算变式
source_status: cited
source_scope: 例题过渡研究提供相关机制依据；本站任务是新设计
source_refs: [L-S02]
implementation_status: planned
implementation_scope: 尚未实现本提案；不描述现有实验是否可运行
user_validation_status: untested
task: 30fps、18帧入场，要求1.8秒开始；自行决定参数并说明依据
allowed_tools: [当前实验控件, 任务约定允许的参考资料]
task_answer_hints: 按需展开，实际使用单独记
observations: []
expected_check: 起点54、终点72；这是判据，不是观察结果
```

## 首轮真人观察怎么做

选几位与目标受众相符的人，从真实入口开始，不先教他们答案。请其用自己的话解释用途和先修，观察第一次尝试、错误、求助与修正；任务后再问感受。愿意参加后续观察的人可以按可行间隔再做等价任务，间隔是试点安排，不是普适最优值。

按实际人数报告“几人／共几人”、所需帮助和错误类型，不沿用研究稿中的 80%／70% 默认通过线。小规模形成性观察用于定位改进，不足以估计总体教学效应或证明整套原语有效。若以后要比较教学方法，需要另行设计相应研究；本版不要求网站先做一个实验平台。

## 方法集合本身怎么修订

本轮完成的是定义审阅和合成案例检查。Map、DIY、Remotion 已参与构造，不能再登记为未见案例。需要进一步检验泛用性时，先冻结当前版本，再让另一位使用者独立选择新任务，记录如何调用、遗漏了什么、为了完成任务额外补了哪些判断。

最小性检查应移除某项，用其余全部操作重建相同任务，并计入准备判据和上游选择的成本。两个目标不同、两项互不能单独替代，不足以证明两条原语逻辑独立。没有新失败或新取舍依据时停止重构。
