# 学习原语使用指南

**先说清希望学习者能做出什么，再决定需要补概念、示范、练习还是反馈。** 不从“做六个页面”或“加一个测验”开始。

## 先写一个足够短的学习约定

一段话即可，不要求每节课填写整套表单：

> 面向【已有经验与常见误解】的人，帮助其在【任务与情境】中做到【可以观察的解释、操作或判断】。允许【工具、材料、Agent 与无障碍支持】，目标相关提示按【条件】提供。用【标准和实际产物】判断本次表现；只承诺【当前完成／变式运用／某段时间后的保持】。缺少先修时去【具体补充入口】。

“学会 Remotion”太宽。“在 30fps、入场持续 18 帧的现有工程里，能把给定秒数换成开始帧号，并解释为何持续时间未变”可以检查。网页练习、正式工程运行和最终视频是不同产物；能力若涉及其中某项，就取得对应证据。

约定还要说明**为什么值得学、适合什么任务、需要哪些投入**。这属于目标与入口条件，不必为每个问题新造一项原语。遇到完全不同的前提，允许走概念体验、项目练习或参考查询路径；不强制所有人从同一段说明开始。

## 从具体失败选择操作

| 实际困难 | 首先调用 | 直接得到什么 |
|---|---|---|
| 不清楚读者把什么当成已知，或疑似把两个量混在一起 | [显化当前理解](PRIMITIVES.md#elicit-starting-model) | 可区分理解的回应及其不确定性 |
| 不知道工具是什么，或没有理解后续过程所需的概念 | [提供必要关系模型](PRIMITIVES.md#relation-model) | 对象、关系、范围和一个具体例子 |
| 看得懂结果，但不知道从哪里做起、为什么这样做 | [展示决策与过程](PRIMITIVES.md#worked-process) | 带理由的步骤和中间结果 |
| 一直看示范，还没有产生与目标有关的回应 | [要求产生目标表现](PRIMITIVES.md#elicit-performance) | 带帮助条件的实际回应 |
| 能复述或做出东西，但理由说不清 | [要求说明依据](PRIMITIVES.md#explain-reasoning) | 结论、关系或证据、条件之间的说明 |
| 出错后只知道错了，不知道差异在哪里、能如何再试 | [对照标准并修正](PRIMITIVES.md#feedback-retry) | 可定位差异、调整动作和再试结果 |
| 只会照着完整答案做 | [调整任务支持](PRIMITIVES.md#fade-support) | 明确减少了哪种帮助的后续任务 |
| 换个数字或条件就不会 | [改变条件再做](PRIMITIVES.md#vary-conditions) | 保持项和改变项清楚的变式及表现 |
| 想判断过一段时间还会不会 | [延后再检查](PRIMITIVES.md#delayed-check) | 时间与帮助条件可追溯的保持观察 |

这是一张选用表，不是每节课的必做清单。教师面对面解释、纸笔、网页和 Agent 对话都可以承载这些操作。

## 材料组织与学习过程分开

课程首页负责给出用途、目标、先修和入口；概念说明提供后续任务需要的关系；任务页接通示范、尝试与反馈；检查记录具体表现。一个页面可以完成多项责任，同一责任也可以跨媒介完成。

学习过程允许返回。做错后回看一个关系，再重做原任务，是有依据的推进；换一页重复同一答案，却不补关系、不调整行动、不产生新证据，不构成学习推进。

## 怎么使用研究

研究为某些教学机制提供有范围的支持。本版把它们组织成操作，是新的方法整理；将它们用于某一网站，是进一步的设计假设。三者不要混写。

例如，记忆检索、预测、代码修改、解释理由都是可能的任务类型，但检索实验的收益不能自动覆盖其余类型。[检索研究的范围](sources/README.md#l-s03)及[分项实践建议](sources/README.md#l-s06)分别说明。

从当前困难选择最少的操作，做好一条可检查的样板，再根据实际错误决定是否扩展。组合方式见[过程组合](PATTERNS.md)，记录方式见[验证与记录](VALIDATION.md)。
