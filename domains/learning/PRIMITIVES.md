# 学习候选操作与专门任务

版本 **0.1.0**。八个候选操作负责不同局部决定；“说明依据”是产生目标表现的专门任务类型，保留独立检索地址。以下“产出”首先指可以制作或观察的材料，不宣称教学动作一执行，学习者就已经获得对应能力。

文中 Remotion 数字例为合成任务，技术模型参见[官方说明及边界](sources/README.md#l-s08)，不是新增的网页体验或真人结果。

各项的输入都包括[学习约定](GUIDE.md)：目标、起点假设、任务、允许工具与帮助、标准、情境及时间范围。输入缺失时先补必要约定，不把“学习者应当会”当事实。

<a id="elicit-starting-model"></a>
## 1. 显化当前理解

**职责：** 选择能区分关键理解的任务，取得学习前或再次学习前的回应。它显化起点，不独自完成纠错与校准。

- **触发与输入**：后续解释依赖某项理解，而当前能力未知；输入包括需要区分的候选理解及可观察判据。
- **操作与产出**：让人预测、解释、分类或试做，留下原回应、获得的帮助与未能区分的部分。答错、不会表达、误读题目都可能产生相似结果，原因先作为候选。
- **正例**：给定同一动画，只改变开始帧号，询问“开始更晚”和“入场变慢”是否相同，并请说明理由。
- **相邻反例**：问“你懂了吗”，或收集答案后仍给所有人完全相同的解释，却称已按起点教学。
- **接口与边界**：题目及判据由课程设计者承担；依据回应分流是过程组合中的额外决定。不能仅凭单次选择给人贴能力标签。
- **删并假设**：它可由“产生目标表现”配合起点专用任务与判据重建；保留入口是为了不遗漏诊断题选择。若独立路由只增加负担，可降为专门任务，不声称不可合并。

本项是诊断职责的整理；课前问题不是所有场景下都已获强效应支持，见[指南分级边界](sources/README.md#l-s06)。

<a id="relation-model"></a>
## 2. 提供必要关系模型

**职责：** 从目标任务反推必须辨认的对象、量、关系和条件，选出足够支撑下一步的表示与实例。

- **触发与输入**：学习者不知道正在处理什么，或后续说明假定了尚未具备的概念。输入是后续任务、正确关系及起点证据或明确假设。
- **操作与产出**：说明各对象是什么、怎样相连、何时成立；用一例将抽象关系与可见结果对应。即时产出是模型说明，不是“已建立在学习者脑中”的断言。
- **正例**：说明一帧是一张画面、30fps 的含义，以及“开始帧号”和“持续帧数”怎样分别决定两个时间量。
- **相邻反例**：只列 frame、fps、interpolate 等词，或把大量完整理论放在开始前而不说明它们服务哪个任务。
- **接口与边界**：给过程示范或练习提供关系；理解是否成立需取得学习者回应。可以用图、文字、实物，不把某种视觉形式定义为本操作。
- **删并假设**：若示范已足以明确全部必要关系，无需再加独立介绍；若关系选择仍需额外判断，这项职责仍应被明确承担。

[概念预训练实验](sources/README.md#l-s01)提供有条件支持；“每门课先学完整理论”不在其结论内。

<a id="worked-process"></a>
## 3. 展示决策与过程

**职责：** 展示从输入和目标走到结果的可解释过程，指出关键步骤为什么成立、检查什么。

- **触发与输入**：学习者已能辨认基本对象，却不知道如何行动或选择。输入包括真实或明确标注为构造的任务、过程、判断标准。
- **操作与产出**：展现起点、关键选择、中间状态、结果及检查依据；说明选择所依赖的关系，避免只有鼠标动作或最终成品。
- **正例**：在 30fps 工程中把开始帧号从 30 改到 45，展示入场区间从 30–48 移为 45–63，并说明长度仍为 18 帧。
- **相邻反例**：只放一条漂亮短片；全速录屏，关键参数变化不可辨认；作者操作过程与读者可以复现的条件混为一谈。
- **接口与边界**：产生可供尝试或局部补全的示范，不能替代学习者自己的表现。缺少可靠过程时先承认未复现，不编造成功路径。
- **删并假设**：静态关系与过程可以在同一例子中呈现；合并时需保留“下一步为何如此选择”的独立责任，而不只是把步骤藏进例子。

例题与解题的组合及逐步过渡有范围内研究支持，见[例题渐隐](sources/README.md#l-s02)。

<a id="elicit-performance"></a>
## 4. 要求产生目标表现

**职责：** 选择与目标能力相符的任务，要求学习者作出可观察回应，并保留帮助条件。

- **触发与输入**：需要促使学习者运用内容，或需要判断某项能力。输入包括要观察的表现、任务材料、判据、允许工具及提示条件。
- **操作与产出**：让人回忆、预测、解释、操作、判断或创作；保留实际回答或产物、操作条件以及是否看过答案。
- **正例**：给出新的开始时刻，让学习者先决定改哪个参数、填什么值，再运行和说明结果。
- **相邻反例**：点“已学会”、直接复制完整答案、Agent 交出成品，就当作学习者能独立解释或操作。
- **接口与边界**：任务及判据不是自由占位参数，课程设计者必须说明为何能观察目标能力。回应交给对照与反馈；无回应时保留未知。允许参考文档的任务仍有效，但不能因此称为无提示记忆检索。
- **删并假设**：解释、诊断等可以作为专门任务保留，合并不应抹去各自判据；若新增任务型引入不同决定，应在该型中明确，不靠一个“生成”词包住一切。

[检索研究](sources/README.md#l-s03)支持的是从记忆提取的特定安排；本项更广，其他任务类型不能自动借用其效果结论。

<a id="explain-reasoning"></a>
## 5. 要求说明依据（专门任务）

**角色：** [产生目标表现](#elicit-performance)的一种专门任务入口，当前不把它列为另一个已证明独立的基础操作。

- **触发与输入**：做对可能来自模仿、猜测或代做，需要观察理解；输入包括待解释的结果、有关关系、证据及适用条件。
- **操作与产出**：要求把“结论—关系或证据—适用条件”连接起来；评价是否解释了当前差异、是否引用了正确依据、是否知道范围。保留原说明，不只标一个正确分数。
- **正例**：说明“开始推迟 15 帧，而两端同时平移，所以入场时长仍为 18 帧”；说明换 fps 后哪些换算需重做。
- **相邻反例**：复述示范句子；篇幅很长但没有说明因果；把“会解释”直接当成“能实际导出视频”。
- **接口与边界**：解释可以暴露问题并进入反馈，但表达困难也可能干扰表现；允许口述、指认、画图等合理表达。不能因不能写长答案就推断没有理解。
- **删并假设**：可完整地表示为特定输出类型及判据时继续作为专门任务；若未来出现现有定义承担不了的独立决定，再审查边界。会操作不等于会解释，仅证明目标不同，不证明操作不可合并。

深层解释问题的实践建议，以及解释与渐隐组合的研究，见[指南](sources/README.md#l-s06)和[组合研究](sources/README.md#l-s09)。

<a id="feedback-retry"></a>
## 6. 对照标准并修正

**职责：** 把实际回应与可信标准对照，给出足以支持下一次调整的信息，并让学习者能够重试。

- **触发与输入**：已有回应或操作结果；输入包括原任务、帮助条件、标准来源和实际产物。缺少可信标准时先记录争议或补标准。
- **操作与产出**：指出具体差异，区分现象与原因候选，提供可执行检查或修改，再保留后续回应。产出是差异、反馈和再试记录，不是笼统“理解已纠正”。
- **正例**：当前参数为 54，却仍回显固定 30→45 题的“晚 0.5 秒”，先修正反馈对象；再让学习者按当前参数核对结果。
- **相邻反例**：只给红叉、鼓励语或分数；自动把错误归为“不够认真”；答案揭示后再答对就登记为独立完成。
- **接口与边界**：反馈可能指出需回到某个关系或示范，形成有目的的循环。即时给完整答案不是默认最佳；是否延后或分层，要按当前任务决定。
- **删并假设**：对照和修正可分时分别调用；本版把它们留作一个反馈闭环入口，不因为包含两个动词就强拆。若只执行了前半，报告“已提供反馈、未观察修正”。

反馈效果随类型和情境变化，见[反馈综述](sources/README.md#l-s05)。本版具体反馈句式是实施建议。

<a id="fade-support"></a>
## 7. 调整任务支持

**职责：** 根据目标与已有表现，选择减少哪种目标相关帮助，形成可承担的下一次尝试；必要时恢复支持。

- **触发与输入**：当前任务大量依赖完整示范或答案，目标需要减少这种依赖。输入是基线任务、实际表现和已有帮助清单。
- **操作与产出**：逐项调整完整答案、解题步骤、目标参数或提示，明确保留什么；产出是支持条件发生了什么变化的任务。
- **正例**：示范已给出帧数，下一题只给秒数；保留操作控件、文档及读屏支持，让学习者选择换算与参数。
- **相邻反例**：把所有说明都藏起；撤除无障碍工具；不给初学者足够信息还把失败解释成能力差。
- **接口与边界**：通过表现与反馈判断是否继续、保持或恢复支持。“零任务提示”表示本次作答没有使用额外针对本题的概念、公式、步骤、定位或答案提示；看了提示再完成，按实际支持条件记录。任务允许的普通工具、参考资料与无障碍支持另行约定；使用允许工具不自动算失败，也不因此称为无帮助记忆检索。
- **删并假设**：修改任务支持可视为任务条件操作；若与变式合并，应仍显式区分“帮助改变”和“任务要求改变”，不能隐藏归因。

[渐隐研究](sources/README.md#l-s02)支持特定例题到解题过渡，不保证所有支持同时消失有益，也不保证任意远迁移。

<a id="vary-conditions"></a>
## 8. 改变条件再做

**职责：** 相对有记录的基线选择有意义的条件变化，考察已学关系的使用范围。

- **触发与输入**：需要区分照抄原例与在变化条件下运用；输入是基线任务与表现、改变项、保持项、标准和帮助条件。不预设基线已掌握。
- **操作与产出**：改变数值、材料、约束或情境，并说明变化为何能检验目标能力；产出是变式及条件完整的回应。
- **正例**：固定 30fps 和 18 帧入场，只把要求改成 1.8 秒开始，让人自行得到起点 54、终点 72。
- **相邻反例**：刚示范淡入，就要求没教过的位移、配音和新 API；将这种失败单独归因于迁移不足。
- **接口与边界**：需要新增能力的题可以做为后续教学，但不能用来干净判断原能力。首个近变式成功不等于跨场景掌握；变式与帮助同时改变时只报告组合条件表现。
- **删并假设**：可与支持和时间调整放在同一任务配置中；保留各决定的单独入口是为了明确改变什么与如何解释结果，并非声称三个操作在逻辑上独立。

例题研究的近迁移与组合条件下的较远迁移不能混称，见[研究范围](sources/README.md#l-s02)。

<a id="delayed-check"></a>
## 9. 延后再检查

**职责：** 按保持目标选择以后何时再次取得表现；时间、任务变化和帮助条件分开记录。

- **触发与输入**：目标包含一段时间后的保持，或需要安排后续练习。输入是基线任务与表现、目标保持时间、可实施间隔及复测条件。
- **操作与产出**：安排延后任务，记录实际间隔、期间练习或接触、工具与提示，取得回应和所需反馈。未知的期间学习照实保留未知。
- **正例**：试点约定数日后在相同工具条件下做等价任务，并如实记录期间是否练习；该间隔只是操作选择。
- **相邻反例**：当天靠完整提示完成，三日后无提示失败，就把全部差异叫遗忘；把 24–72 小时写成任何课程的最优间隔。
- **接口与边界**：延迟检查本身不等于充分的间隔练习方案，也不自动要求“无提示”。需判断时间因素时保持其他条件可比；同时变化时报告组合条件而不单因归因。
- **删并假设**：一次未来任务可以由普通表现任务加时间安排承担；本入口保留保持目标与间隔选择的责任。若只为当下使用，不必调用。

[分散练习综述](sources/README.md#l-s04)主要涉及言语回忆，不能直接等同完整编程项目的保持效果。
