# 视频原语怎样验证

版本 `0.1.0`。验证分别回答：材料是否查过、关系是否表达正确、产物是否做出、目标观众是否理解、感受是否达到。**没有一项能替其他项自动通过。**

本版三个机器示例均为合成设计：来源仅是上传报告，未访问源视频；尚未渲染，事实与可访问性检查待做，真实观众测试未做。本页列的是后续执行方法，不是测试结果。

## 先分清状态与记录

| 部分 | 当前值或内容 | 更新时需要什么 |
|---|---|---|
| `source.source_status` | `report-only` | 记录实际打开的来源位置与核验范围；不能因保存了报告就升级原文证据 |
| `source.media_accessed`、源区间与逐字稿锚点 | `false`、`null`、`null` | 实际访问目标版本并核对位置；不复用示例行号 |
| `selected` | `true` | 只是选用设计，未表示实施 |
| `render.status` / `implemented` / `artifacts` | `proposed` / `false` / 空 | 有可检查产物后记录版本和位置，仍不表示观众受益 |
| `validation.factual` | `pending`，有待查清单、无结果 | 对照原材料记录检查对象、范围、结果 |
| `validation.accessibility` | `pending`，有待查清单、无结果 | 在指定成片、设备和播放方式上实际检查 |
| `validation.viewer` | `untested`、无观察 | 真实观看者、指定版本、任务、回答与观察；不得填模拟结果 |

`checks` 保存待查项目，`records` 保存实际结果。`source.checks` 的例外含义是已经完成的来源定位与核验记录，当前为空。机器结构见[比较示例](examples/compare-options.json)和域内 [check.py](check.py)。真实生产记录保存在项目内，合成方法案例不就地改写成真实节目测试。

## 制作底线逐项检查

| 底线 | 具体问题 | 证据应是什么 |
|---|---|---|
| 事实与来源 | 图形有没有新增不成立的因果、包含或范围关系？ | 与真实稿件、记录或资料的逐项对应 |
| 身份与参照 | 同一对象变化和复制、派生是否区分？参照是否也在暗中改变？ | 关键帧与语义关系记录 |
| 示意与实录 | 流程走到终点是否被误写成执行成功？ | 清楚标签；如声称真实结果，提供实际素材及其支持范围 |
| 字幕与声音 | 预录同步媒体的字幕、必要说话者/非语言声音信息、同步与对白可辨性如何？ | 指定版本的实际播放记录，按适用标准判断 |
| 文字与颜色 | 关键标签在目标设备能否读出？不用颜色能否辨认关系？ | 手机实际播放尺寸、灰度与对比检查；自动检查有其范围 |
| 动作与闪烁 | 是否存在适用规范限制的闪烁或自动运动？有无必要控制？ | 对内容、播放器和适用条件分别检查 |

W3C 的网页成功准则有适用条件：例如 Pause, Stop, Hide 中的相关运动条件涉及自动开始、持续超过五秒且与其他内容并行；不能改写成“所有视频里超过五秒的动作都须单独暂停”。字幕、颜色、运动控制与闪烁是不同检查项。少量已复核的官方说明见[来源登记](sources/references.json)，它们不能替成片的正式合规评估。

## 理解线：让观众做任务

在播放前明确本段目标，播放后优先询问可观察的表现，而非只问“懂了吗”。

| 任务 | 问法示例 | 记录什么 |
|---|---|---|
| 自由复述 | “不看画面，用自己的话说这段最重要的意思。” | 保留的关键点、遗漏与误解 |
| 关系重建 | “这些是三个选择，还是必须依次完成的三步？” | 节点、关系类型、箭头含义 |
| 预测 | “Current 再修改一次，旧的 archive 会发生什么？” | 对变化和不变项的解释 |
| 迁移 | “换成一个新项目，你会保留哪份作当前稿，哪份作回看？” | 能否把关系用于新情境 |

可以为关键关系事先写一个简短评分口径，但必须保留原回答和错误类型；不要用一个总分遮住“谁在决定”或“示意等于执行成功”的关键误解。

## 感受线：问具体画面与体验

分别问：最记得哪一个画面？哪里有空间感或惊喜？哪里舒服、哪里累？音乐有没有抢话？是否愿意用这种形式再看较长内容？若用户只说“好看”，追问具体瞬间。

偏好、疲劳和继续观看意愿独立记录，不把它们当作理解任务的替代指标。播放器观看时长和点击数据如在项目中另有记录，也不直接证明理解提高。

## A／B／C 比较：一份尚未执行的计划

- **A 原版**：使用实际可访问的原视频，固定版本。
- **B 信息呈现改进**：主要改变关系、对应、参照、身份与留停。
- **C 表现力增强**：在 B 基础上调整空间、材质、环境与声音表现。

尽量保持主要旁白、事实与总时长一致；无法保持的变化单独登记。新增解释、额外学习时间、不同音量都可能影响结果，不能把它们归为动画本身的效果。A 尚不可访问时先比较两个原型，不虚构原版基准。

避免让同一个人固定按 A → B → C 重复看同一材料。可让不同观众各看一个版本，或采用不同等难度片段和轮换顺序；如重复观看，记录此前暴露及顺序。小样本用于发现误解与疲劳等失败模式，不据此宣称统计证明。

| 每次观察要保留 | 内容 |
|---|---|
| 条件 | 视频/脚本版本、观众先备知识、设备、播放方式、首次或重复观看 |
| 制作差异 | 改了哪些原语、内容、时长、风格、声音；哪些保持一致 |
| 理解结果 | 原回答、关系重建、预测、迁移、关键误解 |
| 感受结果 | 记忆画面、偏好、惊喜、舒适、疲劳、继续观看意愿 |
| 实际行为 | 暂停、倒退、没读清的标签、需要追问的位置 |
| 结论范围 | 支持/反驳哪项具体设计假设；尚不能回答什么 |

## 机器检查能说明什么

仓库的结构检查核对来源哈希、ID、路径、模块隔离、组合引用，并运行本域校验：示例引用、关系对象、计划时间、焦点与留停、来源及验证状态的一致性。校验不把原语数量固定为十，也不评判审美或声称真人理解。

修改文档后运行仓库的 `validate`；修改校验逻辑后运行现有单元测试。源材料哈希匹配只说明快照未被改写。时序合法只说明安排没有超出计划范围。两者都不表示已渲染或有效。
