# 视频呈现原语候选集 v0.1

**领域版本：** `0.1.0`。**本页十项状态：** 均为 `candidate`。

本页将[输入研究报告](sources/research-original.txt)“最小原语集合与组合检验”中的十张完整卡整理为可选用的动作。名称与主要语义继承报告；机器 ID、显式锚点、统一字段、通用例子及下列边界修正由本次整合新增。原报告的“最小集合”在这里作为待检验假设：**十项不是固定配额，也没有被证明最简或完备。**

这里的原语指可跨题材复用的“输入 → 呈现操作 → 输出变化”。原则说明取舍的理由；配方组织多个动作；海景、角色、材质与声音氛围属于素材和风格；Remotion、SVG、转场、spring 等属于实现。一个组件可以实现不同原语，一个原语也可以由静态画面、剪辑、录屏或动画实现。

## 先看边界，再选动作

- **理解与感受分开评价。** 每张卡分别写“理解预期”和“感受预期”。审美偏好、停留时长与觉得学会了，不能代替复述、关系重建、预测或迁移任务；理解底线也不能被更高的审美分抵消。
- **所有效果都是待检验预期。** 本次没有观看报告所指的 EP03 MP4，没有核验逐字稿或源时间码，没有实施视频改版，也没有进行真实观众验证。文档检查通过不改变这些状态。
- **继承报告不等于全面复核证据。** 原报告包含旧会话引用令牌；本页不将其复制为永久链接，也不将报告的 A/B/C/D 等级写成仓库已独立确认的证据。每卡引用报告章节，并注明原报告所述证据性质；详见[来源说明](sources/README.md)。
- **先明确关系，再决定画法。** 分类、包含、作用范围分别标注；箭头区分先后、因果、输入输出和依赖。来源派生与同一对象的状态改变也分别表达。任何图形或动效都不能补足尚未核清的事实关系。
- **主注意动作与支撑动作分工。** 同一关键时刻，默认只安排一个主注意动作，其余动作提供映射、参照或稳定结构。确需同时比较多个对象时，把它们作为一个明确的比较任务；这是一条可调整的制作约定，不是已证明的普遍定律。

## 按观看困难选用

| 观看困难 | 候选原语 | 创作者短指令 |
|---|---|---|
| 不知道当前看哪里 | [定焦](#focus) | 只突出此刻要看的对象或关系。 |
| 话语、标签和对象对不上 | [对应](#correspond) | 把两种表示的对应关系标清。 |
| 方案切来切去，记不住差异 | [对齐比较](#align-compare) | 先统一比较条件，再突出差异。 |
| 分不清同类、包含与作用范围 | [编组归属](#group) | 标清分组依据和边界的含义。 |
| 一串名词看不出方向关系 | [串联路径](#serial-path) | 标明箭头含义，让路径可以重建。 |
| 变化以后找不到原来的对象 | [保持身份](#identity-preserve) | 留下识别线索，让人知道还是它。 |
| 看见在变，却不知道相对什么变 | [锁定参照](#reference-lock) | 固定一个能解释变化的基准。 |
| 细节看不清，或局部找不到整体 | [改变尺度／视点](#scale-viewpoint) | 先定位，再进入局部或换观察方向。 |
| 刚看清变化就切走 | [留停成像](#hold) | 停止新增事件，让结果可检视。 |
| 分不清动画解释与真实结果 | [证据落地](#evidence-ground) | 说明材料性质，展示可追溯依据。 |

## 粒度、删除与合并规则

选用时先检查现有动作是否已覆盖困难。不能只因为需要一段新动画就新增原语，也不为了维持十项而拒绝新发现。

| 检查 | 保留或调整的依据 |
|---|---|
| 能否说清输入、操作、输出？ | 只有“更高级”“更酷”“卡片飞入”的条目尚不是语义动作。先说清它改变了什么理解关系或观看感受。 |
| 换题材与载体后是否仍成立？ | 如果只适用于一套组件、一个角色或一个软件 API，优先作为实现或素材模式。 |
| 删除以后损失什么？ | 分别检查理解、关系、感受、节奏和辨识度。某一次应用里删掉无损，就删掉本次动作；不能凭单次删除直接废除整个原语。 |
| 是否只是已有动作的参数差异？ | 输入和语义输出相同、差异只有速度、颜色或尺寸时，优先合并成参数。 |
| 是否包含必不可少的多个动作？ | 若总要按次序完成多个不同语义变化，优先作为配方。独立入口是否仍有使用价值，可以继续检验。 |
| 何时改候选集合？ | 记录真实片段、失败模式和删并理由；修改定义时说明版本与适用边界，不把一条成功应用推广为普遍有效。 |

**当前尚未收敛的粒度问题：**“对齐比较”可能是共同参照、对应与定焦的稳定组合，暂保留其按问题选用的价值；“改变尺度／视点”包含改变观察范围与改变观察方向两种模式，使用时分别记录；“编组归属”与“串联路径”各含不同关系类型，类型必须明确；“证据落地”只定义展示依据的呈现操作，来源真伪、主张支持强度仍需独立核验。

定焦与对应暂不合并：前者改变显著性，后者建立映射。保持身份与锁定参照暂不合并：前者回答“是不是同一个对象”，后者回答“相对什么发生了变化”。这些是可检验的定义理由，不是最终分类证明。

<a id="focus"></a>
## 1. 定焦

**ID：** `video.focus`　**状态：** `candidate`　**版本：** `0.1.0`

- **输入／观看困难：** 多个可见对象、一个当前讲述目标；观众不知道该看哪一项，或关键时刻没有与普通信息区分。
- **语义动作：** 在一段时间内提高一个对象、区域或关系的相对显著性，同时降低无关竞争。目标可以是“两方案的这项差异”，不必机械限制为一个图元。
- **输出／结束状态：** 当前主注意目标可辨；解释结束后恢复稳定层级，或明确把焦点交给下一目标。
- **理解预期：** 更容易找到当前话语指向的内容。**感受预期：** 形成节奏、聚光感或一个克制的强调时刻。
- **条件／反例：** 焦点必须与此刻话语和观看任务一致；不要靠抑制背景隐藏判断必需的条件。每句话都闪亮、人物持续跳动、字幕和图形同时争焦点，都会削弱区分。
- **最小实现／参数：** 保持构图，只提高目标边框、字重或亮度，并适度降低其他对象对比；不要求移动或音效。参数为目标、相对强度、持续范围和交接时机，避免依赖颜色这一种编码。
- **组合：** 可在[对应](#correspond)建立映射后强调当前一对；在[对齐比较](#align-compare)中强调一项差异。与尺度移动同时发生时，先明确谁承担主注意动作。
- **失败迹象／最小验证：** 观众先看装饰、人物或旧目标；让未熟悉内容的人短暂看画面后指出“此刻应看哪里”，再检查其回答是否符合实际理解任务。画面显眼不等于理解已提升。
- **例子：** DIY 接线时仅强调当前端子，并保留连接目标与必要极性标签；不让整条灯带同时闪烁。
- **来源／整合状态：** 继承原报告“后台完整原语卡—定焦”；报告将信号提示列为研究依据、聚光感列为设计推论。本次统一字段及补充焦点交接和必要条件边界，原始文献未全面复核，应用与观众效果未验证。

<a id="correspond"></a>
## 2. 对应

**ID：** `video.correspond`　**状态：** `candidate`　**版本：** `0.1.0`

- **输入／观看困难：** 两种或更多表示以及已明确的映射；观众不知道标签指哪个物体、句子指哪块图、图中变量与实际量怎样对应。
- **语义动作：** 用邻近、标签、引线、相同形状、同步出现等方式显式绑定表示。先核对映射是一对一、一对多还是其他关系，再选择编码。
- **输出／结束状态：** 映射可以直接辨认；解释之后可淡化提示，但保留足够线索供回看。
- **理解预期：** 减少搜索和错配。**感受预期：** 形成精确、清楚、有秩序的组织感。
- **条件／反例：** 对应双方必须真实指向同一对象或已声明的关系；共同颜色不能暗示未经证实的同一性。只让标签亮起、所指物体在画外，或只用红绿配对，都不足以完成对应。
- **最小实现／参数：** 将标签放到对象附近并加一条短引线，或在说到对象时同步强调对应标签。参数为距离、标签、编码通道、显示时机和映射数量，不要求动画。
- **组合：** [定焦](#focus)可以强调当前对应项；[编组归属](#group)可以组织多组映射。对应先解决“谁对谁”，不能替代对映射含义的解释。
- **失败迹象／最小验证：** 观众能读标签却指错对象；移除辅助引线后请其重新配对，并说明对应的理由。音频与画面错位时，分别检查时间同步和映射本身。
- **例子：** 将电路图中的 GND 标签与实物板上已核实的 GND 端子相邻展示，用引线和文字完成映射。
- **来源／整合状态：** 继承原报告“后台完整原语卡—对应”；报告以时空邻近与可访问性说明为依据。本次改用通用端子例子，未继承报告尚未核实的“三层 Prompt”具体命名。原始文献未全面复核，应用与观众效果未验证。

<a id="align-compare"></a>
## 3. 对齐比较

**ID：** `video.align-compare`　**状态：** `candidate`　**版本：** `0.1.0`

- **输入／观看困难：** 两个或多个方案、当前选择目标和有意义的共同维度；整屏来回切换使比较依赖记忆，或方案各说各的优点。
- **语义动作：** 统一尺度、单位、条件、位置或字段顺序，保持共同项稳定，再逐项显出影响选择的差异。
- **输出／结束状态：** 可直接比较的差异结构；最后保留共同条件与关键差异总览，未知值明确标注。
- **理解预期：** 说清差异及适用条件，支持选择。**感受预期：** 形成揭示差别的清晰感与满足感。
- **条件／反例：** 必须确有共同维度；不可比的数据不能只靠两列排版制造等价。候选方案并置不代表固定先后，未经核实的数字不能填成精确结论。
- **最小实现／参数：** 同屏两列、相同字段顺序，先静态显示，再只强调当前讨论的差异。参数为比较维度、并置或叠合方式、条件、差异数量和揭示顺序；手机空间不足时减少同时比较的维度。
- **组合：** 以[锁定参照](#reference-lock)保持共同基准，以[定焦](#focus)突出单项差异，以[留停成像](#hold)保留总览。若只能通过多个动作才完成任务，应用记录应同时列出这些组成。
- **失败迹象／最小验证：** 观众记住颜色或“左边更好”，却说不出比较条件；撤掉画面后请其说出关键差异，再改变一个条件，观察选择是否随之合理改变。
- **例子：** 比较“先翻译全文”和“先讨论投稿方向”时，以本次目标、先做什么、成本与风险为共同字段；这只是情境示例，不把某一方案写成普遍最优。
- **来源／整合状态：** 继承原报告“后台完整原语卡—对齐比较”；报告承认它是借静态比较、信号和邻近原则形成的组合抽象。本次补明条件、未知值与可比性；它是否应归为配方仍待使用检验，原始文献与观众效果未全面复核。

## 4. 编组归属

**ID：** `video.group`　**状态：** `candidate`　**版本：** `0.1.0`

- **输入／观看困难：** 对象集合与已核实的关系类型；观众不清楚哪些同类、谁包含谁，或某项设置影响哪些对象。
- **语义动作：** 选择容器、边界、共同底板或空间嵌套，明确表示分类、包含或作用范围；写出本次边界的含义，不能只因距离近就推导归属。
- **输出／结束状态：** 可辨的集合、层级或范围；保留必要边界与名称，避免动作结束后又失去组织线索。
- **理解预期：** 分清并列、包含和影响范围。**感受预期：** 建立秩序、层次和空间分区感。
- **条件／反例：** 先确认关系，再选容器。软件安装目录、项目工作目录与一次任务产物未必互相包含；不能因为同屏出现就套进同一盒子。分组不代表因果关系。
- **最小实现／参数：** 为一组对象增加带标签的边界，或用树状结构表达真实包含。参数为关系类型、嵌套深度、边界强度、标签和展开方式；手机看不清时按层呈现而非无限缩字。
- **组合：** [改变尺度／视点](#scale-viewpoint)进入某个分组，[锁定参照](#reference-lock)保留位置线索，[对应](#correspond)解释边界名称。分组运动应让位于当前讲述目标。
- **失败迹象／最小验证：** 观众把同类误认成包含、把作用范围误认成存储位置；请其重画分组，并解释一个边界内外对象的差异。仅能复述标签不算重建关系。
- **例子：** 在一个已声明规则的文件管理示例中，分别标明“当前工作稿”和“历史快照”，再用项目边界说明它们共同属于哪个项目。
- **来源／整合状态：** 继承原报告“后台完整原语卡—编组归属”；报告将其形式化归为设计推论。本次显式区分类别、包含与作用范围，并避免泛化软件目录事实；原始依据未全面复核，应用与观众效果未验证。

<a id="serial-path"></a>
## 5. 串联路径

**ID：** `video.serial-path`　**状态：** `candidate`　**版本：** `0.1.0`

- **输入／观看困难：** 节点及有方向的关系；听到一串名词却不知道它们表示先后、因果、输入输出还是依赖。
- **语义动作：** 明确每条边的含义，按叙述需要展开节点与连接。已走过部分保留弱可见；存在分支、循环或决策条件时按真实结构呈现，不能为简洁强行线性化。
- **输出／结束状态：** 可重建的有向路径；终点所代表的是“进入某阶段”“产出某物”还是“达到某状态”需明确。
- **理解预期：** 看清流程、方向和条件，避免把过程听成并列清单。**感受预期：** 形成推进感、期待和阶段节奏。
- **条件／反例：** 先后关系不是因果证明；一种箭头不能在未说明时混用多种含义。路径中的确认人、分支条件或失败出口若影响理解，必须保留。
- **最小实现／参数：** 静态节点和有标签的箭头即可；播放时逐步强调当前节点。参数为关系类型、路径结构、阶段顺序、累积显示及停留点；没有真实完成证据时用“流程示意”。
- **组合：** [定焦](#focus)标当前阶段，[保持身份](#identity-preserve)帮助追踪同一对象，[锁定参照](#reference-lock)保留依据，[留停成像](#hold)停在关键关系已形成的时刻。有真实结果再使用[证据落地](#evidence-ground)。
- **失败迹象／最小验证：** 观众只会背顺序，却把“之后”说成“导致”，或把到达末节点当作执行成功；打乱节点请其重排，同时解释每条边和所需条件。
- **例子：** 在明确采用人工选择的任务示例中，呈现“需求 → 澄清 → 候选 → 人确认 → Plan → 执行”。这表达本例安排，不声明所有 Agent 工作流都必须有同一确认门。
- **来源／整合状态：** 继承原报告“后台完整原语卡—串联路径”；报告联系动态表示与瞬时信息研究。本次明确箭头类型、非线性边界与示意状态；原始文献未全面复核，应用与观众效果未验证。

<a id="identity-preserve"></a>
## 6. 保持身份

**ID：** `video.identity-preserve`　**状态：** `candidate`　**版本：** `0.1.0`

- **输入／观看困难：** 同一实体的前后状态与可保留识别线索；变化以后观众以为出现了新对象，或找不到刚才的对象。
- **语义动作：** 在状态变化中保留足够的位置、标签、骨架、纹理或连续轨迹，让“谁发生了变化”可追踪。先确认前后确为同一实体。
- **输出／结束状态：** 对象身份连续，状态差异可辨；最终对象仍能与起始对象建立明确关系。
- **理解预期：** 分清对象本体与变化属性。**感受预期：** 连贯、流畅，也可形成一次有根据的连续变形惊喜。
- **条件／反例：** 复制、派生与替换不是同一实体改变状态。Current 复制出 archive 快照时应保留 Current，并把快照标作新对象；不能为 morph 好看让它变成 archive 后消失。
- **最小实现／参数：** 固定对象标签和位置，只更新一个状态字段；无需复杂形变。参数为保留线索、变化属性、轨迹、速度与切镜方式，不能仅靠颜色保持身份。
- **组合：** [锁定参照](#reference-lock)保留旧状态，[串联路径](#serial-path)交代变化发生的过程，[留停成像](#hold)让结果可看清。跨尺度时先保留定位与身份线索。
- **失败迹象／最小验证：** 观众说不清是“它变了”还是“复制了一份”；请其指出原对象、当前对象及新产生的对象，说明各自关系。连续动画只是提示，不是身份事实的证明。
- **例子：** 文档 Current 更新标题和正文时，文件标识及位置保持；另存为快照则出现带版本标签的第二个对象，并标明派生来源。
- **来源／整合状态：** 继承原报告“后台完整原语卡—保持身份”；报告借动画感知和连续变化说明其依据。本次明确复制、派生、替换与状态改变的差别；原始文献未全面复核，应用与观众效果未验证。

<a id="reference-lock"></a>
## 7. 锁定参照

**ID：** `video.reference-lock`　**状态：** `candidate`　**版本：** `0.1.0`

- **输入／观看困难：** 一个变化对象、要判断的变化维度及可信基准；观众看见动了，却不知道变了多少、哪里变，或什么仍未变。
- **语义动作：** 在变化期间保持有关的基线、尺度、坐标、旧状态或空间锚点稳定，让变化有可比较的参照。
- **输出／结束状态：** 变化对象与基准仍可区分；必要时保留淡化的旧状态，说明什么变了、什么没变。
- **理解预期：** 支持比较变化量和位置。**感受预期：** 稳定、从容，为主要动作提供空间。
- **条件／反例：** 基准必须与判断任务有关；如果坐标尺度也变化，应明确提示，不能同时移动参照又假装变化可比。旧状态是示意、快照还是实测数据也需可辨。
- **最小实现／参数：** 固定一条基线或半透明旧轮廓，仅更新待比较对象。参数为参照类型、单位、对齐方式、显著度和保留时长；不一定增加坐标轴。
- **组合：** 为[保持身份](#identity-preserve)提供变化前后比较，为[对齐比较](#align-compare)提供共同条件，为[改变尺度／视点](#scale-viewpoint)保留位置。参照可以静态支撑，通常不承担主注意动作。
- **失败迹象／最小验证：** 观众误把缩放当增长，或把背景位移当对象移动；请其说明“相对什么变、什么没有变”，必要时要求估计变化方向与大致幅度。
- **例子：** 解释房间布局调整时固定同一比例的墙体轮廓，再移动家具；若镜头缩放，额外标明视图变化，避免误读为房间变大。
- **来源／整合状态：** 继承原报告“后台完整原语卡—锁定参照”；报告称其与静态比较、瞬时信息研究相容，并将该原语视为设计抽象。本次补充单位、可比性和快照性质，原始依据未全面复核，应用与观众效果未验证。

## 8. 改变尺度／视点

**ID：** `video.scale-viewpoint`　**状态：** `candidate`　**版本：** `0.1.0`

- **输入／观看困难：** 同一对象的整体、局部或其他观察方向及其位置关系；局部细节看不清，或只见细节而不知它位于哪里。
- **语义动作：** 先标定对象和位置，再改变观察范围或观察方向。使用记录分别注明 `scale`（范围／尺度）与 `viewpoint`（观察方向）模式，不把二者默认当成同一操作。
- **输出／结束状态：** 新视图仍可对应原对象；观众知道局部在哪里或为何换视点。必要时回到整体或保留小定位图。
- **理解预期：** 建立整体与局部的关系，暴露被遮挡结构。**感受预期：** 形成空间感、探索感或一次有意义的揭示。
- **条件／反例：** 视图关系必须真实；不能用推镜头暗示未经确认的包含关系。只是让文字变大不必使用完整尺度叙事；同时换颜色、位置、标签和视角会破坏身份线索。
- **最小实现／参数：** 先在总览框选局部，再切到带同一标签的局部图，保留定位标记；无需连续飞行镜头或 3D。参数为模式、范围跨度、方向、定位线索、转场和回归位置。
- **组合：** [编组归属](#group)说明层级，[保持身份](#identity-preserve)保持对象线索，[锁定参照](#reference-lock)保留位置，[留停成像](#hold)让新视图稳定。镜头移动时避免多个对象另行争焦点。
- **失败迹象／最小验证：** 观众以为换了一个对象、把视觉层叠当实际包含；让其在总览上指出刚才局部的位置，或说明换视点新增了什么信息。
- **例子：** 先在设备总览中框出接线区域，再切到端子近景，保留设备方向与相同端子标签；涉及真实接线时仍需实物或文档核验。
- **来源／整合状态：** 继承原报告“后台完整原语卡—改变尺度/视点”；报告以空间重定向与表示相符为理由。本次区分两种模式，仍保留是否拆分的粒度问题；原始文献未全面复核，应用与观众效果未验证。

## 9. 留停成像

**ID：** `video.hold`　**状态：** `candidate`　**版本：** `0.1.0`

- **输入／观看困难：** 刚完成的变化或关系、需要检查的结果及观众的阅读任务；画面一形成就切走，观众没有时间整合。
- **语义动作：** 暂停新增关键视觉事件，保留稳定结果。旁白可以总结、提出检查问题或留白；环境运动若继续存在，也不能妨碍观察。
- **输出／结束状态：** 一个可检视、可复述的关系画面；进入下一段时有明确的焦点交接，而非无限拖延。
- **理解预期：** 为关系重建、文字阅读或预测留下时间。**感受预期：** 形成呼吸、余韵与动作后的安定感。
- **条件／反例：** 先确保结果本身表达清楚；停住一张错误或拥挤的图不会修复关系。所有镜头等长停顿、在简单闲聊段反复定格，都可能破坏节奏。
- **最小实现／参数：** 保持最后一个有效画面，不增加新标签或新主动作。参数为要观察的对象、文字量、观众先备知识、停留时长和音频安排；没有适用于所有片段的固定秒数。
- **组合：** 通常接在[对齐比较](#align-compare)、[串联路径](#serial-path)、[改变尺度／视点](#scale-viewpoint)后。保持稳定时仍可用低强度[对应](#correspond)线索，不应重新制造竞争焦点。
- **失败迹象／最小验证：** 观众仍需回退，或觉得无内容等待；比较有无停留版本的关系重建与疲劳，记录总观看时间、暂停和重复观看，不能把额外学习时间算成纯视觉增益。
- **例子：** 一次 DIY 接线完成后保留端口和连接全貌，让观众确认线去向，再进入下一步；画面展示完成不代表真实接线已经通过安全或功能验证。
- **来源／整合状态：** 继承原报告“后台完整原语卡—留停成像”；报告联系瞬时信息和分段研究，并承认具体时长待测。本次补充时间混淆与“稳定结果不等于正确”的边界，原始文献未全面复核，应用与观众效果未验证。

## 10. 证据落地

**ID：** `video.evidence-ground`　**状态：** `candidate`　**版本：** `0.1.0`

- **输入／观看困难：** 一个具体主张、可追溯材料及其支持范围；观众看懂了示意，却不知道现实中是否发生、依据来自哪里。
- **语义动作：** 明确区分“解释示意”和“实际材料”，展示有关的原始界面、录像、测量结果、资料节选或可定位来源，并说明它支持什么、仍不能支持什么。
- **输出／结束状态：** 观众能识别材料性质、主张与依据的对应关系及事实边界；必要时从实录返回解释图，但保留来源入口或标识。
- **理解预期：** 分清模型、演示、观察和结论。**感受预期：** 抽象与真实材料的质感变化可以形成记忆点；可信感不能替代证据可靠性。
- **条件／反例：** 材料必须可追溯且确实相关；截图不自动证明完整工作流成功，终端输出也需说明操作、版本、环境及结果范围。生成的模拟界面、动画进度完成或箭头到终点都不是实际执行证据。
- **最小实现／参数：** 在示意旁显示一份有关的真实资料，标注“示意”或“实录”、来源位置和支持的具体主张；资料缺失则明确缺失，不伪造成功画面。参数为材料类型、来源锚点、展示范围、可读性和必要脱敏。
- **组合：** 先用[串联路径](#serial-path)解释机制，再用本卡展示实际材料；[定焦](#focus)指出有关结果，[对应](#correspond)连接主张与资料，[留停成像](#hold)给足核对时间。
- **失败迹象／最小验证：** 观众把示意当实测，把一次成功当普遍保证；请其区分解释画面与证据画面，并回答这份材料能证明什么、不能证明什么。另行核对来源和材料真实性，不以观众相信为通过标准。
- **例子：** 安装教程先给流程示意，随后显示本次真实环境中的验证结果；如果只有规划分镜，明确写“尚未实录／尚未执行验证”。
- **来源／整合状态：** 继承原报告“后台完整原语卡—证据落地”；报告把它归为科学传播与制作流程经验、设计推论，而非单一学习实验。本次限定其为展示依据的动作，来源真实性与支持强度仍独立检查；原始依据未全面复核，应用与观众效果未验证。
