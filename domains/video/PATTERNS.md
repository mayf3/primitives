# 组合配方：从关系到可制作片段

前三个实例取材于[上传报告](sources/research-original.txt)，经过本次整理与语义纠错；后附阈值、封装、规则试算与预测参照的纸上配方，均为**合成设计方案**。没有把它们与实际节目逐段对齐；时间全是新片段的计划时间，不是已核实的源视频时间码，也不是已经渲染的产物。

### 0.3.1 · 比较之前要决定什么

沿用入口 `video.align-compare`。先写明要回答的差异、候选的适用条件、各字段及单位、对应值从哪里来。条件不同且无法换算时分列条件；缺一项就写“待核”。如果上游只给了两张卡和一个“对比”的动词，固定位置、配色和加高亮都无法决定该比哪一项。

已有可比材料后，分镜师锁定共同基准，让两个值落在同名字段，需要引导时再突出差异。整段的动作清单可保留原有 ID，同一拍选择记“对齐比较”或注明展开动作；评估时只数一项观看任务。选择前介绍三种候选是编组；只要说明“由谁做选择”，就不必增加比较镜头。

**两边怎样取值。** 比较结果时，给同一字段同一行名、单位和读法。若 A 配图标加一句短话，B 却要从密集术语中找答案，先把两边改写到同一具体程度。比较步骤数时保留必要的长短差；比较最后总量时给两边同样的总数与轮廓，明细仍可追认。盖住方案名，换边后再读一次。

**手机同槽。** 比较 A、B 两版课件可一直保留“同一页标题／点同一字／选中了什么”三个条件。在同一位置先演 A，留下小字“A：整页图片”；B 接替时显示“B：标题文本框”，末帧同时保留两句结果。这样能看清两次点击，也无需记住上一屏全文。若上下两屏连字段都换了，检查者应退回补齐比较依据。

## 三个可直接继续制作的实例

### 一、三个选项怎样比较 · 72 秒

**场景：** 读完论文，接下来先逐字翻译、先改实验，还是先规划结构？观众要看出这是面向同一目标的候选选择，不是三个必须依次执行的步骤。

**组合：** 定焦目标 → 编组候选 → 对齐比较 → 定焦选择者 → 留停。共同目标是前提；比较阶段用同名字段和稳定参照来落实。机器记录：[compare-options.json](examples/compare-options.json)。

| 计划时间 | 观众任务与画面 | 主动作 | 保持不变或结束状态 |
|---|---|---|---|
| 0～10 秒 | 知道共同目标是准备投稿 | 定焦目标 | 环境与目标位置稳定 |
| 10～25 秒 | 看见三个平行候选，均不自动获胜 | 编组归属 | 候选名称与位置 |
| 25～42 秒 | 按“先改变什么、先确认什么、主要不确定性”比较 | 对齐比较 | 相同项固定，只解释当前差异 |
| 42～58 秒 | 知道这个情境中由人选择 | 定焦选择者 | 三个候选继续可见 |
| 58～66 秒 | 选择者说完后回到总览，用原来的字段核对其选择 | 锁定参照 | 字段顺序与目标稳定 |
| 66～72 秒 | 留出检查关系的时间 | 留停成像 | 目标、候选与选择者同屏 |

感受目标是从杂乱到清楚、从容；只在选择位置做轻微强调。没有数据支持时，不画方案优劣分数，不写“先脑暴一定最好”。旁白关于风险的补充属于新增解释，制作前要核实。

**检查任务：** 三个对象是什么关系？最后谁作选择？换一篇论文，应该先问哪些条件？另问观众最记得哪个画面、有没有觉得表格太重。

### 二、Current 与历史快照 · 48 秒

**场景：** 解释示例项目中一份持续编辑的 Current 与两份历史快照。这里采用复制式归档，只是一个具体约定。

**组合：** 编组项目 → 保持 Current 身份 → 展示派生副本 → 对应版本标签 → 留停。派生时用身份判断指清母本与新副本；用旧快照衡量下一次改动时，才将它作为参照。机器记录：[current-archive.json](examples/current-archive.json)。

| 计划时间 | 画面与对象关系 | 主动作 | 不能误画成什么 |
|---|---|---|---|
| 0～8 秒 | 标明项目边界和 Current 的名称 | 编组 | 不让文档与项目混为一物 |
| 8～18 秒 | Current 内部内容变化，名称与身份不变 | 保持身份 | 不是换了一份不相关文档 |
| 18～28 秒 | 复制出独立 archive v1，Current 继续可见 | 保持身份（标明派生）、对应版本 | 不能让 Current 变成 archive 后消失 |
| 28～34 秒 | 并看 v1 的旧内容与 Current 的新内容 | 锁定参照（基线为 v1 的旧内容） | 不能暗示快照与工作稿实时同步 |
| 34～40 秒 | 复制出 archive v2，注明第二次快照 | 对应版本 | v1 和 v2 不合并为一个对象 |
| 40～48 秒 | 保留工作稿与两个快照供比较 | 留停成像 | 不切走或继续新增文件 |

感受目标是稳定、清晰的版本感；项目轮廓和背景都可静止。复制过程保留来源关系，但不把“视觉连续”解释成“所有对象身份相同”。真实工程如采用 Git、原地版本或别的约定，应先改语义，再改分镜。

**检查任务：** 哪份继续改、哪份可回看？Current 再更新会不会改写 v1？让观众画出一次新的归档。另问稳定布局是否有帮助、结尾是否停得过长。

### 三、澄清需求、确认方向、形成计划 · 78 秒

**场景：** 本例由 AI 澄清并给候选，人选择方向，然后形成 Plan 并开始 Execute。这是该情境采用的分工，不是所有 Agent 工作流都必须反复请人确认的通用协议。

**组合：** 串联路径 → 定焦当前阶段 → 保持需求身份 → 编组候选 → 定焦人的确认 → 留住作为执行依据的 Plan → 留停。此例要重建分工，材料没有提供逐项比较候选的共同字段。机器记录：[decision-gate.json](examples/decision-gate.json)。

| 计划时间 | 当前重点 | 可制作动作 | 语义约束 |
|---|---|---|---|
| 0～12 秒 | 待澄清的需求 | 一份需求出现在稳定位置 | 不制造已确定方案 |
| 12～30 秒 | 澄清条件 | 条件逐项补齐，原需求仍可定位 | 仍是同一需求，不整屏换对象 |
| 30～46 秒 | AI 提出候选 | 同列展示，注明都只是备选 | 不自动选中，也不把出现顺序当优先级 |
| 46～56 秒 | 人确认方向 | 一次局部对比与克制的声音落点 | 显式区分建议和选择 |
| 56～67 秒 | 形成 Plan | 将已确认内容写入一个新文档 | Plan 派生于选择，不等同于候选本体 |
| 67～72 秒 | 按 Plan 开始执行 | 从计划指向执行过程，Plan 留在原位 | 开始执行不等于成功完成 |
| 72～78 秒 | 检视交接关系 | 停在确认、计划、执行可见的画面 | 标记“流程示意”，没有成功勾选 |

感受目标是逐渐收敛，唯一较明显的强调留给确认环节。若后续取得真实执行结果，可另接“证据落地”：说明素材来源、版本和实际支持的结论。没有实际材料时不补造成功界面。

**检查任务：** 谁提出候选、谁作选择？Plan 何时形成？画面能证明任务已完成吗？另问推进是否清楚、确认时刻是否有记忆点、是否像过于生硬的流程图。

原报告同时出现源区间 16:45～17:30、78 秒分镜和 66 秒焦点事件。本例只使用 78 秒计划时间；源范围与逐字稿均为空。对接原音轨前必须重新核对素材，不能把它当45秒的等长替换。

操作后选中什么、如何表现并发过载、怎样从原句抽出论证关系，见[六个知识播客配方](PODCAST-PATTERNS.md)。

<a id="continuous-threshold"></a>
## 连续变化在哪里跨过阈值？

纸上例子。两条封装线处理同规格货物，合成基线每分钟完成 10 件。横轴是新线的设定值 x，纵轴 R 是“新线完成率／基线完成率”。为了练习读图，给定关系 R(x) = 0.8 + 0.1x，取 0 ≤ x ≤ 4。先沿曲线找与 R = 1 的交点 x = 2，再分别给交点两侧和交点标明“较慢／持平／较快”。换成一个游标加即时文字，观众仍能回答同一问题。阈值来自这次比较如何定义“持平”。

遮掉类别名但保留刻度，观众仍能读到 1；遮掉尺度与判别规则、只留颜色，就不能还原交点所代表的量。分别给 x = 1、2、3，请人指出类别并说出依据。若实际只量过 x = 1 和 3，能报告的是两个采样值分别在阈值两侧；函数形状未经确定时需另有依据才能报出精确交点。这个分镜组合了[锁定参照](PRIMITIVES.md#reference-lock)和[编组归属](PRIMITIVES.md#group)。若旁白仅问哪点更高，只需共同读数基准。

**换条曲线再分区。** 沿用 0 ≤ x ≤ 4 和同一条持平线 R＝1。请读者先找出全部持平位置，再说出每一侧属于哪一类；保留坐标数字和区间端点。

| 合成关系 | 持平位置 | 沿 x 从小到大怎样画 |
|---|---|---|
| R＝1＋0.1(x−1)(x−3) | x＝1、3 | [0,1) 较快，(1,3) 较慢，(3,4] 又较快；两个持平点各标一次。 |
| R＝1−0.1(x−2)² | 仅 x＝2 | x＝1、2、3 的读数为 0.9、1、0.9。在顶点标“持平”，两侧都标“较慢”。曲线接触阈值后折回。 |
| 折线依次连接 (0,0.9)、(1,1)、(3,1)、(4,1.1) | 整段 [1,3]，含两端 | [0,1) 较慢，[1,3] 持平，(3,4] 较快。沿阈值标完整横段，避免只给中点一个“持平”圆点。 |

相切的例子里，仅凭“碰到线就换类”会把右侧错画为较快。平台例子里，只看首尾两个采样值还无法认领中间整段；这里能画出平台，依据是明确给定的折线。

<a id="chunk"></a>
## 已解释的局部怎样成为下一层的一个整体？

0.5.0 增补。采用候选组合 `video.chunk`，展开为编组归属、对应和保持身份。本例约定把“烫皮 → 去皮 → 切丁”称为“番茄预处理”，输入是整只番茄，输出是切丁番茄。三步及其顺序由本例预先给定，未指定火候、工时、去籽或调味要求。接下来的问题只问这组准备之后接哪一步；需要核对内部顺序时再展开。机器记录见[封装流程合成分镜](examples/chunked-process.json)。

封装前先给制作方成员与分组依据、整体短名、输入输出和保留条件，以及后续判断需要哪些内部区别。短名由内容编辑确认，不能把“番茄预处理”自行改成“烹饪完成”。已有规则只约定这三步时，也不能用短名新增“已经去籽”等结果。一个具名代理表示刚才那组结构，语义记录继续保留成员和关系；展开表示与收拢表示都指向同一子流程。

| 计划时间 | 观看任务与画面 | 需要保持什么 |
|---|---|---|
| 0～8 秒 | 用具名边界交代三步、顺序及输入输出 | 每步有自己的标识，箭头只表示本例步骤先后，过程示意与实际完成分开 |
| 8～14 秒 | 把内部图元收起，在原位置显示“番茄预处理”代理，交代它代表刚才三步 | 整组与短名的映射可追认，输入输出继续可见。可以原尺寸切换，无需缩放 |
| 14～19 秒 | 稳定保留代理与输入输出，让观众说出它代指什么 | 看清短名不等于记住全部内部细节，待回答后再决定是否延长 |
| 19～27 秒 | 下一层路径把这个整体接到“下锅”步骤 | 代理作为同一子流程的表示，不画成另复制的一次预处理，也不标成实际已烹饪 |
| 27～35 秒 | 提出“切丁在去皮之前还是之后？”，从代理回到同一组三步 | 原来的成员、顺序、名称和输入输出恢复，定位线索不断开 |
| 35～42 秒 | 留住展开结构、代理归属及下一层接点，核对两层关系 | 两种表示不计成两次执行，能指出哪一问需要内部细节 |

只加外框可以表达归属，仍未给后续整体引用一个可辨名称；只缩成缩略图，也未说明短名与内部结构的映射。给定以上内容决定后，三个组成动作可以完成这个配方。改变尺度、定焦和留停按所在拍的额外任务选用，收拢的动画形式本身不新增语义动作。

**检查任务。** 只看代理，能否指出它代表哪三步、接下来连向哪一步？看到内部顺序问题时，能否找到应展开的结构？若下一章改问准备总用时或能否并行，先补齐相关工时和依赖；短名无法回答未保留的条件。可与“始终展开”版本在同等材料和观看任务下比较，记录误认、回看与疲劳，尚不据画面少了几个框推算工作记忆改善。

<a id="rule-instance"></a>
## 固定规则，怎样从具体试算回到通式？

0.5.0 增补。纸上约定无量纲的规则 `y = x²`，范围为 `−2 ≤ x ≤ 2`。规则是本例的已给输入，三次试算用来解释它的含义。组合对应、锁定参照与留停，需要从图中定位当前值时再定焦。

| 拍点 | 观众怎样核对 | 保留的联系 |
|---|---|---|
| 先认规则与范围 | 显示 `y = x²`、x 的取值范围及同一坐标尺度 | x 始终是代入值，y 始终是该规则的输出 |
| 分别代入 `−2、0、2` | 在公式同一位置代入，依次得到 `4、0、4`，对应标出三点 | 数值、代入步骤与图上位置能相互找回 |
| 在范围内改变 x | 若用动画，令 `u ∈ [0,1]`、`x(u) = −2 + 4u`、`y(u) = (−2 + 4u)²`；静态取值表也可解释同一映射 | 动画各中间值由已给规则计算，时间只负责遍历参数。x 从 −2 到 0 时 y 下降，从 0 到 2 时 y 上升 |
| 回到通式再试一次 | 恢复 `y = x²`，请读者给出 `x = −1` 或 `1` 的结果，再问 `y = 1` 能对应哪些 x | 保留范围与角色，发现同一 y 可对应两个 x，不能把它误读成唯一反向映射 |

三个点不能确定一条通式。只有离散观测、尚未给出规律时，先呈现观测点与未知范围；额外的平滑插值须注明其模型依据。本例也不能在整个范围统一标“x 增大，y 增大”。若换成有滞后、跳变或其他参数的模型，先给出相应规则，再安排联动，不能沿用本例的即时计算效果去断言现实因果。

**检查任务。** 让读者说明“给定规则计算”“观察三个点”“推出通用规律”各自有何依据。回到公式后，能否用未演过的值试算，并解释为什么 `x = −1` 和 `1` 得到相同结果？画面顺滑与看过三个正确答案均不能替这项任务。

<a id="prediction-baseline"></a>
## 先固定一项预测，再比较结果

0.5.0 增补。合成模型从一块方块开始，每轮把每一块复制成两块，只演示整数轮次 `n = 0、1、2、3`。先给最初两轮的数量 1、2，编辑预先提出一种候选预测“每轮只增加一块”，即 `P(n) = 1 + n`。这项预测属于编辑设定，不能称作观众实际猜测、人人常识或统计零假设。

先把预测假设、轮次和数量单位固定，再揭示本例给定的倍增规则 `R(n) = 2ⁿ`。同轮同尺度比较如下，预测保留在原位。

| 轮次 n | 编辑预测 P(n) | 给定模型结果 R(n) | 这一处支持什么判断 |
|---|---|---|---|
| 0 | 1 块 | 1 块 | 起始数量相同 |
| 1 | 2 块 | 2 块 | 此轮预测命中，两种规则尚未被这两个点区分 |
| 2 | 3 块 | 4 块 | 这一轮相差 1 块，须回到每轮怎样生成解释差异 |
| 3 | 4 块 | 8 块 | 保持同一计数方式，差异扩大到 4 块 |

画面中的轮次与成片播放秒数分别说明。若画方块复制，给每轮结果清楚的停点，不补造半轮的实测过程。本例结果来自所定义的模型，只有真实运行或观察素材时才用相应范围的实测称谓。若后来模型确为每轮增加一块，预测可以全部命中，仍能核对参照与结果；无需制造意外或把命中改成失败。

用锁定参照保留预测的口径，用对应绑定同轮数量，必要时接对齐比较和留停。实际观众先作预测时，在制作项目保存其原回答、提问条件与揭示先后；先看到答案再补写的预测不能当成事前回答。改变了假设、单位或对象范围时，另记新预测，不无痕移动原基线。

**检查任务。** 请读者分别指出预测是谁提出、采用什么假设、结果由什么规则或记录得到，再说明哪一轮可区分两种规则。错误预测可以提供检验机会，预测命中也可能帮助理解，不能只凭“惊讶”判断观众已经掌握。

| 认识新概念 | 先认识对象 → 编组 → 定焦属性 → 对应术语 → 留停 | “先认识对象”是制作步骤，不另注册原语 |
| 从整体看局部 | 编组 → 改变尺度／视点 → 锁定定位参照 → 留停 | 不同时更换对象的全部识别线索 |
| 纠正一个观点 | 保留旧说法 → 证据落地 → 对齐比较新旧 → 留停 | 新材料要真实可核；不要无痕换字幕假装没有变化 |
| 区分等待、串行与并发 | 用共同时间尺标事件起止，再查区间是否相交 | 两段区间首尾相接为串行，有共同覆盖才算重叠；中间空档能表明未发生所列事件，要解释成“正在等谁”，另需就绪或依赖条件 |
| 演示实际操作 | 示意解释 → 证据落地 → 定焦真实结果 → 对应回模型 | 录屏只证明实际展示的范围，不自动证明完整任务成功 |
| 章节转折 | 小结 → 留停 → 一次有限视点变化 → 新章节 | 章节信息与必要字幕仍可辨 |
| 平静收束 | 回到稳定大构图 → 减少当前信息 → 留住记忆对象 | 不在收束时不断追加新关系 |

## 检查一个配方是否过大

逐项问：需要这个动作解决什么困难？删掉是否损失关系或目标感受？此刻哪个动作主导注意？动作结束后保留什么？哪里有实际证据、哪里只是提案？当一个常用组合稳定解决完整任务时，把它保留为配方，不必包装成新的不可分原语。

实际制作后按[验证方法](VALIDATION.md)记录理解与感受。原版、改版、观众结果都应绑定具体版本；本页计划时间是可修改起点，不是通用停留秒数。
