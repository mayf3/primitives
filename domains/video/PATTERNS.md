# 组合配方：从关系到可制作片段

下列三个实例取材于[上传报告](sources/research-original.txt)，经过本次整理与语义纠错，均为**合成设计方案**。没有把它们与实际 EP03 视频逐段对齐；时间全是新片段的计划时间，不是已核实的源视频时间码，也不是已经渲染的产物。

## 三个可直接继续制作的实例

### 一、三个选项怎样比较 · 72 秒

**场景：** 读完论文，接下来先逐字翻译、先改实验，还是先规划结构？观众要看出这是面向同一目标的候选选择，不是三个必须依次执行的步骤。

**组合：** 定焦目标 → 编组候选 → 锁定共同目标 → 对齐比较 → 定焦选择者 → 留停。机器记录：[compare-options.json](examples/compare-options.json)。

| 计划时间 | 观众任务与画面 | 主动作 | 保持不变或结束状态 |
|---|---|---|---|
| 0～10 秒 | 知道共同目标是准备投稿 | 定焦目标 | 环境与目标位置稳定 |
| 10～25 秒 | 看见三个平行候选，均不自动获胜 | 编组、对齐比较 | 共同尺度与列顺序 |
| 25～42 秒 | 按“先改变什么、先确认什么、主要不确定性”比较 | 对齐比较 | 相同项固定，只解释当前差异 |
| 42～58 秒 | 知道这个情境中由人选择 | 定焦选择者 | 三个候选继续可见 |
| 58～66 秒 | 回到差异总览，澄清“选择而非流程” | 锁定参照 | 不给选项添加先后箭头 |
| 66～72 秒 | 留出检查关系的时间 | 留停成像 | 目标、候选与选择者同屏 |

感受目标是从杂乱到清楚、从容；只在选择位置做轻微强调。没有数据支持时，不画方案优劣分数，不写“先脑暴一定最好”。旁白关于风险的补充属于新增解释，制作前要核实。

**检查任务：** 三个对象是什么关系？最后谁作选择？换一篇论文，应该先问哪些条件？另问观众最记得哪个画面、有没有觉得表格太重。

### 二、Current 与历史快照 · 48 秒

**场景：** 解释示例项目中一份持续编辑的 Current 与两份历史快照。这里采用复制式归档，只是一个具体约定。

**组合：** 编组项目 → 锁定项目参照 → 保持 Current 身份 → 展示派生副本 → 对应版本标签 → 留停。“复制出副本”是场景动作，不需要新增为第十一项原语。机器记录：[current-archive.json](examples/current-archive.json)。

| 计划时间 | 画面与对象关系 | 主动作 | 不能误画成什么 |
|---|---|---|---|
| 0～8 秒 | 固定项目边界和 Current 位置 | 编组、锁定参照 | 不能让位置不断漂移 |
| 8～18 秒 | Current 内部内容变化，名称与身份不变 | 保持身份 | 不是换了一份不相关文档 |
| 18～28 秒 | 复制出独立 archive v1，Current 继续可见 | 定焦副本、对应 | 不能让 Current 变成 archive 后消失 |
| 28～34 秒 | Current 再修改，v1 不跟随更新 | 保持身份、锁定参照 | 不能暗示快照与工作稿实时同步 |
| 34～40 秒 | 复制出 archive v2，注明第二次快照 | 对应版本 | v1 和 v2 不合并为一个对象 |
| 40～48 秒 | 保留工作稿与两个快照供比较 | 留停成像 | 不切走或继续新增文件 |

感受目标是稳定、清晰的版本感；项目轮廓和背景都可静止。复制过程保留来源关系，但不把“视觉连续”解释成“所有对象身份相同”。真实工程如采用 Git、原地版本或别的约定，应先改语义，再改分镜。

**检查任务：** 哪份继续改、哪份可回看？Current 再更新会不会改写 v1？让观众画出一次新的归档。另问稳定布局是否有帮助、结尾是否停得过长。

### 三、澄清需求、确认方向、形成计划 · 78 秒

**场景：** 本例由 AI 澄清并给候选，人选择方向，然后形成 Plan 并开始 Execute。这是该情境采用的分工，不是所有 Agent 工作流都必须反复请人确认的通用协议。

**组合：** 串联路径 → 定焦当前阶段 → 保持需求身份 → 对齐比较候选 → 定焦人的确认 → 锁定 Plan → 留停。机器记录：[decision-gate.json](examples/decision-gate.json)。

| 计划时间 | 当前重点 | 可制作动作 | 语义约束 |
|---|---|---|---|
| 0～12 秒 | 待澄清的需求 | 一份需求出现在稳定位置 | 不制造已确定方案 |
| 12～30 秒 | 澄清条件 | 条件逐项补齐，原需求仍可定位 | 仍是同一需求，不整屏换对象 |
| 30～46 秒 | AI 提出候选 | 在共同维度并置 | 不自动选中，也不把出现顺序当优先级 |
| 46～56 秒 | 人确认方向 | 一次局部对比与克制的声音落点 | 显式区分建议和选择 |
| 56～67 秒 | 形成 Plan | 将已确认内容写入一个新文档 | Plan 派生于选择，不等同于候选本体 |
| 67～72 秒 | 按 Plan 开始执行 | 从计划指向执行过程，Plan 留在原位 | 开始执行不等于成功完成 |
| 72～78 秒 | 检视交接关系 | 停在确认、计划、执行可见的画面 | 标记“流程示意”，没有成功勾选 |

感受目标是逐渐收敛，唯一较明显的强调留给确认环节。若后续取得真实执行结果，可另接“证据落地”：说明素材来源、版本和实际支持的结论。没有实际材料时不补造成功界面。

**检查任务：** 谁提出候选、谁作选择？Plan 何时形成？画面能证明任务已完成吗？另问推进是否清楚、确认时刻是否有记忆点、是否像过于生硬的流程图。

原报告同时出现源区间 16:45～17:30、78 秒分镜和 66 秒焦点事件。本例只使用 78 秒计划时间；源范围与逐字稿均为空。对接原音轨前必须重新核对素材，不能把它当45秒的等长替换。

## 其他任务的简短配方

| 情境 | 可组合的动作 | 关键限制 |
|---|---|---|
| 认识新概念 | 先认识对象 → 编组 → 定焦属性 → 对应术语 → 留停 | “先认识对象”是制作步骤，不另注册原语 |
| 从整体看局部 | 编组 → 改变尺度／视点 → 锁定定位参照 → 留停 | 不同时更换对象的全部识别线索 |
| 纠正一个观点 | 保留旧说法 → 证据落地 → 对齐比较新旧 → 留停 | 新材料要真实可核；不要无痕换字幕假装没有变化 |
| 演示实际操作 | 示意解释 → 证据落地 → 定焦真实结果 → 对应回模型 | 录屏只证明实际展示的范围，不自动证明完整任务成功 |
| 章节转折 | 小结 → 留停 → 一次有限视点变化 → 新章节 | 章节信息与必要字幕仍可辨 |
| 平静收束 | 回到稳定大构图 → 减少当前信息 → 留住记忆对象 | 不在收束时不断追加新关系 |

## 检查一个配方是否过大

逐项问：需要这个动作解决什么困难？删掉是否损失关系或目标感受？此刻哪个动作主导注意？动作结束后保留什么？哪里有实际证据、哪里只是提案？当一个常用组合稳定解决完整任务时，把它保留为配方，不必包装成新的不可分原语。

实际制作后按[验证方法](VALIDATION.md)记录理解与感受。原版、改版、观众结果都应绑定具体版本；本页计划时间是可修改起点，不是通用停留秒数。
