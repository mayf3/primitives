### 一、 复核 `0.3.1`：为什么这次的处置和 DDP 纠偏比上一轮评审提案更严谨？

#### 1. 对四个反例的工程化裁剪（守住了机器与人工的边界）

* **不把 `lanes` 强加给所有时间图：** 上一轮建议强制要求重叠事件分泳道，而 `0.3.1` 在 `GUIDE.md` 中区分了三种末帧任务——需要认领每路起止时用 `lanes`（并由 `check.py` 查同槽碰撞）或 `table`，只需看并发总峰值时允许用 `aggregate`。这避免了在只问“最多几件事撞在一起”的镜头里画满冗余泳道。
* **区分“推导过程”与“判读末帧”：** 在 `video.align-compare` 中，没有一刀切禁止展示“0.2 + 0.4”的拼接过程，而是规定**推导拍保留来源明细，判读总量的末帧给两边同尺、同轮廓的总数**；且明确指出“字数和图元数只帮助找问题，不能直接判定观众偏好”。
* **厘清倍速播放的物理时钟机制：** 在 `STYLE.md` 中准确指出：只要音频、画面与字幕共用同一媒体时钟，$r$ 倍速并不会导致音画错位，真正改变的是**连续静止可读时间从 $T$ 缩短为 $T/r$**。因此把改写模板移到“话落后的独立整理拍”一次性显现，既消除了同模态双处追字，又给出了精确的倍速验收算式。

#### 2. 对 DDP 梯度累积与通信桶分镜的四处硬核事实纠偏

你在 `#revisions-ddp-buckets` 中指出的四处技术漏洞完全成立，必须作为反面教材记入规范：

1. **默认行为 vs `no_sync()` 上下文：** PyTorch DDP 默认在每次 `backward()` 都触发 ऑल-reduce，只有显式将前 3 个微批的 `forward` 与 `backward` 包在 `model.no_sync()` 中，才会暂缓梯度归约；且暂缓的仅是 DDP 梯度归约，不能把整机网络画成物理断开（如 `SyncBatchNorm` 或 Buffer 广播另有触发机制）。
2. **梯度符号非单调性：** 梯度分量可正可负（如 $+2, -1, +0.5 \rightarrow$ 累计值 $2, 1, 1.5$），上一轮画“数值柱只往上长到 3/4 满”会把**微批次数进度（3/4）**与**梯度数值大小**混为一谈。
3. **Bucket 就绪（Ready）$\neq$ 发起（Launch）：** DDP 各 rank 必须严格按相同的 Bucket 索引顺序发起归约，以防死锁；某桶最后一个参数梯度算完只是标“齐”，轮到该桶索引顺序时才标“发起”。
4. **CPU Launch 条 $\neq$ GPU Kernel 重叠：** 在 Profiler 里，CPU 上的 `aten::backward` 或 `ncclAllReduce` 提交调用与计算相交，不能证明设备端重叠；必须在同一 rank、同一设备的 GPU stream 上指认反向计算 CUDA kernel 与 NCCL collective kernel 的时间交集。

### 二、 全新解释任务测试：合成分镜与删替/展开成本核算

#### 1. 选定本稿未出现过的解释任务

**任务：解释注意力机制中的「Online Softmax（单遍扫描安全归一化）」——为什么在不知道整行最大值 $m_{\text{global}}$ 的情况下，分两块（Block 1、Block 2）先后扫描，靠一个缩放修正因子 $e^{m_1 - m_2}$ 就能得到与传统两遍扫描完全相同的分子累加和？**

* **状态声明：** 以下为**合成分镜设计（`proposed`）**，未绑定源视频、未渲染成片、未做真实观众测试。算例数字（得分 $[1, 3]$ 与 $[2, 4]$）为纸面合成算例，仅用于展示代数恒等变换的视觉对应，不代表硬件 SRAM 切块大小或实测吞吐。
* **观众面临的三个具体困难：**
1. 看到分块算出的局部指数和 $\ell_1 = e^{1-3} + e^{3-3}$，在扫到第 2 块发现更大值 $m_2 = 4$ 时，以为 $\ell_1$ 作废了必须退回第 1 块重算。
2. 看不出“乘上 $e^{3-4}$”在几何或数值上究竟把原来的 $\ell_1$ 变成了什么。
3. 算完修正后的结果，不确定它与“一开始就知道全行最大值是 4”算出来的标准答案是否真的相等。

### 三、 对 `v0.3.1` 仍可成立的 2 个深水区反例（及最小修补建议）

经过三轮迭代，文档在离散对象、拓扑路径、时间泳道和证据边界上已经极为严密。目前仅剩 **2 个可以复现的盲区**，一个出在**机器校验脚本的豁免条件**上，另一个出在**连续标量/高维空间的呈现任务**上：

#### 反例 1：`presentation.event_layout` 设为可选且允许 `"aggregate"`，给了分镜作者在“需要认领单路事件”的剧本里逃避同槽碰撞检查的后门

* **涉及文件与小节：** `GUIDE.md` ·「末帧能回答哪种问题？」、`VALIDATION.md` ·「机器检查能说明什么」及 `domains/video/check.py`。
* **复现条件：**
`0.3.1` 规定：*“声明 `presentation.event_layout = "lanes"` 的排程还须给每项事件标出 `lane_id`，时间重叠的事件占不同泳道……旧记录可省略布局。”*
假设一位分镜作者在写一个新的并发分镜 JSON 时：
* 他在 `semantic.understanding_goal` 或 `validation.viewer.tasks` 里明确要求观众回答：**“请指出窗口 03 和窗口 04 各自的起止时间”**（这是一个个体级认领任务，而非总量峰值任务）；
* 但在 `presentation` 里，他要么**漏写了 `event_layout**`（触发旧记录兼容豁免），要么随手填了 `event_layout: "aggregate"`，然后把两个 `[4, 7)` 的事件叠在同一条轨道上渲染。
* 此时运行 `python3 domains/video/check.py`，**机器检查会 100% 绿灯通过！** 因为校验器只对显式声明了 `event_layout == "lanes"` 的 JSON 开启碰撞检查，而不管 `event_schedule` 里是否已经出现了多个具名独立对象的重叠区间。


* **建议改法：**
收紧 `GUIDE.md` 与 `check.py` 的默认校验逻辑：**只要 `presentation.event_schedule` 中存在两个以上时间区间相交（$\max(s_1, s_2) < \min(e_1, e_2)$）的事件，就要求显式声明 `event_layout`（不再允许对含重叠区间的排程省略该字段）**；且当 `event_layout: "aggregate"` 时，在校验输出或分镜摘录中打印一条明确提醒：*“当前布局仅支持读取并发总量峰值，验收任务不得要求观众从静态图单列恢复各重叠事件的独立起止”*。
* **验收办法：** 构造一个含 `[4, 7)` 双重叠事件但省略 `event_layout` 的测试 JSON，运行 `unittest` 应报错拦截，提示补齐 `"lanes"`、`"table"` 或 `"aggregate"`。

#### 反例 2：当观众的观看困难是「连续量变引起质变（阈值/相变/梯度场）」时，现有的离散图元动作（`group` / `serial-path` / `correspond`）缺乏对“连续域分界线”的归属定义

* **涉及 ID 与小节：** `PRIMITIVES.md` · `video.reference-lock`（第 7 卡）与 `video.group`（第 4 卡）。
* **复现条件：**
现有 11 个入口默认处理的都是**离散实体**（卡片、窗口、节点、端子、代码行）。但在科学、课程与工程解释中，有一类极高频的观看困难是**连续参数空间里的临界边界（Threshold / Phase Boundary）**：
* 例如：在《投机采样》中，草稿温度或接受率 $\alpha$ 连续变化时，什么时候加速比曲线会跌破 $1.0\times$（从“加速区”变成“减速亏损区”）？
* 或者在心理学/社科播客中，解释“耶基斯-多德森定律（Yerkes-Dodson Law）”：唤醒水平（压力）从低到高连续增加时，表现如何从“不足”跨过“最优峰”掉进“焦虑崩溃”？
* 当分镜师在一条连续曲线上画一条水平或垂直的**临界阈值线（如 `盈亏平衡线 1.0x` 或 `过载阈值`）**，把连续空间切分为两个性质相反的区域时，这算 `#4 编组归属（video.group）` 还是 `#7 锁定参照（video.reference-lock）`？
* 如果只按现有 `#7 锁定参照` 画一条基线，观众能看出高了还是低了，但看不出“跨过这条线后系统性质发生了反转（相变/分类改变）”；如果只按现有 `#4 编组归属` 画两个盒子，又丢掉了底层自变量连续滑动的度量关系。


* **已有定义能否处理？**
**完全可以由 `#7 锁定参照` + `#4 编组归属` 协同处理，无需新增第 12 个原语**，但目前两张卡的文字只写了“离散对象集合的容器”和“家具移动/尺寸基线”，导致遇到连续曲线分区时作者不知道该查哪张卡。
* **建议改法（仅需在两张卡各补半句说明）：**
* 在 `#7 锁定参照` 的「最小实现／参数」补入：*“参照也可以是连续坐标中的一条临界阈值线（如盈亏平衡线、安全上限），用于判断变化何时跨过边界。”*
* 在 `#4 编组归属` 的「语义动作」补入：*“除离散对象的容器外，也可在连续曲线或坐标面上用阈值分界线划出不同性质的作用区间（如增益区与亏损区）。”*


* **验收办法：** 给出一条连续变化曲线，拿掉阈值分界线与区间标签后，观众只能说出“先升后降”；补上 `reference-lock`（阈值线）+ `group`（区间命名）后，观众能准确指出“自变量跨过哪个刻度时，系统从状态 A 进入状态 B”。
