# 按观看困难选择视频动作

先写两句话：**“观众看完这段应能解释什么关系？”“这段希望留下什么感受？”** 若关系仍不清楚，先查材料或修讲稿；不要用运动掩盖概念不确定。

## 困难 → 最小动作 → 检查

| 具体困难 | 首选动作 | 先做什么 | 怎样检查 |
|---|---|---|---|
| 不知道当前该看哪儿 | [定焦](PRIMITIVES.md#focus) | 让当前对象显著，其余退为支撑 | 短暂看图后指出主目标 |
| 旁白、标签与图形对不上 | [对应](PRIMITIVES.md#correspond) | 把映射两端临近、标记或同步 | 隐去标签后重新配对 |
| 看过两方案却说不出差异 | [对齐比较](PRIMITIVES.md#align-compare) | 固定共同维度与尺度，逐一显示差异 | 离开画面后复述差别 |
| 分不清并列、包含和作用范围 | [编组归属](PRIMITIVES.md#group) | 先核关系，再选择分组或边界 | 重建归属，解释边界含义 |
| 一串名词被听成同一层次 | [串联路径](PRIMITIVES.md#serial-path) | 每条连接写明先后、因果、输入输出或依赖 | 重排节点并解释箭头 |
| 变完不知道还是不是原来那个 | [保持身份](PRIMITIVES.md#identity-preserve) | 保留识别线索；派生对象另建身份 | 指出谁变化、谁是新对象 |
| 看见变化却不知相对什么变 | [锁定参照](PRIMITIVES.md#reference-lock) | 固定基线、旧状态或位置 | 说明不变项和变化量 |
| 局部看不清或失去整体位置 | [改变尺度／视点](PRIMITIVES.md#scale-viewpoint) | 先标位置，再切入局部，保留定位线索 | 把局部放回整体 |
| 刚形成关系就切走，来不及看 | [留停成像](PRIMITIVES.md#hold) | 暂停新增视觉事件，保留结果 | 不倒退能否重建关键关系 |
| 示意很流畅，却不知现实依据 | [证据落地](PRIMITIVES.md#evidence-ground) | 标明示意与实录，展示可定位的实际材料 | 分辨哪些是解释、哪些是证据 |

## 一次制作的六步

1. **取材料。** 记录目标媒体版本、脚本或逐字稿位置；没有的内容留空。实际观察、报告转述、设计假设分别写。
2. **定关系。** 明确要表达的是差异、包含、时序、因果、来源、作用范围还是同一实体变化。先后不自动等于因果；快照是派生物，不是当前文档变了身份。
3. **选最少动作。** 从上表选一个主操作，需要时补身份、参照或停留。解释不需要动画时可用静态画面。
4. **定关键画面与时序。** 先做起点、变化过程和结束状态的低成本分镜，注明焦点交给谁、什么保持不变、哪里留停。示例见[组合配方](PATTERNS.md)。
5. **再定风格与实现。** 依据[声画分工](STYLE.md)安排海景、人物、字幕、环境声；用项目锁定版本的工具实现，不由组件能力倒推内容关系。
6. **分别检查。** 对照材料查事实与语义；播放成片查字、声与时间；用观众任务检查理解，另问感受。记录实际结果，细节见[验证方法](VALIDATION.md)。

“同一时刻一个主注意动作”是本版的制作启发式，不是禁止同时比较多个对象。一个比较关系可以包含两栏；其余显著运动不应同时争夺目光。若改变视点、字幕弹跳和背景闪光都自称重点，先排出主次。

## 不同时长与观看方式

| 场景 | 优先安排 | 避免机械套用 |
|---|---|---|
| 1～3 分钟解释短片 | 围绕一个核心问题，用少量关系变化推进，结尾保留可重建画面 | 不按“每几秒必须切镜”计工作量 |
| 20～40 分钟对谈 | 人物、章节与环境保持稳定；新概念、分歧、纠正和关键证据时集中制作 | 不给每一句旁白配一个新动作；无意义人物摆动不算解释 |
| 课程与 DIY 教程 | 先认识对象；步骤可暂停核对；实际条件、操作结果与示意分明 | 不用顺滑转场跨过必须看清的端口、动作或结果 |
| 初次接触主题 | 先认少量对象，再讲关系；用具体例子测迁移 | 不把先备知识当所有人已经知道 |
| 主要听音频 | 旁白保留主结论与必要关系，避免只说“你看这里” | 视觉增强不能令音频主线断裂 |
| 手机观看 | 在目标设备和实际播放宽度看字幕、标签、线条；必要时单独排版 | 不把桌面全屏或任意缩放比例当手机验收 |

## 给制作 Agent 的最小交付

一次小修改只需：原材料位置、困难、要保持的关系、选择的原语、预期结束画面、检验问题。要做连续片段时，可复制[比较示例 JSON](examples/compare-options.json)到制作项目，再据实填写以下部分：

| 记录部分 | 保存什么 | 当前合成示例的口径 |
|---|---|---|
| `source` | 材料来源、实际访问情况、源区间、逐字稿锚点、真实证据素材 | `report-only`，未访问媒体；源区间与逐字稿锚点为 `null` |
| `semantic` | 问题、理解与感受目标、对象、带类型的关系、不可损失项 | 合成情境的关系定义，不伪称节目原话 |
| `presentation` | 原语 ID、计划时长、焦点安排、留停与结束状态 | 所有秒数相对新片段起点 |
| `render` | 实现工具、产物位置与实施状态 | `proposed`，`implemented: false`，无产物 |
| `validation` | 事实、可访问性与观众检查，任务和实际记录分开 | 检查待做，结果数组为空，观众 `untested` |

`selected: true` 仅表示选用该设计。检查清单是“要查什么”，检查记录是“实际查到了什么”。填了清单、写了代码、完成渲染、观众理解了，是四件不同的事。

### 两条时间轴

`source.source_range_seconds` 是实际源媒体区间，未经核对不填成已证实值。`presentation.planned_duration_seconds` 是改版片段计划时长；焦点与停留相对该片段从零计时。即使源片段只有 45 秒，重新编排也可能计划 78 秒，但这同时意味着需要调整旁白或剪辑；不是可以直接套在原音轨上的等长替换。

源稿中像 `transcript:ep03:L412-L438` 的示例文字没有对应逐字稿支持，不能复制成真实来源。三层 Prompt 的实际定义未核清时，保留待查问题，不先画成三层包含关系。

## 工具边界

Remotion、SVG、剪辑和录屏是实现选择。记录项目工具版本、帧率、时长、音轨和素材来源；秒数到帧数的转换由渲染层负责。官方文档会变化，必要时按项目版本核对，参考[本轮窄复核清单](sources/references.json)。这里不提供未经实际渲染验证的“可直接生产”组件，也不要求外部项目运行时依赖方法仓库。
