# 按观看困难选择视频动作

先约定受众的先备知识、主要感知通道、设备与播放方式，再写两句话：**“观众看完这段应能解释什么关系？”“这段希望留下什么感受？”** 若关系仍不清楚，先查材料或修讲稿；不要用运动掩盖概念不确定。观看任务也可以是听辨两段录音，不预设所有判断都由眼睛完成。

## 困难 → 最小动作 → 检查

| 具体困难 | 首选动作 | 先做什么 | 怎样检查 |
|---|---|---|---|
| 不知道当前该看哪儿 | [1. 定焦](PRIMITIVES.md#focus) | 让当前对象显著，其余退为支撑 | 短暂看图后指出主目标 |
| 旁白、标签与图形对不上 | [2. 对应](PRIMITIVES.md#correspond) | 把映射两端临近、标记或同步 | 隐去标签后重新配对 |
| 看过两方案却说不出差异 | [3. 对齐比较 · 组合入口](PRIMITIVES.md#align-compare) | 先选能回答问题的共同维度，固定尺度，让同一字段对应，再定焦差异。手机上可在同一位置先后显示 | 换一种排列还能否按共同维度复述差别？ |
| 分不清并列、包含和作用范围 | [4. 编组归属](PRIMITIVES.md#group) | 先核关系，再选具名边界或已声明的共同编码 | 重建归属，解释边界或声音映射的含义 |
| 要先认识整体再拆内部，或讲完子图后接入更大系统 | [12. 封装收拢 · 组合入口](PRIMITIVES.md#chunk) | 先定名称、成员和接口，再按任务展开或收起；首次展示整体不表示内部已讲清 | 能否分清刚知道的外部作用与已解释的内部结构，双向认回同一整体？ |
| 一串名词被听成同一层次 | [5. 串联路径](PRIMITIVES.md#serial-path) | 每条连接或声音接续说明先后、因果、输入输出或依赖 | 重排节点并解释关系，区分播放顺序与源过程顺序 |
| 知道有几项工作，却看不出谁在等、哪几项重叠、谁先赶上谁 | [11. 呈现时间关系](PRIMITIVES.md#temporal-relations)（`video.temporal-relations`） | 给事件共同时间基准，标出起止、重叠或单位时间内的进展 | 指出两件事同时进行的区间，或在哪一段时间的到达量超过了处理量 |
| 变完不知道还是不是原来那个 | [6. 保持身份](PRIMITIVES.md#identity-preserve) | 保留视觉或已建立的声音识别线索；派生对象另建身份 | 指出谁变化、谁是新对象；追认线索不冒充真实身份鉴定 |
| 分不清两件事按什么基准比较，或不知相对什么发生了变化 | [7. 锁定参照](PRIMITIVES.md#reference-lock) | 保持同一尺度、基线或判别条件 | 指出共同基准，再说出它支持的差异判断 |
| 能背规则，却不会判断输入变化后的结果 | [2. 对应](PRIMITIVES.md#correspond)配合[7. 锁定参照](PRIMITIVES.md#reference-lock) | 固定规则、定义域和其他条件，选实例或边界值，演示联动后回到总体关系 | 给一个未演示的输入，让观众预测并说明依据；不从有限例子推出通式 |
| 局部观察难辨，或不知属于哪个整体 | [8. 改变尺度／视点](PRIMITIVES.md#scale-viewpoint) | 先定位再放大、换观察位置；听觉任务说明声源及拾音条件 | 指出新增的局部信息及来处，区分观察条件变化与对象本身变化 |
| 刚形成关系就切走，来不及读或听辨 | [9. 留停成像](PRIMITIVES.md#hold) | 暂缓新增任务，给当前阅读、听完与整合留机会 | 能否定位并重建关键关系；必要回放是否可找到 |
| 示意很流畅，却不知现实依据 | [10. 证据落地](PRIMITIVES.md#evidence-ground) | 标明材料性质，把要核对的主张连到原件中可定位的那一处 | 指出原件哪一处支持哪一项判断，哪些仍是解释 |

<a id="question-anchor"></a>
## 先明确这段为什么值得看，再选择解释动作

面向尚未带着任务进场的观众，在密集解释前交代一个可回答的困惑、现象或选择。问题来自材料与受众需要，可以平实提出，不必制造反常或故意隐瞒已知结论。沿途把刚得到的关系接回该问题，转折处说明已解决哪一部分、还有什么未知。开场承诺与结尾实际回答一致；教程、检索型片段可以直接报任务和结果，无需强行悬疑。

问题锚点是整段的组织安排，调用对应、锁定参照、路径、封装与留停即可，不新增原语。一个熟悉的日常参照也只是帮助理解的中介：先核实目标观众熟悉它，再保留原单位、换算条件与类比失效处。不能把“约等于几圈”继续偷换成“走起来一定很轻松”。

十二个入口用于选择呈现操作，作品级检查另看底线准确、感知通达和片外复述。三方面分别记录，不用原语数量、动画数量或一个总分给作品定级，也不保证覆盖所有受众或获得传播。[作品级检查](VALIDATION.md#work-review)

0.6.1 在作品级检查下细化理解收益、听感、视觉稳定性和跨拍节律，沿用同一套事实与效果边界。局部检查用来定位单个动作的问题，连续观看用来发现累积负担；两者可以来回修订，不必等所有局部“通过”后才看整段。[全片复核](VALIDATION.md#whole-work-review)

<a id="correction"></a>
## 旧假设被修正后，观众应带走什么？

先决定是否需要展示旧假设。它确实是当前解释的障碍时，给出归属和待检验的范围；不为了制造转折虚构“人人都这样想”。可先交代正确结论或待解问题，再按必要程度提及旧说法，避免用无归属的错误大字作开场或封面。

| 材料实际支持的判断 | 可以怎样交代 | 不得偷换成什么 |
|---|---|---|
| 有反例推翻指定全称判断 | 保留旧假设标识，指出反例、断裂的连接和被否定的范围 | 只画红叉、换音乐就宣告证伪，或否定该假设在所有特殊条件下也可能成立 |
| 缺少足够依据 | 标“尚未证实／证据不足”，说明还缺什么 | 已经证明错误 |
| 条件改变或版本过期 | 保留旧条件与新条件的区别，说明何时不再适用 | 原版本在原条件下也必定错误 |
| 编辑放弃一种方案 | 说明选择理由及取舍 | 事实已反驳该方案，或未选方案从来不可用 |

更正时把旧主张与依据连起来，给出可支持的替代解释或明确的未知项，再将旧说法退出当前主张位置。要回顾时持续带着归属、状态和原因；独立切片与总结材料同样检查。保留来源原文与原身份，不在历史记录里把旧说法改写成作者一直主张的新结论。这里的主张状态写入语义说明，不等于原语的 `candidate`、来源核查状态或制作完成状态。

这项安排组合定焦、对应、身份、参照、证据与留停，未新增“证伪原语”。一个反例是否足够、替代解释是否有依据，由内容核验先确定。让观众指出被否定的具体部分、现在可采用什么和仍未知什么；划除、淡出或更正措辞本身不保证之后不再误记。[更正配方](PATTERNS.md#correction) · [更正核验](VALIDATION.md#correction)

<a id="sensory-contract"></a>
## 声音是提示，还是正在被观察的材料？

| 本段声音承担什么 | 优先怎样检查 | 另行交付什么 |
|---|---|---|
| 提示一处可见变化 | 静音检查该变化的定位与归属，再对听提示是否抢话或暗示假结果 | 所承诺的字幕、必要声音说明及视觉状态 |
| 录音、音色、语调或节拍本身就是材料，或用声音编码关系 | 在指定设备与声道条件下听辨，核对来源、播放区间、映射和处理方式；画面辅助找位置，避免干扰 | 按受众与发布要求提供字幕、声音描述、数据或转录等替代访问，说明替代材料能支持哪项判断 |
| 声音与画面共同给出不可缺的一部分 | 连续视听检查，再分别关掉一个通道定位依赖，单通道失败不自动判整个安排失败 | 核对相应无障碍版本是否完整交代必要信息，而非宣称任一通道天然足够 |

静音、只听是有目的的诊断，不是所有作品须通过的同一充分性测试。声音描述能交代“此处金属声变密”，不能据此宣称观众已亲耳比较音色；波形也不自动替代听觉证据。字幕仍保留所需话语、说话者及有意义的声音信息。声音版本的比较需听完对应片段，暂停在一帧不足以核验音质。[听辨配方](PATTERNS.md#audio-evidence) · [感知检查](VALIDATION.md#sensory-review)

<a id="narration-alignment"></a>
## 已有旁白时，先把画面绑到哪句话？

先听选定版本的一段，再排该段的第一个视觉动作。以一句意思的变化切片：同一句里可以先问再答，两人也可能同时开口。记录原声或稿件位置、说话者、原词、这一刻提出的主张，以及屏上引语、概括、预告或示例的归属。源录音的绝对时间与重新剪辑后的入点分别保存。仅拿到转述时，先写待核问题；无声演示从可见动作起排。

| 这一步要决定什么 | 正例和相邻的错误 |
|---|---|
| 屏上说的是否是当前这件事 | “改模板”可配讲者原词或忠实短标签。把“做 20 页”加成当前要求就改变了内容。整理后的完整长模板可在另一个阅读拍出现。 |
| 观众何时应知道一个新概念 | 解谜题时可先问“会出现什么？”；若安排开场预告，就标“稍后对照”并在对应处兑现。把后文答案无标记地当作当场结论，会提前关闭问题。 |
| 报数或换人怎样交接 | 宣布三项时，完整概览应含三项。若只讲第一项，显示“1/3”并追踪后两项在何处交付；只报总数时无需虚构尚未介绍的标题。换人反驳时标清留在屏上的是前一位的观点。 |
| 卡片中放大的小字从哪里来 | 给真实引用留来源。确需教学类比时标明“类比”及其解释的关系，再带观众回到主例。拍到聊天窗、便签或文章时，同样核对里面的文字。 |

先有脚本的合成演练可以据拟稿排以上关系，待音轨确定再复核。一个视听锚点的判据，是观众能否在约定的视听或替代版本中辨认当前谁在对什么提出何种主张。语调参与反讽或限制含义时，还须对听完整语境，不从同一句转录自动推出同一立场。每三秒摘一个同词、只凭标签相同，均不能完成这项判断。[字幕与声画分工](STYLE.md#caption-overlap)

<a id="audiovisual-design"></a>
## 重点段落怎样一起安排声音与画面

0.4.3 增补。选一段需要观众判断变化、找差异或读证据的内容，先写出以下安排，再决定是否推镜、形变或加声音。可以把“建立预期 → 观察变化 → 检验解释”作为组织顺序。材料只有问题、尚无解法时，结束画面如实保留未解问题。概念综述或证据已经很直观的片段，也可直接给结论与依据。[重点片段配方](PODCAST-PATTERNS.md#semantic-beat)

| 分镜要回答的问题 | 交接的最少内容 |
|---|---|
| 观众起初知道什么、正在等什么？ | 当前已建立的对象、待判断关系，以及原声里提出问题的位置。 |
| 变化发生前可以先看见什么？ | 可预备的已知对象或中性结构，及首个可理解内容的出现时刻。提前公开答案时单列预告。 |
| 哪句话或可见动作带来新信息？ | 语义触发点、发生变化的对象和关系。重音检测可以提出定位建议，仍对听原句。 |
| 哪些东西需要持续认回？ | 对象名称、原件位置或共同参照。分别说明同一实体变化、新副本、新证据与换用隐喻。 |
| 观众怎样检验、哪里有时间完成？ | 结束画面的核对任务、清晰可读区间，及同期旁白、字幕、音乐和音效是否争夺注意。 |

中性预备与答案揭示分别计时。容器提前时仍须满足首个有意义内容的入场要求。先演机制后命名，可先展示当前话语已描述的操作，在命名句出现时再加术语。若原声仍在讨论困难，画面就已经演出解决结果，即使没有文字也应按预告处理。现有 `quote`／`paraphrase` 的文字时序约束继续适用，提前亮出的主张用 `preview` 并给观众可辨的提示。无字图形的提前揭示由样片审阅检查。[视觉预备](STYLE.md#visual-preparation)

### 音轨时间不够时怎样处理

先按本次任务约定音轨的可编辑范围。使用已定版音轨时，可减少每拍读量、把独立比较分步展示、延续已知对象或借用自然停顿。若这些安排仍不足以完成观看任务，记录具体缺口和需要的时长，交给音频剪辑环节。

任务已包含音频剪辑时，可在完整语义边界试做停顿或调整片段顺序。附件建议的 0.6～1.2 秒只作为候选试值；先与原长停顿对照，听换气、语气和问答关系，再判断画面是否来得及读。新增的 room tone 取自相容的环境素材并核对接缝，保留原音频与新的编辑版本。单纯增加秒数不保证完成阅读，也可能改变“立即反驳”或迟疑的含义。

音频时长或顺序发生变化后，将源媒体位置映射到新片段时间，重定位受影响的语义触发点、字幕、说话标记、动效、音效与章节。局部插入可按受影响区间平移，重排和删改须逐段核对，不能给全部事件套同一偏移。原有源绝对位置继续用于追溯。实际制作记录中的 `audio_alignment` 应对新版重新对听后再登记 `anchored`；沿用旧版对听结果无法证明新版同步。[样片检查](VALIDATION.md#audiovisual-design)

## 一次制作的六步

1. **取材料。** 记录目标媒体版本、脚本或逐字稿位置；没有的内容留空。实际观察、报告转述、设计假设分别写。补明受众、问题锚点与主要通道，不要求已知主题的观众重新接受一个悬念。
2. **定关系。** 以原声为主的片段先完成上面的语义切片。明确要表达的是差异、包含、时序、因果、来源、作用范围还是同一实体变化。先后不自动等于因果；快照是派生物，不是当前文档变了身份。
3. **选最少动作。** 从上表选一个主操作，需要时补身份、参照或停留。解释不需要动画时可用静态画面。
4. **定关键画面与时序。** 先做起点、变化过程和结束状态的低成本分镜，注明焦点交给谁、什么保持不变、哪里留停。示例见[组合配方](PATTERNS.md)。
5. **再定风格与实现。** 依据[声画分工](STYLE.md)安排海景、人物、字幕、环境声；用项目锁定版本的工具实现，不由组件能力倒推内容关系。
6. **分别检查。** 对照材料查事实与语义；播放成片查字、声与时间；用观众任务检查理解，另问感受。局部检查和整段连续播放交替进行，核对问题回扣、疏密、技术摩擦与所承诺的复述材料。有更正时检查旧结论是否仍被当作当前主张。记录实际结果，细节见[验证方法](VALIDATION.md)。

交给制作方前，另用四问检查关键画面。卡片里需要的是结构词还是具体正文？哪些材料性质需要观众此时知道，屏上准备怎样表述？容器何时出现、首个可理解内容何时可读、运动中会遮到谁？换人或换景别后，原来的识别线索还在哪里？[内容与文案](STYLE.md#content-granularity)、[入场与避让](STYLE.md#container-content)及[换人标识](STYLE.md#speaker-presence)给出制作条件，实际检查按[观看摩擦复核](VALIDATION.md#viewer-friction)记录。

“同一时刻一个主注意动作”是本版的制作启发式，不是禁止同时比较多个对象。一个比较关系可以包含两栏；其余显著运动不应同时争夺目光。若改变视点、字幕弹跳和背景闪光都自称重点，先排出主次。

## 不同时长与观看方式

| 场景 | 优先安排 | 避免机械套用 |
|---|---|---|
| 1～3 分钟解释短片 | 围绕一个核心问题，用少量关系变化推进，结尾保留可重建画面 | 不按“每几秒必须切镜”计工作量 |
| 20～40 分钟对谈 | 人物、章节与环境保持稳定；新概念、分歧、纠正和关键证据时集中制作 | 不给每一句旁白配一个新动作；无意义人物摆动不算解释 |
| 课程与 DIY 教程 | 先认识对象；步骤可暂停核对；实际条件、操作结果与示意分明 | 不用顺滑转场跨过必须看清的端口、动作或结果 |
| 初次接触主题 | 先认少量对象，再讲关系；用具体例子测迁移 | 不把先备知识当所有人已经知道 |
| 主要听音频 | 旁白保留主结论与必要关系，避免只说“你看这里” | 视觉增强不能令音频主线断裂 |
| 手机观看 | 在目标设备和实际播放宽度看字幕、标签、线条；必要时单独排版 | 不把桌面全屏或任意缩放比例当手机验收 |

<a id="model-building"></a>
### 怎样建立整体、展开局部并接到下一层

按任务选择三种接续方式。可先给具名整体的外部作用，再[拆开内部](PATTERNS.md#top-down-chunk)；也可在局部讲清后，用[封装收拢](PATTERNS.md#chunk)把它作为具名整体接入新关系。无论从哪一端开始，名称、成员、接口与例外都需有依据，首次看到短名不等于已理解内部。抽象规则还难以使用时，选有解释价值的具体状态演一遍，再返回规则与取值范围。[具体与总体往返](PATTERNS.md#rule-instance)

若要检查既有理解，可在揭示结果前请观众预测，或给作者明确提出的候选预期。先写下预测及其条件，再比较实测或模型结果，并解释命中或偏离的原因。固定预期的来源和比较口径，不能在看到结果后补造观众的“常识”。这种安排可与封装、联动组合，也可用于静态图。[预期基线](PATTERNS.md#prediction-baseline)

封装的名称和可省略内容由编辑先确定。几项对象能否被当作同一组使用，取决于观众已经建立的关系；同屏块数不能证明其理解程度。让观众指出封装内部、解释一次具体代入或预测新条件下的变化，再决定继续收拢还是返回展开。

<a id="viewing-contract"></a>
### 哪些内容要连续看懂，哪些可以暂停核验

先约定目标速度、设备和可用的回看方式，再写下每段必须当场完成的判断。主张、材料性质、关键判别点、影响结论的范围与不确定性属于连续观看任务。较长引文、页码细目和补充推导可以安排暂停阅读，仍须在实际画面中清晰，并有可找到的回看位置或材料入口。

例如要表达“本页这处单击选中整图”，连续播放应给出该操作、选区和“本页／此处”的范围。完整对象树可供进一步核验；若声称整页不存在可编辑文字，这一更强结论所依赖的检查范围就须在连续层交代。不能把“只检查了一处”的事实藏在暂停小字里。

既有 `presentation.holds[].visible` 只登记实际保留的可见对象和时段，明确要求同时对读的文字继续使用 `required_text_events`。它不记录声样是否听完；纯听觉留停须在制作项目另记声样、播放／回放区间和听辨任务，当前 JSON 校验尚未覆盖，不能为通过检查把声音伪填为可见图元。暂停资料的原文位置与核验问题可写入制作说明及 `validation` 检查清单，不能伪填已完成观察。即使不要求每条出处在连续播放中读完，观众仍应能在暂停后辨字、定位并取回上下文。声音证据还需可定位重放。平台不支持暂停或细节在交付尺寸不可读时，改排清晰视图或可用的独立材料，再核交付条件。[两种观看方式的检查](VALIDATION.md#viewing-contract)

<a id="review-beats"></a>
## 长对谈怎样找到该动的一拍

回看时先听一句，再暂停在它说完的那一帧。比如听到“文件可以打开，但字改不了”，此时能否从页面上指出**鼠标选中了整幅图**？只有锁头或一行标题时，缺的是一次可观察的操作结果。这一帧能支持“这次单击选中了整图”。如果旁白想说整页没有可编辑文本，再查本页完整对象树、编组与编辑权限，或收窄台词和卡片上的断言。Vox 的 Sam Ellis 在采访中举的是用港口、铁路数据做图的实例；3Blue1Brown 的 Grant Sanderson 建议让画面的每个运动具有可指认的用途。[Sam Ellis 访谈](https://www.storybench.org/how-vox-explained-chinas-belt-and-road-initiative/) · [Sanderson 制作问答](https://www.3blue1brown.com/about/)

| 审片时回看哪一层 | 值得更新的时刻 | 具体处理和结束条件 |
|---|---|---|
| 卡片内的变化 | 说到对象、结果或转折词 | 让相关文字或选区在原位显现。如需解释第二项，第一项退为参照。直到结果能被指出，再转移焦点。 |
| 同一话题的构图 | 任务从读一句变成比较两件事，或从感受拥挤转向理解原因 | 从单窗拉开成四窗；需要读内容时停滚并推近一窗。观众能找回它在总览中的位置。 |
| 全段的问题 | 前一问题有了回答，下一章换了问题、场景或说话人 | 可用章节扉页、远近景变化，或由海边回到笔记本；保留刚得出的结论作下一章的起点。 |

对 20～40 分钟知识对谈，可以把反馈中的 **3～5 秒、10～18 秒、60～120 秒**作为首轮扫片的三个观察窗口。逐段写下观众此时在读、辨认、比较还是等待。若旁白已推进，画面却连续几句只有同一标题，应在**第一个失配的词句**补入材料；若观众在读完整模板，则给足静止时间。一次环境缓推可服务沉静感，帧差不能计作信息更新。本轮查到的资料没有给出统一剪切周期，也没有给出“静止八秒造成九成流失”的统计依据。[核对范围](sources/README.md#podcast-review)

以反馈标出的 **21:00～21:35「以后，AI 会更懂我吗？」** 为例。先把问句留在海边远景，让观众听完；在回复给出第一个具体条件时，把那项条件写到桌面的便签上；若后面出现不同看法，再并置两人的原意。若回听发现这一段实际是停顿或情绪收束，就保留远景。**09:35～10:08** 也可用同一方法抽查，先找语义转折再定镜头。这两处时间均来自审片意见，须以目标音轨重定位。

### 从观看任务决定是否动镜头

先记触发的原话或操作、镜头里的对象、观众将看到的差别，以及结果要保留到何时。取消推镜后，如果仍能读出同一个字段、看清同一处结构，就把这次运动记作气氛选择。若从四窗切入一窗才读得到正文，记录切入哪一窗、何时读得清、怎样凭编号找回总览。若从正面换到侧面才看见接点，记录原来的遮挡物和新显出的接点。两个动作都能用静态切镜实现。

缓推、弹簧、错峰和降暗的海风纸卡试值见[风格实现](STYLE.md#ambient-motion)。普通字与大字的对比度口径不同，必要图形还要看相邻色。改变背景或播放尺寸时按[对比度抽查](VALIDATION.md#contrast)重新测。

按具体问题直接取用[微缩 UI](PODCAST-PATTERNS.md#editable-slide)、[可截图的提问模板](PODCAST-PATTERNS.md#takeaway-prompt)、[四窗口过载](PODCAST-PATTERNS.md#text-overload)、[聊天分支](PODCAST-PATTERNS.md#branch-context)、[段落抽骨架与分窗审稿](PODCAST-PATTERNS.md#extract-argument)或[字幕清洗](PODCAST-PATTERNS.md#clean-captions)。说话人换机位时直接查[人物与话轮](PODCAST-PATTERNS.md#speaker-shot)。

## 给制作 Agent 的最小交付

一次小修改只需：原材料位置、困难、要保持的关系、选择的原语、预期结束画面、检验问题。要做连续片段时，可复制[比较示例 JSON](examples/compare-options.json)到制作项目，再据实填写以下部分：

| 记录部分 | 保存什么 | 当前合成示例的口径 |
|---|---|---|
| `source` | 材料来源、实际访问情况、源区间、逐字稿锚点、真实证据素材 | `report-only`，未访问媒体；源区间与逐字稿锚点为 `null` |
| `semantic` | 问题、理解与感受目标、对象、带类型的关系、不可损失项 | 合成情境的关系定义，不伪称节目原话 |
| `presentation` | 原语 ID、计划时长、焦点安排、留停与结束状态 | 所有秒数相对新片段起点 |
| `render` | 实现工具、产物位置与实施状态 | `proposed`，`implemented: false`，无产物 |
| `validation` | 事实、可访问性与观众检查，任务和实际记录分开 | 检查待做，结果数组为空，观众 `untested` |

`selected: true` 仅表示选用该设计。检查清单是“要查什么”，检查记录是“实际查到了什么”。填了清单、写了代码、完成渲染、观众理解了，是四件不同的事。

机器记录中的 `role`、`origin`、`source_status` 和 `META_EXAMPLE_DO_NOT_RENDER` 服务交接与追溯。它们进入渲染前须有明确的观众文案选择。现有 `text_events[].label` 表示观众可见的归属提示，例如“回看刚才的问题”或“示例”，需与事件正文一起审阅。拟真重演、预告及回顾的必要区分仍按各自条件呈现，内部字段不能原样自动拼成卡片副标题。[材料披露](STYLE.md#viewer-copy)

### 素材时间、分镜时间、图内时间和观看时长

`source.source_range_seconds` 是实际源媒体区间，未经核对不填成已证实值。`presentation.planned_duration_seconds` 是改版片段计划时长；焦点与停留相对该片段从零计时。即使源片段只有 45 秒，重新编排也可能计划 78 秒，但这同时意味着需要调整旁白或剪辑；不是可以直接套在原音轨上的等长替换。

源稿中像 `transcript:ep03:L412-L438` 的示例文字没有对应逐字稿支持，不能复制成真实来源。三层 Prompt 的实际定义未核清时，保留待查问题，不先画成三层包含关系。

**同一片段可画多件同时发生的事。** `presentation.event_schedule` 可选，每个 `[start, end)` 区间从计划片段起点计秒，含起点、不含终点，事件之间可以重叠。`presentation.focus_schedule` 则安排观众当前跟随的一个焦点，可以把“四窗同时来稿”作为整体焦点。静态时间图还需标出图内事件的时间单位与刻度，例如用 5 秒画面展示一天的排班。示意事件时长不构成真实系统的耗时数据。例如完整泳道图里画了 10 个示意时间单位，留停 6 个成片秒；2 倍速下，观众连续看见它 3 秒。图内若采用实测毫秒，还须另记对应运行记录。

<a id="event-readout"></a>

**末帧能回答哪种问题？** 对 0.4.0 起有重叠事件的排程，先给 `semantic.event_readout` 指定观看任务，再选 `presentation.event_layout`。认领每项起止用 `individual` 搭配 `lanes` 或 `table`。只读峰值或并发总数可填 `aggregate`，仍可选用能回答该问题的表或泳道。用 `lanes` 时，每项事件写 `lane_id`，相交事件须分槽，端点相接可复用。事件 ID 认领活动，对象 ID 说明活动属于谁，泳道 ID 说明画在哪一行。用 `table` 时逐事件列起止，用 `aggregate` 时只要求总量读数。只在端点交接的区间没有重叠。已标为 0.3.x 且尚未定义新读数任务的并发记录按旧规则读取，命令行会提示迁移。缺少可识别的旧版本时，含重叠事件的排程按当前规则检查。校验器能查布局取值和同槽碰撞，表中文字、轴的单位、画面可读性仍需查末帧。见[并发回复示例](examples/concurrent-replies.json)。

**分拍绘入一张静态时间图。** 成片从第 0 秒画甲站、第 1 秒才画乙站，两站却都在当地时间 10:00–12:00 开放。若图内时钟独立，填写 `presentation.event_axis_unit`（如“当地小时，以当日零时为零点”），在每个事件上同时给出成片 `start/end` 与图内 `axis_start/axis_end`。两站的图内数对均为 `(10,12)`，逐站读图时须占不同泳道。若甲在 8–10 时、乙在 10–12 时开放，即使同时画入也可以共行。图内数值共用同一单位和零点，可以是负数或超过片长。两种时钟一致的旧分镜只用原有字段。

### 把声画安排写进分镜

0.4.0 起，分镜在 `presentation.audio_alignment` 说明音轨与屏上文字的关系。沿用旧格式的记录按原版本读取。剧场入场提示的[完整 JSON](examples/theatre-entry.json)包含一次提问、一次答复、分期说明和编辑举例，所有台词均是为练习拟写的。

| 状态 | 何时选用 | 写什么 |
|---|---|---|
| `not-applicable` | 此片段无须依叙述音轨建立对应，如无旁白的运动示意 | `reason` 说明为何不适用 |
| `pending` | 计划绑定具体原声，但尚未取得或对听 | `reason` 说明待核材料，保留空白 |
| `planned` | 用拟稿编排语义话轮，片段秒还待对听 | `turns` 与 `text_events`；拟稿不填已核原声定位 |
| `anchored` | 在实际制作记录中已听过指定版本，并登记来源核查 | 每个话轮另有源文件／源位置 `locator`，同时保留片段内入出点 |

每个话轮记 `id, start, end, speaker, text, intent`，按一个待绑定的主张取段。若第 5 秒开始回答，第 8 秒才引出关键解法，标 `cue: 8`；当前答案不得在第 5 秒冒充已说出的结论。抢话可在时间上重叠，仍按话轮 ID 确定归属。已剪开或重新排序的原声分段定位，不从计划时长反推源时间。

屏幕文字事件用 `turn` 指向话轮，给入出点、`text` 和 `role`。当前直引用 `quote`，忠实概括用 `paraphrase`，两者写明与话轮一致的 `intent`。先行亮出的内容用 `preview`，先前话轮退为对照用 `recap`，编辑举例用 `example`，分别给观众可见的 `label`。一句从预告转为当前解释时，同一画面可在交接点分为两个事件。报出总数可填话轮的 `total`；画面宣称完整或部分呈现时同时填 `shown` 和 `coverage`（`all` 或 `part`），分期注明当前进度。带旁白的无字画面可显式写 `text_events: []`，仍可定位原声话轮。

回顾或预告若承诺逐字引述，填 `wording: "verbatim"`，并原样摘取该话轮里的连续原文。编辑概括可用 `wording: "paraphrase"`。角色 `role` 管出场时机，引述方式管措辞。画中物件的文字在分镜中注明源物件、版本或画面位置，例如“订票网页上的提示”；它即使与旁白持相反立场，也保留原件依据和归属。

若一个留停要求同时读几条屏幕文字，为这些文字事件分别赋唯一 `id`，将它们列入对应留停的 `required_text_events`。每项都须在整个声明的留停内可见。例如两张卡分别在 [15,19)、[17,20) 秒显示，可把共同阅读段记为 [17,19)。普通留停及无字镜头继续按所需语义对象登记。

举例事件还填 `origin`。方法样本写 `method-example`，实际制作的教学例写 `editorial` 并注明性质。带着方法样本来源复制到 `application` 记录会报错，即使把角色改成回顾也一样。抹去来处再贴文字无法由校验器识别，需拿原件与成片核对。源话有没有被准确转录、数字和标签是否真的出现在画面，同样需要对听和审片。

## 工具边界

Remotion、SVG、剪辑和录屏是实现选择。记录项目工具版本、帧率、时长、音轨和素材来源；秒数到帧数的转换由渲染层负责。官方文档会变化，必要时按项目版本核对，参考[本轮窄复核清单](sources/references.json)。这里不提供未经实际渲染验证的“可直接生产”组件，也不要求外部项目运行时依赖方法仓库。
