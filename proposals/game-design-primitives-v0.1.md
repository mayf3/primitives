# 游戏设计原语候选 v0.1（Game Design Primitives）

**状态：提案 / NOT_TESTED。** 整理日期：2026-11-16。来源：本次《Agent 人生》游戏设计深度研究的13项候选；以下名称、参数和验收阈值属于新设计推断，不是文献作者原话、已实施功能或真人测试结论。

## 领域边界

对象：玩家、可见资源、隐藏质量、事件、选择、历史账本、run与跨run解锁。动作：在约束下观察、试探、承诺、分配和复盘。有效结果：玩家能理解取舍、感到后果可归因、愿意重试；不是“答对AI知识题”。默认有确定性状态引擎、可配置事件池、可复现随机种子与事件日志。真实游戏代码与玩家数据留在游戏项目，不进入方法仓库。

**层级区分：** MDA、Rules of Play 等是理论；“有意义选择”“公平随机”是原则；以下条目是待检验的可执行状态转移候选；多项连接后才是玩法模式。13个不是已证明最小集。名称可能重叠，必须通过删除/合并实验验证。

## 候选卡片

### G01 有代价的捷径 / costly-shortcut

- **解决的问题：**有一种总是正确的最优实践
- **适用条件：**有紧迫目标且未来状态可受影响
- **最小机制：**立刻获得进度，同时创建可追踪的未来负担
- **玩家行动：**快做/稳做
- **状态变化：**进度↑，债务↑
- **反馈方式：**即时成功提示+未来债务兑现
- **预期心理体验：**侥幸与取舍
- **成功案例（类比，非机制等同）：**Papers, Please 的速度/准确性压力
- **失败模式：**债务立刻惩罚或永不兑现
- **可组合对象：**deferred-debt,crisis-amplifier
- **实施建议：**让捷径在某些状态下合理，设置债务到期区间
- **验证方法：**对比不同期限下选择率；若高水平玩家从不选择则重做

### G02 延迟债务 / deferred-debt

- **解决的问题：**选择缺少跨回合影响
- **适用条件：**至少两个时间点且有后续触发器
- **最小机制：**选择写入有来源的债务，未来事件按债务类型兑现
- **玩家行动：**借未来换当下
- **状态变化：**债务账本增加并排定到期
- **反馈方式：**先显示风险线索，兑现时展示来源
- **预期心理体验：**悬念与后悔
- **成功案例（类比，非机制等同）：**Vibe Coder 的 rot/bug 经济
- **失败模式：**全隐藏导致随机惩罚
- **可组合对象：**costly-shortcut,state-gated-echo
- **实施建议：**债务记录cause、severity、due、resolution；至少两种清偿方式
- **验证方法：**玩家能复述早期选择→后果的因果链

### G03 有成本的验证 / costly-verification

- **解决的问题：**验证成为无脑必选
- **适用条件：**不确定输出且存在时间/精力预算
- **最小机制：**消耗资源购买有限证据，不能直接保证成功
- **玩家行动：**跳过/抽查/全面检查
- **状态变化：**时间或精力↓、证据可信度↑
- **反馈方式：**给出证据及其覆盖范围
- **预期心理体验：**掌控感与犹豫
- **成功案例（类比，非机制等同）：**Agents! Please? 的测试环节
- **失败模式：**验证免费或必然给标准答案
- **可组合对象：**legible-risk,probe-before-commit
- **实施建议：**每档验证标记成本、覆盖率与盲区
- **验证方法：**不同截止时间下验证分布变化

### G04 可读风险 / legible-risk

- **解决的问题：**概率失败被感知为设计师陷阱
- **适用条件：**结果有不确定性
- **最小机制：**先呈现风险等级及至少一个可行动线索，后解释命中条件
- **玩家行动：**接受/规避/降低暴露
- **状态变化：**风险暴露变化
- **反馈方式：**前兆、事后风险归因
- **预期心理体验：**紧张而非被欺骗
- **成功案例（类比，非机制等同）：**Sid Meier 对概率感知的设计讨论
- **失败模式：**精确概率变算术题；完全隐藏变彩票
- **可组合对象：**costly-verification,crisis-amplifier
- **实施建议：**用低中高与风险来源展示，严重事故至少两次预警
- **验证方法：**失败公平性均值≥4/5（待验证阈值）

### G05 历史回响 / state-gated-echo

- **解决的问题：**过去选择被剧情遗忘
- **适用条件：**有可复用状态/标签
- **最小机制：**选择写标记，后续事件读取并改变选项/文案/权重
- **玩家行动：**作出关键承诺
- **状态变化：**flags、event eligibility 改变
- **反馈方式：**NPC或系统引用旧选择
- **预期心理体验：**世界记得我
- **成功案例（类比，非机制等同）：**Reigns 状态重编卡池
- **失败模式：**每个选择都生成独立分支树
- **可组合对象：**weighted-storylet-bag,persistent-ledger
- **实施建议：**一个关键标记被至少三处事件消费
- **验证方法：**玩家能指出至少一处历史回应

### G06 耦合资源 / coupled-resources

- **解决的问题：**单一指标最大化
- **适用条件：**存在两个以上相冲突的价值
- **最小机制：**行动同时改变至少两种资源并产生阈值或非线性交互
- **玩家行动：**分配时间、金钱、信任
- **状态变化：**A↑B↓或临界值改变收益
- **反馈方式：**并排显示资源变化与风险
- **预期心理体验：**艰难取舍
- **成功案例（类比，非机制等同）：**Reigns 四权力值；Papers, Please 工资与差错
- **失败模式：**资源太多且互不影响
- **可组合对象：**costly-shortcut,commitment-lock-in
- **实施建议：**核心可见资源控制在3–5种
- **验证方法：**多种策略可存活；单指标不能预测全部胜负

### G07 累积漂移 / accumulating-drift

- **解决的问题：**小错误互不关联
- **适用条件：**重复委托或重复简化流程
- **最小机制：**漂移积累并反向影响后续错误率或处理成本
- **玩家行动：**持续放任/阶段整顿
- **状态变化：**drift↑→未来成本↑
- **反馈方式：**先微小异常，后显著摩擦
- **预期心理体验：**失控与反思
- **成功案例（类比，非机制等同）：**Vibe Coder 的 drift/rot
- **失败模式：**正反馈太强形成不可逆死亡螺旋
- **可组合对象：**deferred-debt,crisis-amplifier
- **实施建议：**至少两种止损路径并设置上限
- **验证方法：**高漂移局面仍有可恢复的运行比例

### G08 承诺与路径锁定 / commitment-lock-in

- **解决的问题：**每回合可无代价切换策略
- **适用条件：**职业/关系/专长有历史
- **最小机制：**重复投资降低本路线成本、提高换路成本
- **玩家行动：**选择长期专长或组织路线
- **状态变化：**specialization↑、switch_cost↑
- **反馈方式：**新机会开放、旧机会变贵
- **预期心理体验：**身份与机会成本
- **成功案例（类比，非机制等同）：**The Life and Suffering of Sir Brante 的路径门槛
- **失败模式：**硬锁死迫使查攻略
- **可组合对象：**state-gated-echo,failure-dividend
- **实施建议：**优先软门槛和替代代价
- **验证方法：**角色扮演选择仍有可行结局

### G09 危机放大器 / crisis-amplifier

- **解决的问题：**资源长期平稳无高潮
- **适用条件：**已有可追踪积累与前兆
- **最小机制：**限时事件放大旧债务、信任或能力的影响
- **玩家行动：**选择救火优先级
- **状态变化：**历史状态转换为集中后果
- **反馈方式：**危机说明触发链
- **预期心理体验：**高潮与顿悟
- **成功案例（类比，非机制等同）：**Papers, Please 随规则增复杂的压力
- **失败模式：**凭空危机、无止损手段
- **可组合对象：**deferred-debt,accumulating-drift
- **实施建议：**危机前给至少两次可读预警
- **验证方法：**玩家能提出改变早期行为的反事实

### G10 持久因果账本 / persistent-ledger

- **解决的问题：**结局无法归因
- **适用条件：**跨事件选择与结算
- **最小机制：**追加记录行动、当时已知证据、未来效果与因果引用
- **玩家行动：**关键决策自动入账
- **状态变化：**ledger append-only
- **反馈方式：**结局展示2–3条可追踪因果链
- **预期心理体验：**自我归因
- **成功案例（类比，非机制等同）：**Agents! Please? 的 moral ledger
- **失败模式：**只列日志却不连因果
- **可组合对象：**state-gated-echo,failure-dividend
- **实施建议：**每项记录cause/effect/knowledge/event_id
- **验证方法：**结局后复述因果链准确率

### G11 试探后承诺 / probe-before-commit

- **解决的问题：**在完全未知情况下被迫猜
- **适用条件：**现实允许低成本局部试验
- **最小机制：**先用一次有限探测改变信息，再进行不可逆决策
- **玩家行动：**抽样/沙盒/缩权后提交
- **状态变化：**证据↑，时间↓
- **反馈方式：**探测显示部分线索与残余不确定
- **预期心理体验：**侦察与主动性
- **成功案例（类比，非机制等同）：**Papers, Please 的检查；Agents! Please? 的运行测试
- **失败模式：**probe总能揭示标准答案
- **可组合对象：**costly-verification,legible-risk
- **实施建议：**探测不消灭不确定性且存在机会成本
- **验证方法：**高风险使用率高于低风险

### G12 状态加权事件袋 / weighted-storylet-bag

- **解决的问题：**分支树成本爆炸且事件随机无因果
- **适用条件：**事件有条件、权重、冷却和状态标签
- **最小机制：**过滤可用事件，再按状态/节奏/多样性权重抽取
- **玩家行动：**通过历史行动间接影响事件池
- **状态变化：**eligible set与weight改变
- **反馈方式：**后续事件回应先前状态
- **预期心理体验：**涌现叙事
- **成功案例（类比，非机制等同）：**Reigns 自适应卡池；Failbetter QBN
- **失败模式：**权重过小像纯随机，过大像固定脚本
- **可组合对象：**state-gated-echo,crisis-amplifier
- **实施建议：**实现requirements、weight_modifier、cooldown、pacing
- **验证方法：**同seed仅改关键flag，事件分布应显著不同

### G13 失败红利 / failure-dividend

- **解决的问题：**失败只浪费时间
- **适用条件：**短局且可重开
- **最小机制：**失败解锁知识、起点或新可能性而非永久数值碾压
- **玩家行动：**复盘并重开
- **状态变化：**meta-options增加
- **反馈方式：**结局指出新认识和新可选路线
- **预期心理体验：**懊恼转好奇
- **成功案例（类比，非机制等同）：**Reigns 王朝延续；Life Restart 天赋继承
- **失败模式：**永久属性加成消灭挑战
- **可组合对象：**persistent-ledger,weighted-storylet-bag
- **实施建议：**优先解锁新选项、事件、信息
- **验证方法：**即时重开率与第二局策略差异

## 三组模式（不是额外原语）

1. **验证困境**：costly-verification + legible-risk + probe-before-commit。玩家用稀缺时间购买有限证据，决定何时足够可信。反例：验证无成本、永远全检。
2. **技术债人生**：costly-shortcut + deferred-debt + accumulating-drift + crisis-amplifier。合理捷径累积成未来危机，危机必须可预警、可止损。反例：一次偷懒即随机破产。
3. **职业回响**：state-gated-echo + commitment-lock-in + persistent-ledger + failure-dividend。人生选择改变未来可行路线，结局复盘促进不同策略重开。反例：硬门槛锁死玩家喜爱的路线。

## 可复用事件接口（建议，不是已运行schema）

```json
{
  "id": "unverified_api",
  "phase": ["junior"],
  "requirements": {"flags_not": ["api_resolved"]},
  "weight": {"base": 1, "modifiers": [{"if": {"Debt": ">3"}, "mul": 1.5}]},
  "risk_signals": ["Agent未提供官方文档链接"],
  "probe": {"cost": {"Time": -1}, "evidence": {"api_exists": "partial"}},
  "choices": [
    {"id": "ship", "effects": {"Time": 2, "Debt": 2}, "ledger": ["trusted_unverified_api"], "followups": [{"event": "api_incident", "after_turns": [2, 5]}]},
    {"id": "check", "effects": {"Time": -2, "Evidence": 2}}
  ],
  "cooldown": 99
}
```

运行时规则：条件过滤→冷却与节奏修正→种子化加权抽取→玩家选择→确定性状态转移→追加账本→排程延迟事件。LLM不得直接裁决数值胜负。需要验证同种子重放、状态边界、事件可达性、债务到期和账本因果一致性。

## 先验证，再注册正式领域

- **最小样板**：15–20分钟、16–20次决策、24个事件、4个可见资源（Time/Cash/Trust/Focus）、少量隐藏质量、2个角色、4次危机候选与6个结局。优先测试 costly-shortcut、deferred-debt、costly-verification、state-gated-echo、coupled-resources、persistent-ledger、weighted-storylet-bag。
- **观测**：≥80%选择能说出取舍；≥70%玩家指出两条选择→后果链；公平性均值≥4/5；≥60%愿立即重开；≥60%在新情境能迁移策略。阈值均为预注册的设计目标，不是已取得结果。
- **可推翻实验**：即时后果 vs 延迟后果；单档验证 vs 分层验证；完全可见质量 vs 风险等级；纯项目结算 vs 职业人生。若复杂版没有增加趣味、归因或重开，删除相应机制。
- **删并检查**：固定同一事件集与成本，逐项去掉原语并用现有原语组合替代；若不损失可观察决策、因果归因与玩家体验且实现更简单，合并或降为模式。不能把删掉的判断暗藏在事件脚本里。
- **状态分离**：资料已检索（2026-11-16）≠定义经评审≠代码已实现≠玩家已验证。当前仅完成研究整理与候选定义。
