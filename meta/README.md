# 原语的原语

**用来设计、审查和修订一套领域原语：先找到任务中不能混淆的区别，再定义可组合的规则，通过反例删减。**

版本 **0.1.0**，编写日期 **2026-11-13**。这是从本仓库人生、写作、设计、视频方法中提炼的新构造方法。它借用公理化方法对定义、前提和推导的要求；作用与最小性仍待实际使用检验。

## 最短使用方法

先用几句话约定：**处理什么任务，怎样算有效，默认已经具备什么能力，哪些成本不能接受。** 不先约定这些，就无法判断某项是否“基础”或“多余”。

随后反复问三个问题：

1. **必须分清什么？** 找出换一种措辞或表现形式后仍会影响结果的对象、关系、条件与身份区别。
2. **这项直接负责什么，怎样与别项接上？** 明确识别条件或输入、变化、产出、不可丢的约束；把其他判断交给明确输入或组合。
3. **什么反例会让我删掉、拆开、合并或降级它？** 用剩余集合重建任务，检查是否偷偷补回了被删除的决定，再用没有参与定义的任务检验。

这三个问题是本版的组织方式，**不是已经证明不可再分的三条公理**。它们可以反过来检查本页，无需建立无限层的“元原语的元原语”。

一次普通写作或页面修改，仍然直接使用相应领域指南。只有在设计方法本身、改变边界或争论“这项是否必要”时，才需要打开本层。

## 它在仓库中的位置

`meta/` 是维护领域方法的基础层，独立于四个领域。它共享构造问题与审查方法；对象、状态、证据门槛和实际效果仍由领域定义。四个领域不必继承它的字段，也不必增加运行依赖。

元层可以引用各域作为分析材料。实际跨域任务的输入输出交接仍写在 [bridges](../bridges/)；ID、版本和来源连接仍由[共享约定](../shared/CONTRACT.md)管理。给某一组合一个方便的名字，不等于把它证明成新的基础原语。

```bash
python3 tools/primitives.py list --scope meta
python3 tools/primitives.py find '最小性' --scope meta
python3 tools/primitives.py show meta.structure
python3 tools/primitives.py show meta.contract
python3 tools/primitives.py show meta.template
```

## 当前状态与下一次修订

本版已经完成四域工作定义的对照、合成案例推导和独立 Agent 审阅。这些工作只能提供定义与边界的理由，不能证明真人更容易使用，也不能证明候选集合最少或完备。案例均注明是继承的合成材料还是本次新构造；没有引入真实个人记录。

接下来最有价值的验证，是让另一位维护者拿一个没有参与本文设计的任务，独立写出候选与组合，再观察：是否仍能说清责任，是否隐藏了额外判断，以及压缩后实际调用是否更困难。结果可以是保留、改写、降为组合，或承认当前框架没有覆盖。

升级本层时记录新反例和修改理由。四域的内容、ID 和版本只有在各自完成评审后才改变；元层发布本身不触发全面改写。
