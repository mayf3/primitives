# 从表面问题到领域原语：四个推导例

这些例子说明怎样应用[完整框架](FRAMEWORK.md)，不是四域最小性证明。写作与人生部分改编自仓库已有的合成教学材料；交互对照和视频删并检查是本次新构造。没有实际用户效果数据，也没有据此修改四域的候选定义。

每例都要看清：任务允许什么，哪种混淆影响结果，由谁承担改变，以及什么反例会限制这项方法。

<a id="writing"></a>
## 一、写作：“加强衔接”可能需要修复内容关系

### 固定输入与表面问题

任务是依据已有活动材料写一段说明，允许提出编辑解释或后续观察建议，保留参与者原话，不把个别结果写成普遍有效。

既有[合成材料](../domains/writing/examples/action-and-trace.md)只说明：组织者先介绍规则十五分钟，部分参与者没有发言；随后缩短介绍，请参与者选一句话谈谈；一人表示下次想带朋友来。没有调整动机、其他人的完整反馈或下一场观察。

一个看似衔接更顺的候选是：

> 缩短介绍让大家更愿意参加，只要继续这样做，下次也会成功。

### 辨认底层结构

| 候选做了什么 | 材料实际上提供了什么 | 必须保留的区别 |
|---|---|---|
| 用“让”说明效果 | 调整之后出现一条反馈 | 先后关系与已获支持的因果关系 |
| 用“大家”概括反应 | 一位参与者的一句表达 | 一个来源与全体范围 |
| 保证“下次也会成功” | 没有下一场记录 | 已有观察与未来推测 |

只把“让”改成“促进”，或者加一个更自然的转折，不能修复这些差异。所需的局部规则是：**检查材料与主张之间的关系，撤回没有依据的升级，让合法的新解释保有自己的归属。**

这对应现有的[接关系](../domains/writing/ACTIONS.md#connect-relations)，不是本次新增一项“高级衔接”。

### 构造一个符合约定的产出

> 活动结束后，一位参与者说：“下次我想带朋友一起来。”这条反馈来自一个人。其他人怎样看这次调整，换一场是否还会这样，现在的记录都回答不了。

前两句分别呈现材料和范围；最后一句是编辑依据材料作出的解释。新解释可以进入文章，但不能被倒填成参与者原话。

这个推导只说明该候选遵守了此例的材料边界。它没有证明这是最好读的写法。作者仍可以在相同约束下调整切口、顺序、篇幅和声音。

### 原语怎样组合，而不是挤进“润色”

先用“接关系”得到关系与范围可核对的候选；再用[调声音](../domains/writing/ACTIONS.md#tune-voice)匹配作者和媒介；最后[回查与停笔](../domains/writing/ACTIONS.md#review-and-stop)，检查新改写有没有重新升级因果或扩大范围。

如果口播版增加了现场内心活动，那就改变了材料内容，必须另有依据或改为允许虚构的任务；不能仅标成“声音调整”。

### 可以被什么反例限制

一句话可以声音自然却缺乏依据，也可以关系正确却不适合口播。这能区分两种责任，不能证明它们在任何方法集合中都不可合并。

若当前任务是自由虚构小说，缺少现实记录并不自动禁止增加人物动机。要先重写任务约定，再检查人物设定、叙事目标和表达关系。不能把本例的材料规则推广为所有写作规则。

**最小性启示：** 少列几种连接词没有减少内容判断；把所有判断叫“润色”也没有减少工作。底层规则应保留对关系的决定能力，语法手段由具体稿件选择。详见[追溯与修订](../domains/writing/TRACE_AND_REVISION.md)。

## 二、人生：“先把工具配齐”隐藏着一个必要条件判断

### 固定输入

沿用[人生合成例](../domains/life/examples/synthetic-review.md)。虚构人物认为：不把所有工具配齐，就不具备让别人阅读草稿的条件。随后本人明确决定用现有工具交付一页草稿；后续记录同时说明部分计划工具仍未配好，两名自愿试读者已经收到稿件。

这些是教学设定，不是用户的人生记录，也不是实际实验。

### 从现象抽出可以检验的关系

设 T 表示“所有计划工具已经配齐”，R 表示“草稿已能交给别人阅读”。原判断把 T 当作 R 的必要条件，即：

```text
原判断：R → T
例内观察：R 且非 T
可得结论：该必要条件判断在这个例内被反驳
```

推导依赖两个观察同时成立。如果只知道“用了已有工具”，却不知道是否早已配齐，就还没有这个反例。两人收到了稿件，也不能推出稿件好读或工具都没有用。

### 为什么不能压成一条“做事记录”

| 需要分清的内容 | 不分清会发生什么 |
|---|---|
| 原始自述与待检验判断 | 把“我认为必须如此”直接当作事实 |
| 本人承诺与 Agent 建议 | 把候选行动写成本人已经决定 |
| 行动完成与证据作用 | 从交付 `done` 自动推出旧判断 `SUPPORTED` |
| 观察与它反驳的范围 | 从某个必要条件不成立推出“所有工具都没用” |

因此，人生领域保留 [Claim](../domains/life/CONCEPTS.md#claim)、[Decision](../domains/life/CONCEPTS.md#decision)、[Activity](../domains/life/CONCEPTS.md#activity) 和 [Evidence 关系](../domains/life/CONCEPTS.md#evidence)等不同角色，有明确的判断用途。这里能提出把例内 Claim 从 `INCONCLUSIVE` 调整为 `CONTRADICTED`；没有实际写入记录。

### 怎样形成可复用方法

从叙述中识别必要条件判断，找出能区分其成立与不成立的观察，安排取得观察的行动，再按观察覆盖的范围更新判断。这是可调用的组合思路；不需要为“换工具”“学完课程才开始”“换设备才交付”逐个新增基础对象。

现有 [State](../domains/life/CONCEPTS.md#state)可以由已有记录形成当前快照，仍有一等使用价值。不能因它有推导来源就机械删除；也不能因保留了它就宣称它不可由其他内容构造。

**最小性启示：** 要保留的是必要的判断区别；至于用几种记录承载、哪些形成派生视图，涉及领域规则和使用成本。此例没有证明当前人生模型是唯一或最小表示。

## 三、交互：“按钮清楚”与“下一步合适”是两个问题

**本次合成设定，原型尚未制作、未进行真人测试。** 一位读者刚读完 Agent 简介，当前目标是用自己的材料做一个 PPT 提纲。比较以下四个方案，保持当前位置、基础解释和必要条件相同。

| 方案 | 按钮文字 | 目的地 |
|---|---|---|
| A1 | 继续 | 再读一份重复的概念说明 |
| A2 | 阅读另一份 Agent 概念说明 | 同 A1 |
| B1 | 继续 | 一个当前可用的提纲任务 |
| B2 | 用你的材料制作 PPT 提纲 | 同 B1 |

### 辨认结构

A2 的文案可以准确预告目的地，目的地却未必推进这个提纲任务。B1 提供了一个适合的后继，点击前线索仍然含混。这个设定区分了：

- [预告入口结果](../domains/design/PRIMITIVES.md#entry-outcome)：如何准确表达一个已经存在的入口。
- [接通下一步](../domains/design/PRIMITIVES.md#next-step)：怎样根据目标、已有产出和条件，选择并接通一个后继。

这只是构造出两项职责不能一对一替代的情形；用户是否真的预测准确或做出提纲，还需要实际观察。

### 把组合展开到可以检查

| 步骤 | 必要输入 | 直接产出 | 不能偷偷附带的结论 |
|---|---|---|---|
| 选择后继 | 读者当前目标、已有产出、已知条件、核对过的候选任务 | 被选后继及选择理由；无合适选项时可结束 | 有按钮就代表学习已发生 |
| 预告入口 | 被选后继、真实结果类型、必要的投入说明 | 可核对的按钮或链接表达 | 写得准确就意味着选得合适 |
| 呈现执行结果 | 提纲任务实际返回的结果或错误 | 让用户能辨认当前状态、结果或错误及其影响 | 展示“完成”就代表内容质量合格 |

这是“选择—表达—执行后呈现”的任务分工，第三步不能被前两步凭空产生。需要怎样测评提纲，仍由具体任务另行定义。[反馈呈现边界](../domains/design/PRIMITIVES.md#visible-change)

若任务还需保留有效输入并提供可继续执行的恢复动作，再显式组合[保留恢复路径](../domains/design/PRIMITIVES.md#recovery-path)。准确显示错误，并不自动提供恢复能力。

### 真正的删除重建怎么做

暂时从候选集中移除 `design.next-step`，只允许调用剩余动作及已经声明的默认能力，重建 B2。记录谁选择了提纲任务：

- 若剩余规则及预先声明的默认能力能够完整构造后继选择，且未补入等价的新决定，则可以把这套构造明确写成模式，继续比较调用成本。
- 若只是说“入口文案里自然就知道该推荐什么”，后继选择被藏了起来，尚未完成删除。

把一个新的后继选择规则移入模式，是责任迁移，仍然可以有组织上的价值；它没有消除这项判断。迁移责任与从剩余基底推导出来，应分别报告，不能都算作基底减少。

此过程要与当前保留方案比较调用成本和遗漏情况。本文尚未执行该比较，不改变设计 0.2.0 的[暂保留裁决](../domains/design/REVISIONS.md#next-step-decision)。

### 一个更深的反例

“每次点击必须产生新知识”会误伤返回修正输入、撤销错误、重试和主动结束。这些行为可能没有新知识，但能恢复或推进任务。评价后继应回到当前目标、结果与可执行条件；页面换了、字数增加了，并不足以说明发生了进展。

## 四、视频：画面连续，不等于对象身份正确

### 固定关系与错误表现

依据现有[Current 与历史快照合成方案](../domains/video/examples/current-archive.json)，要解释的关系是：Current 继续存在并接受后续编辑；archive v1 是从某一时刻内容派生出的另一个对象；Current 后来的修改不自动改写旧快照。

可以用三个逻辑时刻表达，表中不是源媒体时间码：

| 逻辑时刻 | Current | archive v1 |
|---|---|---|
| 归档前 | 当前内容为 v1 | 尚未创建 |
| 创建快照后 | 同一工作对象，内容仍为 v1 | 新对象，保存此时内容 |
| 继续编辑后 | 同一工作对象，内容改为 v2 | 仍保留此前内容 |

如果动画把 Current 直接变形成 archive，随后 Current 消失，画面可以很顺，但会错误表示“原对象变成历史对象”。

### 从关系推出表现约束

先区分**同一对象的状态改变**和**产生另一个对象**，再要求实现保留两个身份与派生关系。这里调用[保持身份](../domains/video/PRIMITIVES.md#identity-preserve)，结合[对应](../domains/video/PRIMITIVES.md#correspond)或其他必要呈现动作。

静态两份文档、剪辑或复制动画都可以候选，只要能表达同样的关系。不同实现的阅读时间、节奏和感受可能不同，不能由语义正确直接推出最佳表现。

这个例子的底层是身份、派生与改变范围。“少用转场”或“统一动画风格”都不能单独解决关系表达错误。

### “对齐比较”能不能降为配方

另取一项当前明确待审的候选：[对齐比较](../domains/video/PRIMITIVES.md#align-compare)。尝试用“锁定参照 + 对应 + 定焦，必要时留停”替代。

先固定一种输入：目标、共同维度、相同单位和比较条件都已经给定。逐项说明这些动作的产出；若确能完整覆盖所需呈现，它可以在这个输入范围内成为一个配方候选。

再换一种输入：方案甲只给月费用，方案乙只给单次费用，使用次数未知；或一个只谈速度，另一个只谈隐私。此时要追问：

- 谁判断目前能否比较？
- 谁选共同维度，处理单位和条件？
- 谁保留未知，而不补造数据？

这些工作若没有归属，就没有完成分解。可以把输入范围收窄到“比较结构已由上游给定”，并明确上游责任；也可以保留较宽的候选，再说明其包含的呈现组合。它们是不同的建模选择，要比较总成本和使用错误。

**当前结论：** 这是可执行的审查方案，尚未实施对照或取得观众数据。元层不替视频域裁定原有十项应减为多少项。

<a id="review-decisions"></a>
## 五、把四例用于维护，但不要把它们当成证明

| 发现 | 本版采取的处置 | 仍待什么材料 |
|---|---|---|
| 同一表面形式可以隐藏不同关系 | 定义先写必要区别，再列实现 | 新任务中这种区别是否帮助选用 |
| 派生视图和快捷组合有实际用途 | 允许保留入口，分别说明基础与组合身份 | 调用、维护和出错成本 |
| 两项职责可分，不等于集合不可约 | 删除时使用全部剩余项重建 | 明确任务下的替代方案与对照 |
| 输入准备可以隐藏被删掉的工作 | 默认能力与上游判断写入边界 | 上游是否真正提供输入、成本是否转移 |
| 形式正确、结构清楚与人实际理解不同 | 分开检查推导、实施和效果 | 实际使用者在指定任务中的观察 |

这些案例已经参与本文构造，下一轮不能再称为未见案例。若要评审新的领域集合，应冻结候选定义，让另一位维护者选择未参与构造的任务，按[轻量卡](TEMPLATE.md)记录失败与修订。检查不通过时可以收窄模型，不必总是新增原语。
