# 从学习目标到可用的学习体验

**学习域决定要帮助人形成什么能力、怎样取得相关表现；设计域决定这些信息和动作怎样被看见、理解和使用。** 两者需要交接，不能互相替代。

组合版本：学习 `0.1.0`、设计 `0.2.0`。这是实施提案与合成说明，未运行真人测试。[机器记录](learning-to-experience.json)锁定方法版本；[Remotion 首条样板](remotion-learning-pilot.md)给出已核对源码基础上的有限实施任务。

## 交接内容

| 阶段 | 责任 | 交给下一步什么 |
|---|---|---|
| 学习约定 | 学习：受众、目标、先修、允许工具、任务与判据 | 哪些关系必须先理解、要产生什么回应、帮助条件是什么 |
| 页面入口 | 设计：页面承诺、入口结果、先修与阅读关系 | 读者看得见的用途、必要解释、下一步和可达任务 |
| 尝试与反馈 | 学习：示范、目标表现、解释及对照；设计：准确显示变化并保留恢复 | 原回应、所用帮助、差异和可继续的动作 |
| 变式与观察 | 学习：按需调整支持、情境或时间 | 绑定条件的表现记录；仍未知的部分 |

两个域的直接入口分别是[学习指南](../domains/learning/GUIDE.md)和[设计指南](../domains/design/GUIDE.md)。不用要求设计者阅读所有论文，也不让最终学习者看到原语 ID 或实施状态字段。

## 三个不能互换的事实

1. 页面有“Remotion 是什么”，是内容存在；新手能用自己的话说明用途与机制，是学习者表现。
2. 链接和键盘可以到达练习，是实施可达；新手知道该点它且预期正确，是人的发现与判断。
3. 动画运行、工程导出，是指定产物成立；学习者能解释参数、在变式中作决定，还需相应任务证据。

保留来源、实施、用户观察的独立记录，字段相似不自动继承状态。合成演练可以帮助发现缺口，不能填充真实用户数据。

## 为什么这次不要求三个网站都变成课程

- **Learn** 明确承诺学习能力，需要接通概念、过程、尝试与反馈。当前先做 Remotion 一条路径。
- **Map** 可以以找解释、选节目、知道下一步为终点。需要帮助理解关系时可调用学习域，但没有练习并不自动是缺陷。
- **DIY** 可依据任务选择过程示范与条件判断；作者做过、数字模拟成立、读者个人完成和实物验证继续分别记录。此处只说明职责，不新增制作操作或放宽项目安全门槛。

三站是已知应用场景，本说明不是未见案例验证。本轮未重测 Map 和 DIY，也未发布三站改动。

## 可用的修改顺序

先定一条样板的学习约定；核对当前真实源与线上路径；补入口与必要关系；复用现有示范和练习；修正同一路径的内容与状态矛盾；在已教范围内增加一题变式。完成技术验收后，再做真实学习者观察。

已有风格系统继续服务阅读。只有信息层级、对应关系或可操作性存在具体问题时才调整视觉；本轮没有依据先做全面换肤、账户系统、题库或全站进度产品。
