# 一个问题怎样经过人生、写作与设计

**这是合成的工作示例，没有真实用户测试结果，没有写入用户的人生记录，也没有修改线上网站。**

情境：准备一个播客导览，希望第一次来的读者能判断某期节目是否适合自己，并知道下一步怎么继续。任务可以从写作或设计开始；只有涉及真实取舍与判断时才调用人生方法。

## 1. 人生方法：明确这次要检验什么

使用 [Claim](../domains/life/CONCEPTS.md#claim) 区分判断与事实：

> 待检验判断：在入口里说清节目解决的问题，可能帮助第一次来的读者选对一期节目。

这句话是合成假设，没有用户证据。项目任务不会因此升级为人生 Goal。若它确实服务某个已存在的长期目标，引用那个 Goal 的原记录；不要另造一个“完成导览”的人生终态。

使用 [Activity](../domains/life/CONCEPTS.md#activity) 描述一次行动：做一份可点的入口文案候选，随后观察读者点击前的预测。期望产生的是预测与实际去向的对照记录，而不是“做了很多设计工作”。

这一阶段输出**问题、假设、约束、希望得到的观察**，不自动产生本人已确认的 Decision。

## 2. 写作方法：把材料组织成读者能用的说明

合成材料包只提供两条信息：

- 示例节目 A 解释 Agent 的基本含义，并给两个任务例子。
- 站内摘要可以先读；完整音频在外部播放器。

使用[选切口](../domains/writing/ACTIONS.md#choose-angle)与[接关系](../domains/writing/ACTIONS.md#connect-relations)，写出候选：

> 想知道 Agent 除了聊天还能做什么？先读这期的概念和两个任务例子，再决定要不要听完整节目。

后台保留“哪条材料支持哪句说明”。“这一定会让新手理解 Agent”没有来源，不能补进文案。作者是否采用、页面是否实现、读者是否理解，继续分别记录。

这一阶段交给设计的是**可用文案、材料边界、目的地类型**，不是一张全部统一成 Claim 的文章图。

## 3. 设计方法：让点击结果与后继动作可预测

使用[预告入口结果](../domains/design/PRIMITIVES.md#entry-outcome)：

- 站内入口：“先读概念和两个例子”。
- 音频入口：“到外部播放器听完整节目”。

时长、是否新窗口、是否需要登录等，只在实际核对后写入。不要为了文案完整而填一个看似合理的值。

再使用[接通下一步](../domains/design/PRIMITIVES.md#next-step)：在摘要结束后，提供与当前理解相衔接的工具选择入口，同时保留结束、返回和自由浏览。

这是提案。设计记录分别写来源核对状态、实施状态和用户验证状态，不能用“文案已写好”替代“页面已部署”。

## 4. 得到真实观察后，再决定它支持什么

计划观察：在点击前请读者说出两个入口分别会打开什么；完成后请其说明这页给了什么、如果继续会做什么。实际观察还没有发生，记录为空。

将来有结果时，原样保存参与者做了什么、说了什么，再形成设计解释。如果这些观察与第一步的 Claim 有关，可以按人生方法建立明确支持或反驳关系；一次顺利点击不能直接证明长期创作路径正确。

## 连接为什么不破坏隔离

| 交接 | 传递的材料 | 接收者继续负责什么 |
|---|---|---|
| 人生 → 写作 | 有边界的问题、假设与约束 | 选择切口、材料与表达 |
| 写作 → 设计 | 文案、来源边界、目的地类型 | 页面组织、操作与反馈 |
| 设计观察 → 人生 | 原始观察、条件与范围 | 判断其是否与原 Claim 有关 |

三套方法各自仍可独立运行。本例的[机器记录](explain-and-guide.json)只检查方法 ID、模块版本与交接是否连得上；不会确认人生决策、采用稿件或更新线上页面。
