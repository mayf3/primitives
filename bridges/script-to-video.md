# 从讲稿到视频，再到观看入口

这是**按需使用的跨领域组合**，不是每次制作必须运行的工作流。人生、写作、设计、视频仍各有独立入口；只有本次任务确实跨域才交接材料。

| 任务 | 所属领域 | 输出给谁 |
|---|---|---|
| 判断问题是否值得做、提出待检验的取舍 | [人生](../domains/life/GUIDE.md)，仅在确有该任务时 | 给制作过程明确问题与约束，不搬运个人记录 |
| 把材料组织成可讲述的文字，保留原话与新增解释 | [写作](../domains/writing/GUIDE.md) | 给视频领域提供稿件、事实边界与来源位置 |
| 按时间呈现对象、关系与感受 | [视频](../domains/video/GUIDE.md) | 给项目提供分镜、声画安排及独立验证问题 |
| 让观众知道点开会看到什么、如何定位和继续 | [设计](../domains/design/GUIDE.md) | 给发布项目提供观看入口、导航与操作反馈 |

## 合成实例：把版本管理讲解做成可观看内容

1. **写作。** 使用 `writing.connect-relations` 和 `writing.choose-angle`，围绕“为什么 Current 改了，旧快照还留着”组织一段讲稿。输入中只有示例约定；“这能减少返工”等效果推断另标，不能回填成原材料事实。
2. **视频。** 使用 `video.focus`、`video.group`、`video.identity-preserve`、`video.reference-lock`、`video.correspond`、`video.hold`。生成[Current/Archive 分镜](../domains/video/PATTERNS.md)及[机器记录](../domains/video/examples/current-archive.json)。保持 Current 身份，并把快照画成派生新对象。
3. **设计。** 使用 `design.entry-outcome`、`design.position-progress`，提出“观看 48 秒示例：分清工作稿与历史快照”的入口及章节定位。48 秒是当前计划值；成片没有产出前，发布入口仍是提案，不能声称已可观看。实际时长、字幕和播放器能力由发布项目核实后再使用。

## 交接条件

- 写作 → 视频：包含讲稿版本、原材料位置、新增解释与未解决问题。关系不清的部分先退回核对，不靠图形猜测。
- 视频 → 设计：交付的是计划还是实际成片必须明说；需要真实产物、核实后的时长、内容承诺、字幕及观看限制，才可对外使用完成态文案。
- 验证记录 → 后续判断：仅传递实际观察及版本范围。结构检查或部署成功不产生“观众更理解”的结论；如要把观察接入人生判断，另按该领域的事实与证据关系规则处理。

一个网页里的高亮和一个片段里的定焦可能实现相似，但任务、时序与验证不同；不会因名称或技术相似就合并成同一原语。视频渲染成功也不自动满足网页操作或键盘访问要求。

本组合锁定的模块版本及交接关系见[机器记录](script-to-video.json)。状态为 `synthetic` / `not-run`，没有观众观察。它只是方法交接例，不安装 Remotion 工程，不创建调度或跨仓自动同步。
